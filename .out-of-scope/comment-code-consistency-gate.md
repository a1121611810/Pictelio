# 通用「注释↔代码一致性」门禁 —— 拒收（2026-10-14，承 #1013）

## 请求（被本条目拒收的形状）

建一道常设门禁，自动校验「注释说的与代码做的是同一件事」。

## 拒收理由（全部经实测，非臆断）

票 #1013 花了整轮 triage 把这件事量化到可判定的程度，结论是**成本收益不支持常设门禁**：

1. **真真空率低**：全仓 839 个源码文件 → 609 条否定式声明候选 → 284 条真声明句 →
   44 条含可提取形态 → 逐条变异实测确认 **3 条**真真空（真真空率 3/17）。
2. **朴素机检假阳率 71%**：声明的主语常是常量 / 元组 / 元陈述，不是文件 ——
   按「文件里有没有 X」判会把正常代码误判（实测 7 条 5 误判）。
3. **引用法筛真空系统性高估**：门禁大多写成「X 的必要条件」，声明写成「禁止 X」，
   措辞无交集但逻辑蕴含 —— 按注释引用筛会漏掉这类真覆盖（实测把覆盖最好的一簇误判为真空）。
4. **一般情形不可判定**：「注释 ⇔ 代码」的任意形态等价性判定，是程序与散文的等价问题。

## 替代处置（已落地，commit a4758799）

真空的 3 条**具体**声明已各自机器化（成对断言 / 剥注释扫描 / 单文件字面量判据），
不再依赖「有人读注释」。这是正确的粒度：一条声明一条断言，而不是一类声明一道门禁。

## 方法论留档（将来发现新矛盾时按需执行，勿建常设门禁）

1. **人工标注**该声明的主语与判定形态（是文件？常量？元组？还是元陈述？）——
   标不出主语的声明不可机检，登记为待收窄（#1013 的 #7 一度因此误判「不可判定」，
   后经 review 指正：主语可按文件收窄，今天就是绿的）。
2. **注入违规**（只加违规形态，不改判定逻辑）。
3. **跑全包**：绿 = 真真空，才值得补断言；红 = 已有门禁覆盖，别重复建设。
4. 补断言时落进**已拥有该事实的门禁文件**（复用其抽取器 / 扫描面），不另立文件、
   不复制抽取器（#1003「验的是正则副本」的老教训）。
