# Review–Fix Loop（实现后自审自修直到收敛）

> **状态**：已定稿（Round 2 全部按推荐通过）。本文是本循环的事实源。
> `AGENTS.md`「工作流强制规范」只保留一条指向本文的高优先级指向，实体不再留在入口文件。

一段**事件触发**的活动：一次实现/修改完成后，机器反复自审自修，直到触发停机规则。

- **交付物**：本轮 commit 的 diff 触及的文件集合
- **起点**：你宣布「这段做完了，开始查」的那一刻 —— **不按时间排期**
- **终点**：commit 落地为止。**不含 push、不含部署**（那是另一段活动）

## 词汇（先查这里；不要硬套结构）

| 词 | 本循环中的含义 |
| --- | --- |
| **Trigger** | 事件：你宣布「这段做完了」。不排期。 |
| **Checkpoint** | 你被拉进来确认的点 —— 见「Checkpoint 与 Brief」 |
| **Push right** | review 与修复全自动跑到底，你只在 checkpoint 被打断；**但空转会把你往前拉**（例外见下） |
| **Brief** | checkpoint 呈现给你的清单，不是原始输出 |

## 每轮做什么

1. 固定基线点 → `/code-review`
2. 有阻塞项 → `/tdd` 修复 → 回到 1
3. 无阻塞项 → 本轮通过 → 进入停机判定

`/tdd` 与 `/code-review` 可独立调用，闭环规则不变。优先用子代理并行执行独立的检查与修复。

### 必须用仓库版 code-review

**本循环用的是 `.agents/skills/code-review/`（Pictelio 统一三审计版）**，双轴并行：
Standards 轴与 Spec 轴各派一个 sub-agent，上下文互不污染；Spec 轴 brief 逐字注入，不得改写或「酌情执行」。

该文件声明「项目级 skill，按加载优先级**遮蔽全局同名 skill**」——
**全局同名的通用版不是这个循环要用的东西**，实现者不要去 `~/.agents/skills/` 里找。

三审计锚点：blast radius review（翻转/接口变更的调用点完备性）·
read-point evidence（声明—实现对照）· Oracle check（期望值溯源）· 平台/宿主契约。

standards 源为**发现式（存在即用）**，`docs/development/`、`CONTRIBUTING.md` 在本仓缺失**不算缺陷**。

## 停机：把「收敛」和「停机」拆成两件事

> 为什么要拆：「直到问题完全解决」在本仓**查不到任何可判定定义**，
> 且当 agent 同时是**测试的作者**和**修复的作者**时，收敛判据的分母是自己写的 —— 永远刷得绿。
> 故**不以「连续 N 轮无新发现」作为成功判据**。

### 单轮判据

本轮 review 在**交付物**里 0 发现 = 该轮通过。

### 停机规则（任一触发即停）

| # | 条件 | 出处 |
| --- | --- | --- |
| a | 连续两轮**只**在「本轮自己写的」里发现问题、在交付物里 0 发现 ⇒ **空转** | `docs/specs/md3-continuity.md:438` |
| b | 本轮该插的外部锚点验证未过 ⇒ 不得进入下一轮 | 见下节 |
| c | 你主动叫停 | — |

### 多轮推进的出口条件（自 AGENTS.md 搬入）

「循环至零问题」**没有自然终点**，故多轮推进必须同时满足：

1. **每轮都要有外部锚点**：真实设备 / 真实数据 / 真实用户可见的行为，至少轮一次。
   只有内部信号（全绿 / 自造变异）时，**不得**把该轮计为推进。
2. **单轮诊断规则**：即上表 a。
3. **门禁硬化最多一轮**：修门禁只能占一轮；下一轮必须回到产品本身。
4. **自测绿不算数**：「已知绕过 N/N 全抓」里的 N 是自己 imagined 的，分母随想象涨、不收敛。
   只有**外部复核**（另一方用**自己写的**攻击）把它打红，才算封住。

## 外部锚点：什么时候插

**按改动性质触发 + 计数兜底**，不用固定 N 轮：

- **命中以下任一 ⇒ 本轮结束前必须插锚点**，未过不许进下一轮：
  Android 原生侧改动 · 跨端契约 · 真实数据形状
- **其余改动**：每 **3** 轮兜底插一次

理由：固定 3 轮会对纯文案改动强插真机（浪费），而对跨端契约改动拖到第 3 轮又太晚。
判据锚仓库已有概念：**E2E 只钉「只有真机能证伪」的链路**。

## Checkpoint 与 Brief

**Checkpoint 三处**（其余轮次全程无打断）：

1. 锚点验证时（真机 / 真实数据）
2. 判空转时
3. 提交前

**Brief 五项**（缺一不可，**不塞 diff**）：

1. 本轮是第几轮
2. 改了哪些文件
3. 本轮**新**发现（不是旧发现复述）
4. 收敛进度 / 有没有触发空转
5. 需要你做的**唯一**决定 + 成品链接

### 判空转时 Brief 缩成三行

① 哪一轮判空转 ② 换过什么锚点、为什么还是没打红 ③ 你要决定什么

**理由**：空转的语义是**机器已经无法自证** —— 再给它换一个锚点，它照样会用自己的判据给自己发绿。必须外部输入。

> **push right 不是无限的**：正常情况一路把你往后推；一旦判空转，它就是把你**往前**拉 ——
> 因为这时机器的判断力已不可信。

## 门禁纪律（本循环内层）

若本轮涉及门禁改动，适用下列判据 —— **不得另造**：

- 门禁**判别力三要件**：反事实（须喂两种以上换皮形态）· 抽取器自身有效（扫描面非空 + 命中数下界）· 阳性对照
- **阴性证据三禁令**：搜到 0 条 / 手动跑过 / 门禁绿 ⇒ 一律视为空转门禁
- **「零命中 ≠ 不支持」**：产物 grep 0 命中有两种成因，产物本身区分不了，必须跑一次真实编译
- 每条门禁须**显式登记「已知失效面（抓不到什么）」**
- 门禁职责由单测与跨端契约承担；E2E 只钉只有真机能证伪的链路

### 门禁冻结线（防「给回归创造就业」）

> 自 AGENTS.md 原文搬入。**其第 2 条与本文「停机规则 a」同源**，保留两处是为不改动原规则表述；
> 实现时按**同一条**处理，不要当成两条独立规则。

门禁的价值是**防回归**，不是**显得严谨**。两者冲突时**以前者为准**。

1. **规模线**：单个门禁文件超过其**被测对象**的 30% ⇒ 停止加码，先问「我是在防回归，还是在给回归创造就业」（实例与数据见 `docs/research/md3-visual-regression-2026-09.md` §8.8）。
2. **单轮诊断**：一轮只在「自己这轮写的」里找到问题、在「要交付的东西」里找到 0 个 ⇒ 该轮判为**空转**，换方向。
3. **变异测试的分母不自选**：「已知绕过 N/N」里的 N 是自己 imagined 的，随想象涨、不收敛。
   封住一条的唯一凭据是**外部复核**（另一方用**自己写的**攻击）把它打红；自测绿**不作为**证据。
4. **Goodhart 警告**：一旦「门禁是否完美」变成目标，它就不再是目标。优先级恒为
   **真实设备 / 真实数据 / 用户可见行为 > 门禁信号**。
5. **假绿比没门禁更糟**：会骗人的门禁会被人信。故门禁的**已知失效面必须显式登记**（同上 §8.8），
   不得只记它抓到了什么。
