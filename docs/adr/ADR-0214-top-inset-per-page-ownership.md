# ADR-0214：顶部安全区让位改为「逐页归属」—— 修订 ADR-0168 的全局 Root padding 决策

## 状态

accepted（2026-10-02）

**修订 ADR-0168**（`docs/adr/ADR-0168-lynx-systembars-e2e-base-and-fullscreen-toggle.md`）的三处结论。
不推翻 ADR-0168 的其余部分（边到边基底、insets 换算唯一化、状态栏着色诉求、全屏模式），
只改**「顶部让位由谁施加」**这一条归属。

关联：spec [#900](https://github.com/a1121611810/Pictelio/issues/900)（及子票 #901–#907）。

## 背景

ADR-0168 落地时把顶部安全区做成**根容器集中补偿**（`App.vue` 根 `<page>` 的 `paddingTop = safeTop`），
并在「否决的替代方案」里**明确否决**了逐页归属：

> **逐页全 bleed 沉浸（替代 Root 全局 padding）**：保底正确性优先 —— 首批全局 padding 使所有页面
> 零遮挡，个别沉浸页（图片查看器）留待后续按页 opt-out。（ADR-0168:26）

同时承诺：

> 下游（Root padding + 6 个弹层 spacer）**一行不改**。（ADR-0168:42）

以及：

> 图片查看器 / IllustDetail 全 bleed 沉浸**不入首批**（spec D7）。（ADR-0168:32）

## 决策

### 1. 撤销 ADR-0168:26 的否决 —— 逐页归属现在被采纳

**理由**：ADR-0168 的否决理由是「保底正确性优先 —— 首批全局 padding 使所有页面零遮挡」。
这条理由在**首批**成立，但它同时**堵死了「个别沉浸页 opt-out」这条它自己规划的后续路径**：
根容器一压 padding，所有页面的内容盒恒从状态栏**下方**开始，任何页面都无法把内容放到状态栏底下。
换言之，ADR-0168 想留的「后续按页 opt-out」在当时的契约下**不可实现**。

本次需求（首页沉浸悬浮顶栏）正好撞上这个死结。两条路：
① 保留全局 padding + 为沉浸页加例外机制；② 把让位下沉到页面。
选了 ② —— 见下方「为什么不给全局 padding 加例外开关」。

### 2. 顶部让位下沉到页面；底部不动

- 顶部：25 条路由逐条显式声明归属（`RouteMeta.topInset`，**必填**，漏声明在 `vue-tsc` 层转红）。
  - `self`：页面自带一个**零内容 spacer** 让位。**按路由计 24 条**。
  - `bleed`：两侧都不让位，内容铺到状态栏底下。**按路由计 1 条**（首页），由构建期宏
    `PICTELIO_HOME_BLEED` 控制，**缺省开启**（产品裁定 2026-10-02）；
    **回退阀 = 显式 `PICTELIO_HOME_BLEED=0`** ⇒ 回到旧的 64dp 顶栏。
    极性的唯一事实源是 `packages/app-lynx/homeBleedHeaderFlag.ts`，
    由 `tests/homeBleedHeaderFlag.test.ts` 的真值表钉住（code-review 第 4 轮 B1/B2 补齐）。

  两个维度别混（第三轮 review 指出此处易被读成 25 个组件）：
  - **路由维度**：25 条 = 24 self + 1 bleed。路由比组件多 1，因为
    `/user/:id/following` 与 `/user/:id/followers` 共用 `FollowList`。
  - **页面组件维度**：24 个 = 13 个经公共顶栏 `PageTopBar` 内的 spacer + 11 个自持，两类交集为空。
  - 首页属那 24 个组件之一：它在 'bleed' 下 spacer 值为 0（正是「出血」的含义），
    开关关闭时同一组件以 'self' 让位。
- 底部：**完全不动**。根容器继续压 `paddingBottom`；6 个底部弹层继续各自消费 `safeBottom`。
  两侧并存不冲突（弹层让位 vs 页面内容兜底），删它要另开票。

### 3. 让位用零内容 spacer，**不用父容器 padding**

既有先例：6 个底部弹层已经是「零内容元素 + 显式逻辑像素高度」，由跨端契约测试逐个断言。

不用 padding 的理由：Lynx 的 border-box UA 默认会让 padding 在 border-box 下**吃掉内容高度**，
而 web-core 预览**不复刻**该默认（`App.vue` 转场包裹层的 `pb-18` 已登记过这个坑）。
spacer 方案在两种渲染器下同义。

### 4. 删掉第三种模式 `'root'`

收口时发现：根容器补偿删除后，保留 `'root'` 模式是**纯脚枪** —— 它的含义从「根容器补偿」
退化成「**完全不让位**」，与 `'bleed'` 逐字节同义却长得完全不像。
任何人给新路由写 `'root'`（很自然，它曾是默认值），页面就会顶到状态栏底下，而
**编译过、单测绿、门禁全绿**，只有真机上肉眼可见。

⇒ 词汇表砍到 **两值**。让「我不管顶部」必须**显式写成 `'bleed'`**。
未知模式的回落方向选 `'self'`（绝大多数页面的正常行为），绝不回落成 `'bleed'`。

## 为什么不给全局 padding 加例外开关（而不是保留 ADR-0168 原方案 + 局部例外）

考虑过「保留根容器 padding，加一个 `topInset: 'bleed'` 例外让根容器对该页不压」。
否决理由：

1. **例外机制本身就是新的全局耦合**。根容器要读当前路由的 meta 才能决定压不压，
   把「路由元数据」接进「根布局」这条新边 —— 而这正是 ADR-0168:42 承诺「几何消费方零改动」想避免的。
2. **两套机制并存更难推理**：一处是「根容器统一压」，一处是「页面自己压」。
   出问题时无法从单页判断责任方。改为「全部下沉到页面」后，
   **让位归属点唯一**（顶栏 / 页面根），与 ADR-0194 公共层「修一处漏 N 处是结构性必然」的教训同向。
3. **例外开关会长期存在**，而例外一旦存在就会被更多页面申请 —— 最后回到今天的局面，只是更混乱。

## 与 ADR-0168 的一处范围分歧（如实登记，不掩盖）

ADR-0168:32 规划的第一个 bleed 页是**图片查看器 / IllustDetail**，本次落地的是**首页（推荐页）**。

- 首页是**应用首帧**（首屏内容化，`router.ts` 初始路由），用户每天第一眼看到的就是它；
  图片查看器是**二级触达**路径。
- 首页本来就有全出血轮播（ADR-0118）与其配套的 scrim 遮罩 + 对比度实测手段（`tests/immersiveScrimContrast.test.ts`），
  在这里做 bleed 的风险面比在图片查看器小。
- **但这确实是与 ADR-0168 规划不同的选择**，不是原计划的兑现。图片查看器是否也 bleed
  **留待另票**，本 ADR 不预先批准。

## 已实证的证据（真机，emulator-5554 / 1080×2160 / density 480 ⇒ 换算比率 3.0）

平台真值：`dumpsys window` → `type=statusBars frame=[0,0][1080,72]` ⇒ inset = 72 物理 px = 24 逻辑 px。

| 验证项 | 结果 |
| --- | --- |
| 迁移后逐页对拍（推荐 / 插画 / 我的 / 收藏 / 追更 / 网络自检 / 平台自检 / 错误页） | 8/8 与平台真值一致（偏差 ≤ 1.0 物理 px） |
| 首页 bleed + 顶部遮罩，状态栏图标对比度 | 无遮罩时最坏 **1.09:1**（近乎不可见）；加遮罩后 **12.03:1** |
| 判据自证能红 | 注入 3× 缺陷 → 顶栏下边缘 256→400（比率 2.996×）判红；spacer 强制为 0 → 反推 inset 10.8（真值 72）判红 |

复跑工具：`packages/app-lynx/scripts/verify-top-inset.mjs`（幅值对拍，可重复执行）。

## 后果

### 正面
- 顶栏成为顶部让位的**唯一归属点**，页面可选择「参与让位」或「刻意出血」。
- 沉浸式页面成为可能，而不必在「全局安全」和「沉浸」之间二选一。

### 负面 / 代价（必须记下来）
- **全站 25 条路由都改了归属**，不再是「几何消费方零改动」。收口后根容器对顶部**不再兜底** ——
  声明 `self` 却没有 spacer 的页面会静默破版。
  ⇒ 已补机器防线：跨端契约测试断言「让位归属与让位实现必须**同时**存在」，
  并已自证能红（去掉某页的几何消费 → 门禁指名该路由与后果）。
- **首页 bleed 由构建期宏 `PICTELIO_HOME_BLEED` 控制，缺省开启**（产品裁定 2026-10-02）。
  **回退阀 = 显式 `PICTELIO_HOME_BLEED=0`** ⇒ 回到旧的 64dp 顶栏，布局与本改动落地前逐像素一致。
  刻意用 `!== '0'` 而非 `=== '1'`：默认值应由「关掉需要显式动作」表达，漏传 env 不该悄悄退回旧顶栏。
  两条路径**都进 CI**（主配置跑缺省、fallback 配置跑回退），互为对方的存在性证明。
- **首页 bleed 引入一个新的 Lynx 平台行为依赖**：CSS 变量出现在 `linear-gradient()` 函数实参内
  （既有范式是「整个渐变作为变量值」，二者**不是同一件事**）。真机实测可用，
  并已补源级守卫 + 设备取证记录（见 `src/pages/recommendedBleedHeader.template.test.ts`）。
- **深色主题下的状态栏可读性尚未实测**（`#906` 风险⑤，已显式挂账）。
- **横图封面留白变大**：取消 64dp 顶栏后可视区更高，而 ADR-0118 的封面策略是
  「贴顶、宽满、按原图比例、不裁切」，宽图撑不满 ⇒ 留白比之前多 64dp。
  属 ADR-0118 范畴，**留待另票**，本 ADR 不裁定。
