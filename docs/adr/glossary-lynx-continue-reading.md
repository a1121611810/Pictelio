## 核心术语

| 术语 | 定义 | _Avoid_（须规避的别称） |
|------|------|------------------------|
| **继续读（Continue Reading）** | 书架第三段的**本地回访列表**，内含**两类条目**：小说的**阅读位置**（续读条目）+ 插画的**浏览历史**（浏览记录条目）。按「我最近在这儿」组织，**用户零操作成本**——进入正文页 / 打开插画详情页即产生记录。与「稍后看」并存，二者边界见易混辨析 #1。📌 **两类同段同页**：一个 `/continue` 列表，不按类型分段。 | 最近阅读（**见易混辨析 #2**）、阅读历史、上次看到、阅读位置（单独使用时指代的是位置本身不是列表）、待读、接着看 |
| **浏览历史（Browsing History）** | **本地**的插画浏览流水，**只含插画**。每次打开插画详情页即产生/更新一条。**30 天过期**（沿 ADR-0094 先例）——它是行为流水，不是未完成事项。与阅读位置**同段同页**呈现（见易混辨析 #2），但**数据与生命周期完全独立**。 | 最近浏览、看过、阅读记录、浏览记录、继续看 |
| **浏览记录条目（History Entry）** | 浏览历史的存储单元。一条 = 一次插画浏览的快照：`{ illustId, title, coverUrl, userId, userName, xRestrict, visitedAt, visitCount }`。账号级键持久化，纯本地，**无任何服务端对应物**。`visitCount` 与「重复打开只更新时间戳、不新增条目」沿 ADR-0094 语义。 | 历史条目、浏览项、缓存条目、快照条目（后者是「稍后看」的存储单元，见四功能表） |
| **续读条目（Continue Reading Entry）** | 继续读的存储单元。一条 = **一个作品的一条位置**：`{ novelId, seriesId?, chapterNo?, chapterTotal?, title, coverUrl, userId, userName, xRestrict, lastOpenedAt, completedAt? }`。账号级键持久化，纯本地，**无任何服务端对应物**。 | 历史条目、阅读记录项、缓存条目、快照条目（后者是「稍后看」的存储单元，见四功能表） |
| **阅读位置（Reading Position）** | 「读到哪」的**坐标**，粒度为**话（= Pixiv 的 novel）级**。坐标载体是 `novelId`；`chapterNo` / `chapterTotal` 是它的**显示派生量**，用于渲染「第 3/12 话」。 | 进度（裸用）、百分比进度、页码、书签（Pixiv 无此概念）、续读点 |
| **会话末位置（Session-end Position）** | 阅读位置采用的**语义**：记录**本次退出时读到的那话**。允许用户在重读时把位置**往回拨**，不做单调推进。 | 最新位置、远端位置、最远进度 |
| **已完成态（Completed State）** | 「读完了」这一状态，由 `completedAt` 标记。**软删**：条目保留在存储中，只是不再出现在「继续读」主列表；`/continue` 页可查看与清除。**完成后重开作品不会撤销完成态**，但位置照常更新。 | 已读（易与 Pixiv 服务端语义混）、读完即删、归档 |
| **作品失效（Unavailable Work）** | 续读条目仍在，但实时数据拉取失败（作品被删除 / 下架 / 不可访问）。列表**照常渲染该条目**并显式标注不可用，**不静默隐藏**（测试硬约束 #3）。 | 自动隐藏、失效清理、跳过不可用项 |

## 易混术语辨析

1. **继续读 ≠ 稍后看 ≠ 追更 ≠ 收藏**（本表最重要红线，续读是「四功能表」之外的**第四条独立轴**）：

   | | 继续读 | 稍后看 | 追更 | 收藏 |
   |---|---|---|---|---|
   | 数据位置 | 本地 | 本地 | **服务端** | **服务端** |
   | 产生方式 | **系统观察**（进入正文即记录） | **用户主动**（手动添加） | 用户主动 | 用户主动 |
   | 维度 | 单个 novel + 话级位置 | 作品（插画+小说） | **小说系列** | 作品（插画+小说） |
   | 对应物 | 无 | 无 | `/v1/watchlist/novel` 族 | 收藏端点（public/private） |
   | 可为空吗 | 可以（没读过小说时） | 可以 | 否（服务端列表） | 否 |

   - **判别口诀：谁主动？** 用户主动表达的意图 → 稍后看 / 追更 / 收藏；系统从行为里观察到的 → 继续读。
   - **视觉必须可分辨**（「继续读」行显示「上次读到 第N话」，「稍后看」行显示「加入于」）。
     二者若长得一样，意图/行为这条边界在界面上即失效。
   - **代码红线**：继续读与稍后看是**两个 store、两个键、两条导航**。不得让「继续读」复用
     `watchLater*` 任何符号，也不得把二者渲染成同一组件形态。

2. **阅读位置 ≠ 浏览历史**（两者**并存、同段同页**呈现）：

   | | 阅读位置（继续读条目） | 浏览历史（浏览记录条目） |
   |---|---|---|
   | 作品类型 | **小说** | **插画** |
   | 记什么 | 读到**哪**（话级位置） | **打开过**（无位置概念） |
   | 性质 | 未完成事项 | 行为流水 |
   | 过期 | **不过期** | **30 天**（ADR-0094） |
   | 有「读完」吗 | 有（`completedAt` 软删） | 无 |
   | 呈现 | 书架段 3 内，行带「上次读到 第N话」 | **同一段落、同一 `/continue` 页**，行**无**状态文案 |

   - **📌 同段同页是刻意的**：两种生命周期的差异**对用户是隐形的**——过期条目只是悄悄离场，
     用户从不会看到「这条已过期」这个状态。UI 上真正要区分的只有**行内文案**，
     那是 per-row 的事，不构成 per-segment 结构决策的依据。**书架因此维持 3 段，不扩为 4 段。**
   - **数据层仍然完全独立**：两条轴按作品类型**天然不相交**（小说 vs 插画），
     打开小说不在浏览历史留记录、反之亦然。⇒ 零去重判断、零重叠数据。
   - **过期策略是逐对象的，不是按「历史」这个词统一施加**。把浏览历史的 30 天套到阅读位置上，
     等于替用户删掉没读完的书；反之阅读位置不过期也不适用于流水。
   - ADR-0094 的 `historyStore` 随 ADR-0203 客户端删除消失；**本项目重建它，但只重建插画侧**，
     字段沿用其快照形状（`xRestrict` 等）。
   - _Avoid_: 把任一类叫「最近浏览」/「最近阅读」而不说清是哪一类条目——这两个名字都被双方占用。

3. **会话末位置 ≠ 最远水位（Kindle） ≠ 最旧未读（Mihon）**（外部对照，见 ADR-0219 §2.2）：
   - **Kindle**：Whispersync 同步的是 "furthest page read"（**最远读到的水位**，单调不回退）。
   - **Mihon/Tachiyomi**：作品内 resume **跳最旧未读话**（等价于单调推进）。
   - 两个成熟产品都因此在**重读**场景出错（社区 issue 有明确报告：在重读第 21 话，
     回来后跳到第 63 话）。
   - **本项目不同**：本地单机、无跨端合并，**没有任何防回退的动机**，故采用会话末位置。
     结果是**重读场景正确**——而这是上面两个产品做不到的。
   - _Avoid_: 「向 Kindle 看齐」「最远进度」「未读就跳下一话」。

4. **继续读 ≠ 「开始阅读」按钮**（前者是功能位，后者是介绍页的 CTA）：
   `packages/app-lynx/CONTEXT.md` 的「开始阅读」词条当前写着「进入正文页**固定从头开始**。
   无续读——阅读进度持久化未立项」。该描述**对现状为真**。ADR-0219 落地后它会被改写为
   「未读过则「开始阅读」从头；已有位置则「**继续阅读**」并从该话开始」。
   ⇒ **改写必须与实现同轮提交**，否则该词条会变成一句谎话（它描述的是**当前状态**，
   不是机制）。在此之前，任何人不得据该词条断言「本项目不支持续读」。

5. **章节级 ≠ 段落级**（粒度为何停在话级）：
   本项目的阅读位置粒度是**话**，不是段落、不是页、不是百分比。
   外部一手证据一致：LINE WEBTOON「同步閱讀紀錄」保存的是**阅读过的集数**；Mihon 是**话级**；
   Kindle 是**页级**（但 Kindle 读器是分页模型，有精确 location 寻址能力）。
   本项目停在话级是**平台约束**，不是偷懒：Lynx 端的 `main-thread-bindscroll`
   在当前构建**未确认派发**（`pages/NovelDetail.vue:161-163`，2026-09-02 真机复测），
   段内滚动位置拿不到可靠信号。⇒ 任何「第 N 段 / 37%」的续读形态在当前引擎下**不可实现**，
   不要在需求里承诺。

## 关系

- **续读条目**（小说）属于 **继续读**；**浏览记录条目**（插画）属于 **浏览历史**。
  两者账号级键各自带 `${uid}` 后缀（照 `watch_later_${uid}` 范式）。
- **继续读** 与 **稍后看 / 追更 / 收藏** 四者**相互独立**：无数据同步、无入口联动、无语义包含。
- **续读条目**与**浏览记录条目** 📌 **同段同页**呈现（书架段 3 / `/continue`），
  但**作品类型天然不相交**（小说 vs 插画）、生命周期各自独立（§易混辨析 #2）。
- **阅读位置**由续读条目持有；`chapterNo` / `chapterTotal` 派生自 `seriesId`，
  **单本小说（无系列）没有 chapterTotal**，此时不渲染「第N话」而退化显示标题。
- **已完成态**是**续读条目**上的一个状态位，不是一个独立列表；它与**位置**可以同时存在
  （完成后重开 → 完成态保留、位置更新）。浏览记录**没有**对应概念。
- 段 3 与 `/continue` 页**均渲染各自的快照条目**，点击进**实时详情页**——
  与「快照条目 ≠ 实时数据」同源。

## 示例对话

> **Dev:** 书架第三段和第二段都是封面+标题+作者，用户会不会觉得重复？
> **领域:** 会，所以**行内信息必须不同**。稍后看那行显示「加入于」，继续读那行显示
> 「上次读到 第3话」。二者的判别不在卡片形态（形态就该一致），在**那条状态文案**——
> 用户认的是「我存的」还是「我读到哪了」。
>
> **Dev:** 用户读完了一本，又点进去重看了一下，继续读里它变回「在读」了吗？
> **领域:** 没有。完成态（`completedAt`）**保留**，只有**位置**更新了。
> 所以他现在在重读第 21 话，退出后再点继续读，回的是**第 21 话**。
> 这条链是通的：会话末位置 → 完成后位置仍更新 → 重读场景正确。
>
> **Dev:** 为什么不跟 Kindle 一样记「最远读到哪」？那样不是更保险？
> **领域:** 「保险」的前提是**多设备会冲突**——你两台设备各读各的，得有个规则决定谁说了算，
> 最小成本规则就是取最远的。Pictelio 是本地单机，**根本没有冲突可解决**，
> 为了一个不存在的冲突去牺牲重读场景不划算。Mihon 选了同样的单调语义，
> 结果它的用户就在抱怨重读时跳错章。
>
> **Dev:** 这条记录会跟着 WebDAV 备份跑到新手机吗？
> **领域:** 不会。备份域当前只收 `show_r18_` / `show_r18g_` / `ai_filter_mode_` 三类账号级键，
> 稍后看都不在里面，继续读沿用同一条边界。理由见 ADR-0219 §2.5。
