# 收藏加标签统一术语表（illust bookmark with tags）

> 范围：双端（`packages/app` webview + `packages/app-lynx`）「收藏插画时可加标签」功能的统一领域语言。结论来源：[同类三方客户端调研](../research/bookmark-tags-similar-clients.md)（pixivpy / Pixez / Pixeval / pixivgo / pixivswift 六实现差分，2026-09-14）与[非同类 app 收藏打标 UX 模式调研](../research/bookmark-tags-ux-patterns.md)（Pinterest / Instagram / YouTube / Raindrop 等 10 产品）；架构决策见 ADR-0160。本表只定义领域语言，不写实现细节。

## 核心术语

| 术语 | 定义 | _Avoid_ |
|------|------|---------|
| **收藏（bookmark）** | Pixiv 服务端「用户 × 插画」的收藏记录，携带一个可见性与 0..10 个收藏标签。本功能的领域主体。_避免_：与「收藏列表 feed」（webview `bookmarkStore` 管的收藏 tab 数据流）混称——后者是浏览域概念。 | 加喜欢、like、星标 |
| **快速收藏（quick bookmark）** | 单击心形按钮的**零决策**收藏：不带标签、公开可见、乐观翻转 + 爆发动效。既有行为，本功能**保持不变**。 | 默认收藏、一键收藏 |
| **收藏面板（bookmark panel）** | 长按心形唤出的底部面板：可见性切换 + 收藏标签选择（勾选/新建）+ 保存。是「带标签收藏」与「编辑已收藏」的**唯一**入口。 | 标签编辑器、收藏对话框、tag sheet |
| **收藏标签（bookmark tag）** | 用户挂在**某条收藏上**的私有标签（服务端 `bookmark tag` 实体），宇宙来自标签库或内联新建。 | 私有标签（口语可用，正式文档用「收藏标签」） |
| **作品标签（work tag）** | 作品自带的标签（`illust.tags` / `meta.tags`），在面板中仅作**建议来源**（可一键选为收藏标签），本身不是收藏状态的一部分。 | （单独说「标签」时必须限定是哪一种，见歧义记录） |
| **标签库（bookmark tag universe）** | 用户历史上用过的全部收藏标签集合（`GET /v1/user/bookmark-tags/illust`，分页；**公开/私密分库**）。面板中作为常驻候选来源。 | 标签宇宙（同义，文档统一用「标签库」） |
| **可见性（visibility / restrict）** | 一条收藏的 public（公开）/ private（私密）属性；与标签在收藏面板**同面板**选择。收藏列表的公开/私密分库由此决定。 | restrict（实现层词汇，领域层用「可见性」）；公开性 |
| **双轨收藏（dual-track bookmark）** | 单击 = 快速收藏、长按 = 收藏面板的**同控件双路径**交互总称（官方 App 与 Pixez 收敛的形态，UX 调研模式 P1+P2）。 | 双模收藏、长短按分级（不精确） |
| **覆盖式编辑（overwrite edit）** | 编辑已收藏作品的标签/可见性 = **重发 `bookmark/add`**（携带完整标签集 + 可见性）覆盖服务端记录。App API **没有** edit 端点；六实现差分一致，且**不先 delete**。 | 删了重加（delete+re-add 是被否决的备选）、更新收藏 |
| **预填（prefill）** | 打开收藏面板时从 `GET /v2/illust/bookmark/detail` 恢复现状：`is_bookmarked` / `restrict` / 已有标签（`is_registered`）——编辑模式的初始勾选数据源。 | 回显、恢复（不精确） |
| **标签上限（tag limit）** | 每条收藏**最多 10 个**收藏标签（官方帮助中心 + 官方公告双源）。面板 UI 强制。 | （无别名） |
| **空格分隔序列化（space-joined serialization）** | 多个收藏标签以空格 join 成**单值**、写入单个 `tags[]` 表单字段的线上格式（六实现差分一致；服务端按空格切分）。双端 `Record<string, string>` 请求通道因此**零改动**。 | 逗号分隔（错误格式）；`tags=a&tags=b` 重复键（无一家使用，不采用） |
| **私密直存（legacy long-press private）** | webview 详情页**现状**的长按行为（长按 500ms → 私密快速收藏）。本功能将其**升级**为收藏面板（可见性在面板内选），属有意的行为变更（ADR-0160 D4）。**已退役（#545，2026-09-15）**：插画**列表卡片**的长按私密直存亦改为打开收藏面板（与详情页统一，#541 裁决），**插画侧全域不存在此手势**；仅 NovelCard（小说侧，无收藏面板）保留同名旧手势。 | （历史概念，**插画侧**不再存在于领域语言） |

## 歧义记录

- 「**标签**」单独使用时歧义：可能指**收藏标签**（本功能主体）或**作品标签**（建议来源）。正式表述必须带限定词；代码与测试命名中 bookmark tag / work tag 不得缩写为裸 `tag` 语义混淆点（如测试断言里同时出现两类时）。
- 「**bookmarkStore**」（webview）是**收藏列表 feed store**（收藏 tab），不是收藏动作状态机——卡片/详情页的收藏动作状态各自本地管理（webview 组件内 signal / lynx `useBookmarkMutation`）。新代码禁止把收藏面板状态塞进 `bookmarkStore`。
- 「**私密收藏**」在 webview 现状语境 = 长按直存（私密直存，legacy）；本功能后长按 = 面板（可见性只是面板中的一个开关）。历史 E2E / 文档提到「长按私密收藏」时以本表「私密直存（legacy）」理解。**#545 后插画卡片长按亦为面板**；小说侧（NovelCard）仍为旧手势。

## 关系

- 一条**收藏**属于恰好一个作品（插画），携带一个**可见性** + 0..10 个**收藏标签**。
- **快速收藏**与**收藏面板**是同一心形控件的两种触发路径（**双轨收藏**）；两者共享乐观更新与动效资产，仅决策开销不同。
- **预填**是**覆盖式编辑**的前置：面板先经 bookmark/detail 恢复现状，保存时整体覆盖。
- **标签库**按可见性分库（public / private 两套宇宙）；作品标签不在任何库中，仅作建议。

## 示例对话

> **Dev:** 长按已收藏作品的心形，打开**收藏面板**后直接改标签保存，要走 delete 再 add 吗？
> **领域:** 不——**覆盖式编辑**就是重发 add，服务端整条覆盖；先 delete 会闪断收藏状态，六家实现都没这么做。
> **Dev:** 那没收藏的作品长按呢？
> **领域:** 同一个面板，只是**预填**为空（没有已有标签可恢复），保存即带标签收藏；或者用户什么都不选只切了私密，保存就是一条私密的空标签收藏——这和**快速收藏**（恒公开）不同轨。
> **Dev:** 面板里那些灰的、带数字的 chip 是什么？
> **领域:** 那是**标签库**（用户自己的历史标签，带使用计数）按当前可见性分库展示；作品自带的**作品标签**是另一组建议，两者来源不同，勾选后都是**收藏标签**。
