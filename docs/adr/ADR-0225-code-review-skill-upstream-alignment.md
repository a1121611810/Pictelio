# ADR-0225：code-review skill 对齐上游——上游骨架 + 本仓 override + 三方机检

- **状态**：已接受（Accepted，2026-10-20）｜**已实施**（本轮落地）
- **日期**：2026-10-20
- **相关**：[ADR-0097（agent skill 仓内化治理记录）](./ADR-0097-agent-skill-repo-localization.md)、[ADR-0224（领域文档改名对齐上游 skill 约定）](./ADR-0224-domain-doc-rename-to-glossary.md)
- **术语文档**：[`docs/agents/code-review-upstream.md`](../agents/code-review-upstream.md)（上游基线 + 逐条裁决，唯一事实源）
- **证据**：上游提交 `3da8c011`（2026-10-07, #1208）｜本仓偏离度实测（§5.1）｜变异矩阵（§5.4）

## 1. 背景

本仓的 `.agents/skills/code-review/SKILL.md` 是上游 `mattpocock/skills` 的
`skills/engineering/code-review/SKILL.md` 的 fork（引入于 `4bf64232`，2026-08-20）。它承载本仓的
**三审计**（调用点完备性 + 输入源接线 + 期望值溯源 + 平台与宿主契约）、触发式维度卡点与仓库锚点——
比上游那份更严。

但「更严」的另一面是**结构性失联**：

1. **没有基线记录**：本仓从未记下 fork 点的上游 commit，也没有任何「上游又变了」的判据。
2. **没有裁决表**：每次本仓偏离上游都只存在于文件里，理由散落在 ADR 与评审账本中。
3. **没有机械闸**：漂移对 CI 与人眼都是零信号。

实测偏离度（上游 `3da8c011` 89 行 vs 本仓 **改前** 174 行）：

- **共有非空行只有 3 行**（上游 57 行非空文本的 5%、本仓 136 行非空文本的 2%）——若把空行也算进「共有行」是 35 行，那是**高估约 10 倍**的口径，不足以说明任何文本重叠；
- **上游 54 行非空文本在本仓没有对应物** ⇒ 本仓是**彻底重写**，不是「上游 + patch」。

> 口径提醒（第一版 ADR 写错过）：「共有行」这个指标会把空行算进去，而 markdown 文件的空格行占三成左右。**判断 fork 接近度必须看非空行**——本仓改前 3 行、改后 8 行（上游的 14%）。

上游自己的纪律（`docs/engineering/code-review.md`）只说了一句：

> Keep a note of the commit you forked from so you can re-sync by hand.

只记 SHA 让「**发现**上游动了」变容易；要让「**发现不了**」变不可能，需要机械闸。

## 2. 决策

采用 **C 档：上游为主 + 本地补充**。落地形态是三件事，缺一件都不成立：

### 2.1 上游骨架：上游的标题是本仓文件的段落锚

本仓 `SKILL.md` 按**上游的段落顺序与标题**组织，每个上游标题在本仓文件里有一个同名锚点
（`<!-- upstream-section: <上游标题> -->`），上游没有的机制集中在 `## 本仓 overlay（上游无此段）` 一节。

**为什么不是逐字保留上游 89 行**：本仓**不采纳**上游 4 处做法、**不搬**上游 2 个文件——

- 不采纳但**有替代物**（裁决表记 `adapt`）：12 条 Fowler smell 全文粘进第 3 步（OV-13，移到
  `### Standards 轴`）、spec 来源放宽到 `specs/` 与 `.scratch/`（OV-4，收紧到 `docs/specs/` +
  `docs/adr/`）、brief 400 字上限（OV-8，改为不设上限）、英文短描述（OV-12，改用承载三审计
  触发线索的长中文描述）。
- 不搬且**本仓没有对应物**（裁决表记 `not-ported`）：`agents/openai.yaml`（OV-15）、上游自己的
  用户说明页（OV-16）。

逐字保留会让 skill 指示 agent 去做本仓明确拒斥的事。另有 1 处上游句子**行为保留、措辞被压缩**
（OV-14：无 spec 则跳过 Spec 轴）——它不算否决，单列一行以免裁决表漏记。

> ⚠️ **「不采纳 / 不搬」与裁决表的 `adapt` / `not-ported` 是同一件事的两种说法**，判据只有一个：
> **本仓有没有对应物**。两处措辞若不一致，读者会以为矛盾——§2.2 的表是准的。

**骨架对齐 + 显式 override** 才能同时保住「上游的意图」与「本仓的判断」。

### 2.2 每处偏离都要有编号、理由、落点

凡本仓与上游不同之处，文件里用 `<!-- upstream-override: <ID> -->` 标记，ID 指向
`docs/agents/code-review-upstream.md` 裁决表的一行。裁决表 **16 行**，分四档处置：

| 处置 | 含义 | 条数 |
| --- | --- | --- |
| `adopt` | 直接采纳上游（4 条：`5c89081d` 的「用户没给就问」+ #1208 的 3 处改动） | 4 |
| `adapt` | 采纳上游意图、按本仓实况改写（**本仓有对应物**） | 9 |
| `not-ported` | 上游有、本仓**整块/整文件没有**对应物（并说明为何不需要） | 2 |
| `local-only` | 本仓新增、上游没有 | 1 |

> ⚠️ `adapt` 与 `not-ported` 的分界是**「本仓有没有对应物」**，不是「上游那句字面搬没搬」——
> OV-8（不采纳上游的 400 字上限）、OV-12（不采纳上游的英文短描述）本仓都有替代物 ⇒ `adapt`；
> 只有 OV-15（`agents/openai.yaml`）、OV-16（上游用户说明页）本仓真的没有 ⇒ `not-ported`。
> 这个分界不是措辞洁癖：**规则 6 靠它判别「白名单不能用来给删掉的上游块洗白」**。

### 2.3 三方机检：上游正文 ↔ 本仓文件 ↔ 裁决表

`scripts/check-code-review-upstream.mjs` 把三者当成一个三角来校验，规则见
`docs/agents/code-review-upstream.md`「结构约定」一节（7 条）。核心两条：

> **块内容与上游不同 ⇒ 该块必须有 override 标记**（块级登记存在性）。
> **`not-ported` 行指名的块在本地必须真的不存在**（白名单不能用来给「删掉的上游块」洗白）。

⚠️ **这套机制的判别力有明确边界，第一版 ADR 把话说满了，本版订正**：

- ✅ 保证得住：裁决表与文件**双向自洽**（进 CI）、上游漂移可发现（联网）、上游块缺失/本仓块新增
  **都登记过**、本仓独占块**正文没被清空**。
- ❌ **保证不住**：**块内「每一处差异」都登记过**。规则 5 只是「这个块被登记过」，不是「这处差异
  登记过」——实测反事实：把某个**已带标记**的块正文整段静默改写 ⇒ 闸 **exit 0**、CI 测试**全绿**。
  逐处登记目前**靠人的纪律**，不是机器保证。

⇒ 因此本 ADR **不**宣称「上游原文被静默改写 = 机器可判定事件」。准确的说法是：
**「上游漂移与裁决账本的自洽性」是机器保证的；「块内逐处差异的登记」是人的纪律。**
完整的保证/不保证清单见 `docs/agents/code-review-upstream.md`「机检的边界」一节。

配套的两条设计：

- **文件清单表驱动**：闸从基线文档的「上游派生文件清单」表解析路径与基线 commit，代码里不硬编码
  路径——否则「新增一个上游派生文件却忘了加进闸」这类盲区会重演。
- **退出码三态可分**：`0` 没漂移且一致 · `1` 漂移或不一致 · `2` **查不了**（缺工具 / 联网失败 /
  基线悬空 / 文档解析失败）。「查不了」永远不是「没漂移」——把两者合并正是门禁静默失效的典型路径。

### 2.4 联网的部分不进 CI，离线的部分进 CI

闸要联网，而 PR 门禁必须离线（联网门禁会因为与 diff 无关的原因变红）。分工：

- **联网**（`pnpm run check:code-review-upstream`，发布前手动位）：上游漂移 + 与上游正文的块级比对
  （规则 3、4、5）。
- **离线**（`packages/app-lynx/tests/codeReviewUpstreamSync.test.ts`，11 项，进 `test:all`）：标记 ↔ 裁决表
  双向一致、锚点合法性、落点标题真实存在、标记语法只以真标记出现、基线 sha 齐全，**加上两条不依赖
  上游也能判的规则**——`not-ported` 行不得指名本地仍存在的块（规则 6）、本仓独占块正文不得为空
  （规则 7），**以及闸的「查不了」路径必须退出 2 而不是 0**（三态退出码里最容易被静默吞掉的一档）。

⚠️ **联网闸没有任何注册触发点**：它只挂在发布前手动位（`ci.yml` 没有对应 job，发布清单未列）。
**没人记得手跑 = 上游漂移零信号**——这是本轮遗留的已知缺口，见 §4。

## 3. 不做什么

- **不逐字保留上游正文**（§2.1）。
- **不留 stub / alias / 软链**：上游在自己仓里也没留；留了「哪个是真源」就重新含糊。
- **不把另三个上游派生文件现在就塞进闸**：见 §4。
- **不把闸接进默认门禁**：联网依赖会让 PR 门禁失真。

## 4. 后果与遗留

**消除的风险**：本仓 skill 与上游的关系从「凭记忆」变成「有基线、有裁决、有机器闸」；下一次上游动，
闸会点名是哪一次提交，并指出哪些 override 需要重裁。

**新增的代价**：本仓文件多了一层标记语法（两处 HTML 注释）；裁决表要随每次 override 同步。
**标记语法只准以真标记出现**（正文内联引用会被判违规）——这条已在闸与测试里落地。

**遗留（明确记录，不假装清零）**：

- **另三个上游派生文件尚未纳入闸**：`docs/agents/triage-labels.md`、`docs/agents/issue-tracker.md`、
  `docs/agents/domain.md`。它们是 setup skill 的**种子模板**经本仓本地化改编后的产物（不是逐字
  fork），上游在各自引入之后都动过（实测 **1 次 / 8 次 / 2 次**提交，按种子模板路径
  `skills/engineering/setup-matt-pocock-skills/{triage-labels,issue-tracker-github,domain}.md` 计，
  口径与机械闸一致：含 merge commit）。
  三者需各自裁决「跟到什么程度」才能进表——**未裁决前不纳入闸，避免用「基线一填就绿」掩盖真实漂移**。
- ⚠️ **上游 `docs/agents/triage-labels.md` 不是本仓文件的祖先**：本仓这三个文件来自种子模板
  `skills/engineering/setup-matt-pocock-skills/`，不是上游仓自己的 `docs/agents/`（后者是 setup 在
  上游自己仓里跑出来的产物）。核上游漂移要核对**种子模板**那条路径——这是本轮实测踩到的坑。

## 5. 证据

### 5.1 偏离度实测（改名前 / 改后）

```bash
# 口径：共有行必须只算非空行（markdown 的空行占三成，算进去会高估约 10 倍）
python3 - <<'PY'
import difflib, subprocess
up   = open('/tmp/upstream-cr-3da8c011.md').read().splitlines()
old  = subprocess.run(['git','show','HEAD:.agents/skills/code-review/SKILL.md'],
                       capture_output=True, text=True).stdout.splitlines()
new  = open('.agents/skills/code-review/SKILL.md').read().splitlines()
for label, local in (('改前', old), ('改后', new)):
    sm = difflib.SequenceMatcher(None, up, local, autojunk=False)
    nb = sum(1 for b in sm.get_matching_blocks() for i in range(b.size)
             if up[b.a+i].strip() and local[b.b+i].strip())
    print(label, '共有非空行 =', nb)
PY
```

| | 上游（`3da8c011`） | 本仓改前 | 本仓改后 |
| --- | --- | --- | --- |
| 总行 / 非空行 | 89 / 57 | 174 / 136 | 237 / 182 |
| 共有非空行 | — | **3**（上游的 5%） | **8**（上游的 14%） |
| 上游有而本仓无（非空） | — | 54 | 49 |

> 「上游为主」在这里是**结构意义**（上游的段落顺序与标题是骨架、每处偏离都有编号裁决），**不是文本占比意义**
> ——改后共有非空行也只有上游的 14%。

`gh api repos/mattpocock/skills/commits?path=skills/engineering/code-review/SKILL.md` ⇒

⇒ **上游自 2026-10-07 起未再动过**，本仓基线取 `3da8c011` 即上游最新。

### 5.4 变异验证（每条新判据都要有反事实）

临时变异 → 立即还原，逐条记录（**每行都是实跑结果**，不是设计意图）：

| # | 变异 | 闸 | 离线测试 |
| --- | --- | --- | --- |
| M1 | 删掉一个 override 标记 | **红**（行无标记 + 块偏离无标记） | **红** |
| M2 | 加一个裁决表里没有的标记 | **红**（标记无裁决行） | **红** |
| M3 | 把某裁决的落点改成 `—` | **红**（无落点却带标记） | **红** |
| M4 | 删掉一整行裁决 | **红**（标记无裁决行） | **红** |
| M5 | 正文内联引用标记语法 | **红**（语法只能以真标记出现） | **红** |
| M6 | 把基线 commit 回退到更早的上游 commit | **红**（点名上游那一次提交） | 不适用（联网侧） |
| M7 | 删掉本仓专属的 overlay 块 | **红**（OV-11 无标记） | **红** |
| CF-F | 预登记一条 `not-ported` 行，指名**仍在本地**的上游块 | **红**（规则 6：白名单不能给删掉的上游块洗白） | **红** |
| CF-E | 整段清空 overlay 正文 152 行（留锚点 + 标记） | **红**（规则 7：空壳） | **红** |
| CF-T | 把裁决表**整段删空** | 不适用（表没了，闸读到 0 行即报解析失败） | **红**（判据 4 改成断言解析出的行 ⇒ 恒真断言已消除） |
| **CF-B** | **静默改写一个已带标记的块的正文** | ⚠️ **绿（已知盲区）** | ⚠️ **绿（已知盲区）** |

**CF-B 是这套机制的判别力边界，第一版 ADR 曾把它说成「机器可判定事件」，本版订正**（见 §2.3）：
规则 5 是**块级登记存在性**，不是**逐处差异登记**。逐处登记目前靠人的纪律。

⚠️ 第一轮跑变异矩阵时，**M1–M5 的「测试红」全是噪声**：沙箱里 vitest 起不来（缺
`packages/app-lynx/package.json`，workspace 依赖解析不了），而我当时**没先跑沙箱的测试基线**。
补跑基线才发现沙箱从一开始就是红的，随后改为「真仓临时变异 + 立即还原」，并逐条核对还原。
**教训**：变异矩阵的第一行必须是**未变异的基线**，否则「红」证明不了任何事。

⚠️ 另有一轮变异**打偏**：第一次跑 CF-E 时只删了 overlay 的一半正文，闸自然绿——那是变异没打到位，
不是闸有牙。第二轮按「整段清空」重跑才红。**教训**：反事实必须打在**判据的真正边界**上，
否则「绿」证明不了判据存在。
