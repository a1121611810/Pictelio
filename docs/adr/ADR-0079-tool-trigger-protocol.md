# ADR-0079：工具触发协议（CodeGraph / OpenWiki / 文档查询主动路由）

## 背景

AGENTS.md 中 CodeGraph、OpenWiki、Context7/MDN 的规范都是**被动式**（"当涉及 XX 时优先使用"），模型需要自行判断"是否涉及"，导致实际使用不稳定：漏用（直接 Grep/Read 摸索）、用错工具（该读 OpenWiki 却查符号）、用错姿势（传错参数、中文搜索失败后放弃）、浅尝辄止（拿到一次结果不再追问调用链）。排查发现 AGENTS.md 已 53KB，「代码智能规范」「文档查询规范」「OpenWiki 查询规范」分散在多个章节，且「约定」「注意事项」存在散落重复条目，注意力被稀释。

## 决策

采用**主动触发协议**，并维持**摘要-细节分工**：

- **新增「工具触发协议」章节**（AGENTS.md 顶部，任务开始第一步）：接到任务先做 30 秒工具路由判断——架构/概念/集成/测试类问题必须先读 `openwiki/`；符号/调用链/影响类问题必须先调 CodeGraph；库文档先 Context7、浏览器 API 先 MDN；两者都涉及则先 OpenWiki 后 CodeGraph。违反视为架构违规。
- **强制路由表**：将「与 CodeGraph 的协作规则」从参考语气改为"必须"语气（表格化强制分流）。
- **删除散落重复**：「约定」577 行「代码探索」条目、「注意事项」623-625 行三条（已被协议与三大规范覆盖）。
- **自检证据化**：「任务完成前自检」新增"工具使用证据"项——记录路由判断与所用工具；发现偏差当场沉淀 feedback memory。
- **持续反馈闭环**（制度化）：agent 自检捕获偏差 + 用户反馈兜底 + 每次改动相关章节时回顾失败案例，把高频失败固化为规则。AGENTS.md 保留摘要，参数/索引维护/降级细节继续沉在全局 memory `mcp-codegraph-usage.md`、`mcp-doc-query.md` 单一事实源。

## Considered Options

- **扩充补全现有规范**（否决）：让已 53KB 的 AGENTS.md 继续膨胀，注意力稀释更严重，且仍是被动式。
- **精简收敛只留摘要**（否决）：丢失参数速查、索引维护、降级细节，模型降级场景无从判断。
- **一次性演练验证**（否决）：用户明确无法马上给出典型任务，改走持续积累发现问题。
- **新建独立 skill 承载触发**（否决）：skill 是"被调用才生效"，而触发协议需要在任务开始就生效，必须放在每会话加载的 AGENTS.md。

## Consequences

- 所有会话的任务开始行为改变：第一步是工具路由判断，而非直接读代码/搜索。
- 失败案例会以 feedback memory 形式持续沉淀，未来可据此进一步修订协议。
- 验证方式为持续积累式（用户反馈 + agent 自检），无一次性验收。
