# ADR-0134：小说正文列表虚拟化（`<list single>`）与主线程滚动信号（app-lynx）

> 状态：已接受（2026-09-02，wayfinder 地图 #304 / 选型 #311 / 原型 #313）
> 决策链：T0 帧级基线（rev2）→ T1 时延（#312）→ 方案选型（#311）→ spike（#313）→ 本 ADR

## 背景

app-lynx 小说正文（NovelDetail）现状 = 全文一次性 `v-for` 渲染进单个 `<scroll-view>`（无虚拟化）。用户体感「小说详情滑动明显更差」；量化：真机 60Hz 同文同深度对照显示现状深滚 jank 递增劣化（11.8→22.6→30.2%，H1「元素树单调增长」签名）、内存膨胀（288MB）。

## 决策

1. **正文改为 `<list list-type="single">` 引擎虚拟化**（「B 路径」）：段落为 `<list-item>`（Vue `:key` 与 Lynx `:item-key` 双份一致、稳定 id = `p-<idx>`；`estimated-main-axis-size-px` 估算滚动条）；头部信息卡与「— 完 —」为独立 item（`meta` / `end`）；**受限小说不经 list**（保留原头部+遮罩分支）。依据：官方 `scroll-view-vs-list` 指南（「内容超过约三屏优先用 list」）；架构事实 = 段落轻文本 item 的原生回收在真机健康（#302 背景下的正文场景实测排除，与卡片 cell 不同）。
2. **A 路径（scroll-view 段落窗口化）作废**：其信号源（per-frame `@scroll`）在真机 `scroll-view` 上实测不派发（见下），窗口化无法驱动。
3. **主线程滚动信号（MT scroll signal）作为滚动感知的通道**：`<list>` 绑定 `:main-thread-bindscroll`（事件流向主线程）在原生 4.0.1 **派发**（scrollTop 递增实测）——由此：**追更询问「≥70% 进度」信号可复活**（实施随本 ADR 一并落地，替代「仅到底+停留」兜底语义）；滚动感知类优化的信号源恢复。
4. **停留底线的语义确认**（产品例行）：追更询问触发条件 = 系列作品 + 未追更 + 本会话未「暂不」+ 停留 ≥10s +（**MT 进度 ≥70% 或到底**）——MT 信号落地后恢复 ≥70% 分支（原语义见 glossary 追更询问）。
5. 相关定论（引用不回述）：IFR 保留启用（首屏收益，拍板）；MTS 可用于 JS 驱动交互（ADR-0115 判定修订——0.5.1 官方姿势真机可用）；「输入派发地板」48–50ms 为 SDK 层（应用层无解）。

## 数据（spike，OPPO R11s 60Hz，同文「神国漫游记」25679 字，18 屏深滚后采样）

| 指标 | scroll-view（改造前） | list single（改造后） |
| --- | --- | --- |
| jank（3 次） | 11.8/22.6/30.2%（中位 22.6） | 6.1/19.6/8.2%（中位 8.2） |
| 内存 TOTAL | 287.8 MB | 167.0 MB（-42%） |
| P50 | 13–14ms | 10–11ms |
| 白屏 | 无 | 无 |

## 实施注意（引 #313 spike 已知项）

- `estimated-main-axis-size-px` 精调（按正文平均/估算行高），减少短段/长段混排的滚动条修正抖动。
- 滚动恢复（若后续做）需**锚点 id**（当前 `p-<idx>` 只满足虚拟化；列为实施议题）。
- 回归清单：追更询问（≥70%+到底）、评论浮层、系列行、屏蔽/举报、受限小说遮罩。
- 全量实施 = 本 ADR + to-spec/to-tickets 交付；原型实现存 `prototype/vapor-eval`（7e92665a）供移植。
