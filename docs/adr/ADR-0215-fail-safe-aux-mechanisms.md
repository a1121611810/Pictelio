# ADR-0215：辅助机制必须 fail-safe，且每条声称都要有可复现的机器证据

## 1. 背景

#900–#907（首页沉浸悬浮顶栏）落地后，六轮 code-review + 真机验证暴露出**五个互不相关的缺陷**，但它们共享同一个结构：

> **一个「辅助性机制」失败了，而系统给出了「一切正常」的表象。**

| # | 辅助机制 | 失败形态 | 表象 |
|---|---------|---------|------|
| A（#908） | 入场动画 `listItemStyle` | 绑在**冷挂载静态兄弟**上时，整段设置区永久不可见 | 无日志、无报错、单测全绿 |
| B（#910） | `tsconfig.node.json` | 声明了 project reference，但**没有任何命令执行过它** | 7 个类型错误长期存在而无人发现 |
| C（#909-1） | 文档里的对比度数字 | `12.03:1` **无法在提交内复现**（量对比度的工具不存在） | 数字看起来精确可信 |
| D（#909-3） | 验收判据 | 「整屏浅纯色底」这一族输入下给不出答案 | 报 PASS 或报 FAIL，**都不是「不知道」** |
| E | 顶栏高度契约 | 脚本里的 `17.067` 与页面里的 `17.067vw` 是两个独立字面量 | 各自漂移时不会有任何东西变红 |

补充一个**同结构但已自愈**的实例：Pillow 依赖。度量脚本 `from PIL import Image`，而该包**在仓里任何地方都没声明**（`grep -rn -i pillow` 零命中）。本机装了所以全绿，推到 CI 后 10+ 用例全红。

这五条的共同点不是「代码写错了」，而是 **失败方向错了**：它们都朝「静默通过」的方向坏，而不是朝「响亮报错」的方向坏。

## 2. 决策

### 决策 1 · 辅助机制一律 fail-safe，**不得朝「静默通过」的方向坏**

具体到动效：**任何入场/退场/错峰动画都不得让内容消失**。装饰性效果是 additive 的——它可以改变内容**如何出现**，不能改变内容**是否出现**。

- `item-rise` 帧体当前 `from { opacity: 0 }` ⇒ 动画不运行时元素停在 `from`，**占位但不可见**。
- 修法方向：**把「动画未生效」与「内容可见」解耦**。具体形态在 spec 阶段定（可能是 `from` 不改 opacity、也可能是补一个「动画缺席即终态可见」的兜底），但**验收条件固定**：把动画整条摘掉，任何页面的内容必须**完全可���**。
- 这条**优先于**保持视觉一致性。若两者冲突，牺牲视觉。

### 决策 2 · 每条「我们以为成立」的声称，要么有机器防线，要么显式登记为未验证

枚举本轮需要补的四类防线：

1. **跨端/跨语言契约的等式**（决策 C 类的通用形态）：脚本的硬编码常量 ↔ 页面实际的令牌/类名。这类等式此前**零防线**，因为「A 有门禁、B 有门禁，**A 与 B 之间的等式没人验**」。
2. **文档里的数字**：任何写进 ADR/清单的实测数字，必须有**提交内可复现**的取样手段；没有就别写数字，改写成「在某条件下量得」。
3. **判据的失效面**：判据原理上区分不了的输入族，**必须在代码里登记并有会红的断言**（AGENTS.md「门禁冻结线」#5）。
4. **未声明的外部依赖**：仓内脚本用到的任何第三方，必须在仓内声明或**改为零依赖**。**不得**靠「CI 机器上恰好装了」。

### 决策 3 · 顶栏几何一致性的门禁范围**明确受限**，且限制要写在文件里

全站顶栏几何一致性需要一个机器防线，但**正则扫 `h-[Nvw]` 不可行**——该写法在页面里大量用于非顶栏元素（进度条、列表格高、网格单元），首版这么做过并把正常页面判红。

⇒ 门禁只做**无歧义**的断言（跨文件等式 / 公共组件两变体 / 已登记的自绘页清单 / 清单防空转 / 换算处同源），并**在文件头明写它不做全站枚举**。宁可承认覆盖不全，也不留一道看起来覆盖了实际没有的门禁。

### 决策 4 · 横图封面留白：**接受并登记**，不改封面策略

取消首页 64dp 顶栏后，横图封面（宽高比大、可视区更高）的顶部留白比其他图多 64dp。**这是已接受的取舍**，不是缺陷：改动 ADR-0118 的「贴顶、宽满、不裁切」策略需要新的分档阈值依据，代价大于收益。

- 登记在 [./glossary-lynx-units.md](./glossary-lynx-units.md) 相邻处与本 ADR §5。
- ⚠️ **代价是写明的**：首页的视觉均衡性依赖图片本身的宽高比分布，**不由代码保证**。若将来收到「某些图看起来不均衡」的反馈，那是本决策的已知代价，不是回归。

## 3. 为什么不做别的

| 备选 | 不选的理由 |
|------|-----------|
| **给 CI 装 Pillow** | 把问题往后推。度量结果会随 Pillow 版本/解码差异漂移；且依赖仍未在仓内声明，下一个干净环境还会炸。改为零依赖后，脚本在**任何**有 python3 的机器上直接可跑 |
| **只修 Me.vue 那 10 处绑定**（治标） | 动画契约仍是 fail-closed 的，下一个静态兄弟页会再踩。决策 1 要的是契约层面的修复 |
| **全站扫 `h-[Nvw]` 做一致性门禁** | 会把正常页面判红（首版实证）。判据过宽比没有门禁更糟 |
| **横图按比例分档压缩留白** | 分档阈值从哪来没有依据；偏离 ADR-0118 的统一策略 |
| **给「整屏浅纯色底」加第三/第四个信号** | 该族与浅色顶栏在**颜色统计上同形**，颜色维度已无信号可用。硬加只会制造「看起来更全」的门禁 |

## 4. 后果

### 正面

- 五类「朝静默通过方向坏」的机制里，A/B/C/E 有机器防线；D 转为显式登记的已知失效面。
- 动效契约的失效方向从「内容消失」翻转为「内容保持可见」——这是**全站 8 个消费页 + 所有未来页面**的通用改善。

### 负面 / 代价（必须记下来）

- **CI 门禁变严**：`tsconfig.node.json` 接入 `check` 后，构建配置层的类型错误会阻断 CI。**这是它本来的样子**，不是新负担。
- **入场动画的视觉可能退化**：若 `item-rise` 的 `from { opacity: 0 }` 必须改，错峰观感会变化。需在真机确认并记录。
- **零依赖 PNG 解码器是自维护代码**（约 50 行 stdlib）：覆盖面有限（bit depth 8 + color type 2/6、非隔行），超出范围**显式报错**而非静默降级。这是取舍。
- **Pillow 依赖被移除**：仓内若有其他脚本依赖它，需各自处理（本轮枚举为零）。

### 未决

- 入场动画「fail-safe」的具体形态（改 `from` / 加兜底 / 改绑定时机）留给 spec 阶段定，**验收条件已固定**（见决策 1）。
- 「整屏浅纯色底」这一族**永久无法**在颜色维度上判别——不再投入。

## 5. 证据

- 缺陷清单与真机复现：#908（根因 + 跨页对照）、#909（各项实测表与勘误）、#910（基线 7 个类型错误 + 逐条命令）。
- Pillow 事件：CI run 36991015462，`top_inset_metrics.py` 在 GitHub runner 上 10+ 次 `Command failed`；修复提交 `c403aa42`。
- 判据自身的三次假绿（源文本断言当覆盖 / 阈值从单个样本推 / 接缝字段序错位）见 #909 与对应 commit message。
- 全站顶栏高度同源证据：`grep -rln "17.067vw" src/` 命中 13 个文件，值全相同；`PageTopBar.template.test.ts` 钉住两个变体。
