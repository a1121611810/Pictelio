## 1. 背景

`/shelf` 是 ADR-0218 确立的顶层目的地之一，承载「我存的、没看完的」，三段为
**我的收藏 / 稍后看 / 继续读**。其中段 3 自 ADR-0203 删除旧客户端后一直是**显式空态占位**
（`pages/Shelf.vue:105-108, 262-282`；i18n `shelf.continueReading.*`）。

项目侧实测（CodeGraph 全库查询 + 源码核对）：

| 事实 | 证据 |
|---|---|
| 阅读位置持久化 = **零** | `currentCharIndex` / `readingProgress` / `lastRead` / `scrollRestore` 四次查询全部无结果 |
| 浏览历史 = **零** | 唯一 `lastRead` 命中是 `notificationStore.countUnreadNotifications`（通知已读，与阅读无关） |
| 「开始阅读」**固定从头开始** | `CONTEXT.md` 词条 + `NovelIntro.vue` CTA |
| 章节级**可寻址** | `SeriesSheet` 选话跳 `/novel/:id`，正文路由直接可达（ADR-0167 禁止路由级重定向） |
| ⚠️ **段内位置不可观测** | `NovelDetail.vue:161-163`：2026-09-02 真机复测，`main-thread-bindscroll` 在本构建未确认派发；仅 `@scrolltolower` 权威 |

外部一手证据（按「先联网取证、再结合项目」）：

| 来源 | 事实 |
|---|---|
| **Kindle**（Amazon 官方手册原文） | Whispersync 同步 "bookmarks, notes, highlights, and **furthest page read**"——最远水位，单调不回退 |
| **Mihon/Tachiyomi**（社区 issue #159） | 作品内 resume 跳**最旧未读话**；用户明确报告**重读场景坏掉**（在重读第 21 话，回来跳到第 63 话） |
| **LINE WEBTOON**（官方帮助中心） | 「我的漫畫」聚合最近看過+最愛+下載；「同步閱讀紀錄」保存**阅读过的集数**（话级） |

项目已有研究（[`feature-dimension-external-evidence-2026-10.md`](../research/feature-dimension-external-evidence-2026-10.md)）
§4.6 的结论是：「接着读」在成熟产品里 = **位置持久化 + 聚合入口**两件事，本项目**两件都没有**；
§5.4 把它列为待补项第 4 条。本 ADR 回答该条。

**范围勾回（2026-10-04，产品负责人裁定）**：本 ADR 最初只做「继续读（小说位置）」，
并把「浏览历史」判为不同概念而不重建。该判断**过窄**，已撤销。
`app-lynx-navigation-dimension-restructure.md` §4 的 **P1 承诺是「浏览历史 store + 小说阅读位置持久化 + 书架第三段接上」**，
而那条承诺的依据正是本节上方同一份 LINE WEBTOON 一手证据——
「我的漫畫」把「最近看過」与「同步閱讀紀錄」收在**同一个面**里，两者是并列条目而非二选一。
本 ADR 采纳该范围：📌 **两条轴按作品类型分工**（见 §2.1）。

> ⚠️ 顺带纠正一处口径：把两者放在一起**不是**未经论证的合并；
> **真正欠定义的只有生命周期**（浏览历史有 30 天过期、继续读不过期），
> 这一点在 §2.5 补齐。范围本身自始有一手证据支撑。

## 2. 决策

### 2.1 范围与入口

| 项 | 决策 |
|---|---|
| 📌 **两条轴的分工** | **插画 → 浏览历史**（行为流水，30 天过期）；**小说 → 继续读**（未完成事项，不过期）。按作品类型**天然不相交**，无需任何去重判断——打开小说**不会**在浏览历史里产生记录，反之亦然 |
| 书架段结构 | 变 **4 段**：我的收藏 / 稍后看 / **继续读**（段 3）/ **最近浏览**（段 4），各带自己的「查看全部」 |
| 顶层目的地 | **不新增**。浏览历史落书架**段 4**——ADR-0218 §3.3 已算清加第 5 个**顶层**目的地会导致外环重叠 ~10px（那约束的是导航环项数，与页内分段无关） |
| 聚合面 | 书架同时是本 ADR 两轴的容器。与 LINE WEBTOON「我的漫畫」的构成一致（最近看過 + 閱讀紀錄 + 我的最愛 同面） |
| 完整列表 | 两条轴各有次级页：`/continue`（继续读）与 `/history`（最近浏览） |
| 层级 | `/shelf` → `/continue` \| `/history` → 详情 = **2 层**，符合 NN/g 2 层上限（与 ADR-0218 §3.1 同一口径） |
| 继续读排序 | **最近打开时间倒序**（非作品创建时间） |
| 继续读段 3 展示 | 前 3 条（`PREVIEW_N = 3`，与段 1/2 一致），行 = 封面 + 标题 + 作者 + **「上次读到 第N话」** |
| 浏览历史段 4 展示 | 前 3 条，行 = 封面 + 标题 + 作者（**无状态文案**——浏览历史没有「读到哪」可言；与段 2 稍后看的区别在段标题而非行内文案） |

⚠️ **不做进度条**：Pixiv 不返回字数分布，百分比只能按话数占比**推算**；
单本小说（无系列）更算不出占比。⇒ 推算进度条是「看起来精确的假数据」，按禁静默降级红线不引入。

### 2.2 位置语义：会话末位置（**本 ADR 最核心、也最反直觉的一条**）

采用**会话末位置** = 记录**本次退出时读到的那话**，允许往回拨；**不**采用外部两个成熟产品的单调语义。

理由不是偏好，是**约束差异**：

- Kindle 取「最远水位」、Mihon 取「最旧未读」——**两者都需要单调语义，是因为它们有需要仲裁的冲突**：
  Kindle 同一本书在多台设备上各读各的，Whispersync 必须决定谁说了算，最便宜的规则就是取最远；
  Mihon 的 resume 语义与「未读」标记耦合，只能顺着未读往前走。
- **Pictelio 是本地单机，无跨端合并，不存在需要仲裁的冲突。**
  为一个不存在的冲突牺牲重读场景，不划算。
- 由此得到一个**外部两个产品都拿不到**的能力：用户在重读第 21 话时退出，
  再点继续读回到的是**第 21 话**（Mihon 会跳到第 63 话，有社区 issue 佐证）。

与 §2.4「完成后位置仍更新」串起来构成完整闭环：**会话末位置 → 完成后位置仍更新 → 重读场景正确**。

### 2.3 记录时机与完成判定

| 事件 | 行为 |
|---|---|
| 进入正文页（任一入口） | **立即记录**——门槛为零。`@scrolltolower` 或 `intro → body` 均触发 |
| 触底且为**单本小说**（无系列） | 标记 `completedAt`（软删） |
| 触底且为**系列的末话** | 标记 `completedAt`（软删） |
| **完成后再次进入该作品** | **完成态保留**，仅更新位置（不复活为「在读」） |

⚠️ **单本必须覆盖**：Pixiv 上单篇小说是最常见形态。若只判「系列末话」，
单篇用户将**永远无法完成**、条目永不离场——功能在主场景下失效。

⚠️ **可观测信号只有两个**：打开了哪本、是否触底。段内进度**不可观测**（§1），
因此不接受「停留 N 秒」「滚动超过 X%」这类门槛条件——那会造出依赖不存在信号的逻辑。

### 2.4 导航落点：扩展 `openNovel()`，**不绕过**单点缝隙

点击续读条目**无视介绍页开关直达正文**。实现方式**不是**在第七个入口旁开一条
`navigate('/novel/:id')` 捷径，而是给既有缝隙加**显式意图参数**：

```
openNovel(id, { resume: true })   // resume ⇒ 无论 novelIntroFirst 如何都进正文
```

理由：ADR-0183 已把六个入口的导航收进 `openNovel()` 单点，且
`tests/novelIntroEntryGuards.test.ts` 以**源级守卫**钉死「`/intro` 串只许存在于
`novelNavigation.ts`」。绕过缝隙会让该守卫转红，且把「这次要不要经介绍页」的决策
散落到调用点。扩展缝隙则让决策留在缝隙内部。

同时，介绍页主 CTA 依位置**改变文案与落点**（未读过 = 「开始阅读」从头；已有位置 = 「**继续阅读**」从该话起）——
单按钮形态不变，不新增视觉层级。

### 2.5 数据生命周期：**未完成事项 ≠ 行为流水**（两轴两套规则）

**这一节是两个 store 唯一的共享决策，其余全部各管各的。**

| 项 | 浏览历史（插画） | 继续读（小说） |
|---|---|---|
| 性质 | **行为流水** | **未完成事项** |
| **过期** | **30 天**（沿用 ADR-0094 先例） | **不设过期** |
| 触发 | 打开插画详情页 | 进入小说正文页 |
| 容量上限 | 300 条，超出丢最旧 + `console.warn` | 200 条，同策略 |
| 完成态 | 无（流水无「读完」） | `completedAt` 软删 |
| 排序 | 最近浏览时间倒序 | 最近打开时间倒序 |
| 备份域 | **不进** | **不进** |

- **为什么浏览历史要 30 天过期**：流水记录的价值随时间衰减，30 天后「我上周刷到的那张图」
  已经不值得召回。ADR-0094 当初定的 30 天在**这个对象上是对的**。
- **为什么继续读不设过期**：半年前在读的书今天回来继续是真实场景。
  过期 = 替用户删掉一件没做完的事。
  ⚠️ 这条曾被误用——ADR-0094 的 30 天一度被当作「全项目的历史类数据通用规则」，
  本 ADR 明确**否定**这种泛化：过期策略是**逐对象的**，不是按「历史」这个词统一施加的。
- **备份域**：已查证 `ACCOUNT_KEY_PREFIXES = ["show_r18_", "show_r18g_", "ai_filter_mode_"]`——
  **`watch_later_` 当前就不在备份域内**，本 ADR 两轴沿用同一条边界，不为它们单独开口子。
  两者的键各自带账号 uid 后缀（本机多账号互不干扰），但**不随 WebDAV 迁移**。
- **完成态**（仅继续读）：**软删**（`completedAt`），`/continue` 页可见可清。
  完成是用户资产；硬删后重读无任何入口 = 吞掉用户数据，违反测试硬约束 #3。
- **失效作品**（两轴同）：照常渲染 + 显式标注不可用 + 手动移除，**不静默隐藏**。
- **受限内容**（两轴同）：快照存 `xRestrict`（ADR-0094 旧模型已有该字段先例），
  列表**本地**判定走受限卡，零网络。不存则每行都要等网络才知道能否显示，
  且网络失败时「受限」与「加载失败」会被混为一谈。

### 2.6 度量：接现成本地读点，不新增设施

**段 3 与段 4 各接一次** `recordSectionObserved(name, empty)`，键名分别为
`'continueReading'` 与 `'browsingHistory'`
（`stores/usageMetrics.ts:111` 已有同族方法，签名 `(name, empty?)` 与分段形态严丝合缝；
`sectionSeen` / `sectionEmpty` 本就是通用字典，不限单一页面）。

`Shelf.vue` 当前对 usageMetrics 的引用数为 **0**——三段全部无读点，本 ADR 为段 3/4 补上。
该方法**零新增设施**且**无网络出口**（`usageMetrics` 隐私决策 5 = A：只存本地计数与时间戳）。

⚠️ **刻意不加**「续读条目被点击次数」：那需要给纯逻辑状态机加字段/方法/单测，
而**没有分母的点击数说明不了任何事**——这正是本仓 research §2.4 引 NN/g 的警告
（「不能只看点击量，因为用户可能只是点错了」）。

## 3. 后果

### 3.1 正面

- **兑现 ADR-0218 的 P1 承诺**（浏览历史 store + 小说阅读位置持久化 + 书架第三段接上）与其 §3.2 首条负面项。
- 📌 **粘性覆盖面比只做小说大一个量级**。继续读只在用户读过小说后才产生记录；
  浏览历史是**每一次浏览插画都产生记录**——在一个以图为主的客户端里，后者才是触达面的大头。
  （这是范围勾回的主因：初版只算了「位置」那一侧，漏了「浏览」那一侧。）
- **重读场景正确**——外部一手证据中两个成熟产品在此处均有用户投诉。
- **两轴按作品类型天然不相交**，零去重判断、零重叠数据、零自相矛盾的界面。
- **零新增网络出口、零新增依赖、零埋点 SDK**；存储复用 `prefs()` seam。
- **改动面收敛**：2 个新 store + 2 个新页 + `Shelf.vue` 段 3/4 + `openNovel()` 加参数
  + 介绍页 CTA 文案分支 + `IllustDetail.vue` 写记录 + 1 处 i18n。不动既有路由条目。

### 3.2 负面与已知失效面（**登记，不是待办**）

- ⚠️ **浏览历史的时间语义是「打开过」，不是「看完」**。用户在推荐流里误点开一张图也会留记录。
  30 天过期 + 300 条上限能约束体积，但**列表里必然有一部分是噪音**。
  未做「浏览超过 N 秒才算」这类过滤——那需要停留时长信号，且会把召回门槛抬高。
  若实测段 4 噪音明显，**处置方向是加过滤而不是加排序**。
- ⚠️ **粘性收益无法在本仓验证**。`revisitIntervalsMs`（相邻启动间隔）是**全局**指标，
  不会因本功能单独变化。两段读点能回答「功能被不被使用」（长期为空 = 无人在读；
  非空但零点击 = 位置存错或入口过深），**不能**回答「粘性因此提升」。
  后者需发布前后的整体复访间隔对比，属发版观测。
  **本仓无发布前后基线**，故此项**不作为验收条件**——若日后要量化，需单独立项。
- ⚠️ **段内位置仍不可恢复**。继续读只做到**话级**。用户读完第 5 话的一半再退出，
  回来还是从第 5 话开头。若引擎日后恢复 `main-thread-bindscroll` 派发，
  可加段级坐标——**本 ADR 不承诺该时间表**。
- ⚠️ **「章」的词面歧义**。Pixiv 的 novel 在产品语境里被用户叫「章」，
  但 Pixiv 自身不用这个词。UI 文案用「第N话」而非「第N章」（Pixiv 小说是**话**体裁）。
- ⚠️ **无 E2E 覆盖**。`android-e2e/specs/` 现有 10 个 spec 均不涉及书架；
  android-e2e 不进 CI（ADR-0084）⇒ 本功能的端到端验证是**手动**的，回归防线只有单元测试。
- ⚠️ **完成态可能被误判**：`@scrolltolower` 触底即算读完。若用户打开只为看最后一段，
  会被记为已完成——但 §2.3 定的「完成后位置仍更新 + 状态不复活」使误判可自愈。

### 3.3 与外部做法的差异登记

| 维度 | Kindle | Mihon | LINE WEBTOON | **本项目** |
|---|---|---|---|---|
| 位置粒度 | 页 | 话 | 话 | **话**（引擎约束） |
| 推进语义 | 最远水位 | 最旧未读 | 集数记录 | **会话末（可回拨）** |
| 跨端 | 有 | 插件可选 | 有 | **无** |
| 重读正确性 | ❌ | ❌（有 issue 佐证） | 未取证 | **✅** |
| 浏览历史 | 混在 `last reading location` 里 | History 页 | **「最近看過」与「閱讀紀錄」并列同面** | **段 4 浏览历史与段 3 继续读并列同面** |
| 流水过期 | 未取证 | 未取证 | 未取证 | **30 天**（沿 ADR-0094） |
| 入口 | 书库 | 书库/历史 | 我的漫畫 | **书架段 3 + 段 4** |

## 4. 落地时必须同轮改写的既有描述（**否则它们当场变假**）

以下三处描述的是**当前状态**而非机制。本功能落地会使命中它们为假，
**必须与实现同轮提交**——留到后续会让文档开始说谎：

| # | 位置 | 现描述 | 须改为 |
