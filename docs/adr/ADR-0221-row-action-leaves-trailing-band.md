# ADR-0221：行内动作离开行尾——遮挡带是行尾的「固定占用者」

- **状态**：已接受（票 #932）
- **日期**：2026-10-07

- **术语文档**：[./glossary-app-lynx-hit-testing.md](./glossary-app-lynx-hit-testing.md)（**权威**：遮挡带 / 行内动作 / 行尾动作 / 行首动作）、[./glossary-bottom-occlusion-allowance.md](./glossary-bottom-occlusion-allowance.md)（竖直轴，交叉引用）

## 1. 背景

票 #932：`/continue` 行的行尾「移除」按钮被悬浮搜索 FAB 遮挡，**点它开的是搜索弹层，不是删除**。

真机像素 + 点按双重取证（emulator-5554 / 1080×2160）：

| 量 | 实测 |
|---|---|
| GlobalFab 水平带 | `x[872,1033]` = **80.741vw..95.648vw**（理论导出 80.8..95.733vw，差 <1px 为栅格化粒度） |
| 行尾药丸 | `x[867,1021]`，宽 154px |
| **落在带内的宽度占比** | **149/154 = 97%** |
| 点被压区（y=1391） | 100% 触发搜索弹层 |
| 点露出区（y=1350） | 正常移除 |

### 1.1 为什么 ADR-0217 治不了它

`FabAllowanceSpacer` 是**滚动内容末尾**的零内容占位，它保证**末项**能滚到 FAB 上方——那是**竖直轴**。
本缺陷发生在**水平轴**，且发生在**中间某行**。`/continue` 的末项让位齐全，照样被吞点击。

⇒ 两者**正交**，必须各自成立。术语文档已把这条对照写成表（`glossary-app-lynx-hit-testing.md` §边界约定）。

### 1.2 一条更强的性质：遮挡带与路由档位无关

`fabCx = 100 - FAB_EDGE_VW - FAB_SIZE_VW/2` 只用两个常量，**两档的水平带完全相同**；
`routeMode` 只改 `top`。⇒ 「`search` 档才会撞上」是**错觉**：`menu` 档页（4 个顶层 tab）
同样横向暴露，只是 FAB 竖直位置低（4.267–19.2vw）且 19.2vw 让位恰好护住末项。

## 2. 决策

**行内动作不得落在行的尾部。** 凡有 GlobalFab 的页面，行内动作一律置于**行首**，形态为
10.667vw（40dp）圆形图标按钮。

**理由不是「离 FAB 远」**——那是个依赖 FAB 位置的弱表述。真正的理由是：

> **行的尾部被固定几何占用了。** 遮挡带 `[80.80, 95.73]vw` 由 FAB 自身尺寸与右距导出，
> 与路由无关、与档位无关。尾部因此不是「偶尔空出来的地方」，而是**恒定不可交互区**。
> 这条性质在 FAB 移动、隐藏或收起之后**依然成立**——它是几何恒等式，不是当前布局的巧合。

### 2.1 为什么不用「加水平让位」（方案 A）

行尾药丸要让开带内，行右缘须退到 80.8vw ⇒ 每行**永久**让出 ~13.9vw（屏宽 13.9%）。
`search` 档页几乎全是全宽行 ⇒ 右侧长期空掉近 1/5 屏宽，且**标题被迫换行**（原型实测：
「百合の生活『買い物編』」由 1 行变 2 行）。

### 2.2 为什么不用「FAB 滚动收起」（方案 C）

原型实测有效，但：① **静止态不解决**（截图可见静止时 FAB 仍在原位、仍重叠）；
② ADR-0217 §2.1 明确「不推荐」并自述**「这是产品判断，非平台限制」**⇒ 推翻它需要新 ADR，
且推翻理由（FAB 外环是 4 个 tab 的导航入口）与本缺陷无关。

### 2.3 为什么不用 `delete` 字形而沿用 `close`

「移除」的语义字形是 `delete`(e92e)，它在官方 codepoints 里存在但**未登记**进 `ICON_CODEPOINTS`。
登记它需改 `iconMap.ts` **并重跑 `scripts/generate-icon-subset.py`**——该脚本需**联网下载源字体**
并依赖 fonttools，产物是**提交的二进制 TTF + base64 CSS**。

为一个遮挡修复引入「联网 + 二进制字体产物」的重生成，**与本次修复不成比例** ⇒ 沿用已登记的 `close`。
⚠️ 代价已登记：`close` 在 `iconMap.ts` 的语义注记是「✕ 关闭」，此处承载「移除」是**语义借用**。
若日后要真 `delete` 字形，应另开图标登记票，不与本票捆绑。

## 3. 代价（诚实登记，不粉饰）

1. **行首不是零成本**：缩略图也在行首。实测缩略图左缘 **6.20vw → 18.43vw（右推 12.2vw）**。
   但行尾药丸（14.3vw）同时被移除 ⇒ **标题列净变化 ≈ +1vw**。动作的占位是**搬移**不是**新增**。
   ⚠️ 该净值依赖标题的 `[max-line:1]`；日后再动封面尺寸会改变它。
2. **破坏性动作失去视觉严重性线索**：`MuteTags` 的移除文案刻意用 `text-error`。
   统一为图标按钮后**必须保留 error 语义**（图标染 `text-error`），否则破坏性动作与普通动作同形。
3. **按压反馈从"看得见文字"退化为"只有图标"**：拇指遮挡下唯一线索就是状态层。
   ⇒ 4 处中有 3 处**当前没有**按压状态层（仅 `MuteTags` 有），本次**一并补齐**收敛到
   `active:bg-layer-pressed-on-surface` + `pressColor.className`（ADR-0211 决策 2 载体）。
   ⚠️ utility 必须是**顶层** `bg-layer-pressed-*`；嵌在 `state` 下会产出 `bg-state-layer-*`
   ——**不同名的死类名、静默无样式**。
4. **朗读顺序变了**：由「行 → 动作」变为「动作 → 行」。屏读用户先听到破坏性动作再听到导航目标。
   属 B 的固有代价，**接受**。且见 §6：当前 SDK 上这条基本不可验证。
5. **40dp 触控目标沿用而非新增**：4 处现状本就是 `h-[10.667vw]` = 40dp，已低于 Android 48dp
   建议值、但过 WCAG 2.2 AA(24px)。本决策**沿用既有偏差**，不新增、不修（修是独立票）。

**本次处理（4 处，均为破坏性、无二次确认或低代价）**

**后续处理（3 处，非破坏性；票 #950 / #951，2026-10-12）**

上一批的四处全是**破坏性**动作（硬删 / 有确认层），图标化零信息损失。剩下三处的形态债
在同一天结清，处理方式与上一批**不同**，故单列：

| 站点 | 动作 | 路由 | 与上一批的差别 |
|---|---|---|---|
| `components/UserRow.vue` | 关注 / 取关 | `/user/:id/following`、`/user/:id/followers`、`/mypixiv` | **有状态 toggle**：原靠「关注」/「已关注」文案表达状态，改纯图标会丢可发现性 |
| `pages/IllustDetail.vue` | 关注作者 | `/illust/:id` | 同上 |
| `components/RankingEntryCard.vue` | 收起 ✕ | `/illusts` | `absolute` 浮层，非行内 flex 动作 |

**怎么保住状态语义**（这是本批唯一的真问题）：字体子集里**没有** `person_add` /
`person_check`（仅 `person` / `check` / `favorite_border`），故**两处关注开关**（`UserRow` /
`IllustDetail`）一律**两态同用 `person` 图标 + 沿用原有的填充对比**（未关注 = outline 边框 + 透明底，
已关注 = `bg-primary` 实心 + 反色）——与被替换的药丸同一套视觉语言，未新造语义。
（第三处 `RankingEntryCard` 的收起 ✕ **无两态**，用的是 `close` 图标，不适用本段。）
文字移除后，状态**只**由 `accessibility-label` 承载，三处全部补齐；
「每个 `:accessibility-element` 配一个 label」这条既有配平契约同步扩展（见
`IllustDetail.template.test.ts` / `UserRow.template.test.ts`）。

顺带修掉一个原有抖动：药丸是 `px-4` + 变长文案，「已关注」比「关注」宽，切状态时会挤动内容；
改为固定 10.667vw 圆形后不再抖。

**刻意不处理（登记在案，避免下个 reviewer 当成遗漏）**

| 站点 | 为什么不处理 |
|---|---|
| `components/SearchSheet.vue:438`（历史 ✕） | 在 modal 内 ⇒ `hasOpenModal` 强制 `mode='hidden'`，**不可能重叠** |
| `pages/NovelIntro.vue:528-536` | 动作行钉在页面底部，与 FAB 竖直带（43.7–58.7vw）不交叠 |

> ⚠️ **已验伪并移出登记**：`pages/UserHome.vue`（关注数 / 粉丝数 chip）。
> 本表当初对它的措辞是「非破坏性导航 chip」、**从未声称「同带重叠」**——是票 #951
> 把它们归进「三者均落在 GlobalFab 遮挡带内」时顺带算进去的。静态复算：卡片 `m-3 p-3.5`
> ⇒ 内容盒 6.73–90.27vw，头像 17.067vw、内容列 `ml-3.5` ⇒ chip 行起点 27.0vw；两个 chip
> 宽度由文字决定（各 `px-2`），合计约 35vw ⇒ **右缘 ≈ 62vw，距带左沿 80.80vw 尚有约 19vw**。
> 它们是**内容不是动作**，搬到行首反而是语义错误 ⇒ 正确处置是**移出登记**，不是改代码。
>
> **2026-10-12 补真机像素取证**（ADR §5 要求的第 2 项，此前缺）：`emulator-5554`
> （pictelio_ui，1080×2160 / density480 / Android14）实测 chip 行右缘 **56.8vw**（≈613px），
> 距带左沿 80.80vw 差约 24vw ⇒ **不在带内**，与静态估算同向且更保守。
> ⚠️ 同时**收窄**原结论的强度：chip 宽度由文字内容决定，模板对 chip 行**无** `max-w` /
> `[max-line:1]` / `shrink-0` 约束，故「~19vw 余量」**不是常数**——关注数位数增长或切到
> 英文 locale（`"{{count}} following"`）都会把它推宽。原句「远大于任何合理误差」已删除：
> 正确表述是「**在已实测的该账号数据下**成立」。本条按内容站点登记留痕，不改代码。

## 5. 取证要求（不得降级为「看起来对」）

原生 LynxView **不识别 `pointer-events`**（ADR-0123），且 Lynx a11y 树**不导出** FAB 节点
⇒ 「能拿到结构坐标」这条路在本页**走不通**。

验收必须落在**行为**上：

1. **点按取证**：在被遮挡的行尾位置 `input tap`，断言**动作被触发**（条目数变化 / 确认框出现），
   且 `logcat` 中**无** `sheet-enter`。
2. **像素取证**：测出行首按钮右缘 < 遮挡带左缘（80.8vw），且**留有间隙**（贴边不算通过——
   贴边时命中归属没有余量）。

---

## 6. 不宣称的事项（防下一个 agent 过度归因）

- 本 ADR **不**宣称修好了或保持了屏读可达性。Lynx 4.0.1 的 a11y 树只暴露表单元素
  （ADR-0061:130，ADR-0209:169-172 真机复现：`uiautomator dump` 得 0 个 Lynx 节点），
  且行级 `accessibility-label` 会吞掉子文本（`ContinueRow.vue:56-57` 已登记）。
  ⇒ 「行尾药丸的标签没出现在 dump 里」**很可能是 SDK 既有限制，不是本票造成的**。
- 本 ADR **不**宣称底部让位机制有任何问题。`FabAllowanceSpacer` 依然全绿、依然必要。

## 7. 后果

- 首批 4 处行尾动作改为行首图标按钮（票 #932）。**真机点按取证只覆盖两页**：
  `/continue`（点按删除成功、无搜索弹层）与 `/watchlist`（点按弹出取消确认框、无搜索弹层）。
  `/later` 与 `/mute-tags` 在验证环境为**空态**（无数据、动作无法触发）⇒
  **仅代码与静态验证，取证待补**——不得把这两页记作「已验证」。
- 本批 3 处（票 #950 / #951）**已完成 §5 的双项取证**（2026-10-12）：点按 + 像素两项都有，
  两台模拟器各跑一轮。`emulator-5554`（pictelio_ui，1080×2160 / density480 / Android14，
  ADR 参照机）：关注开关落在 **9.6vw**（UserRow）/ **12.2vw**（IllustDetail）、收起 ✕ 落在
  **10.5vw**，均远在带左沿 80.80vw 之外；图标正常渲染（非豆腐块）；点按后**实心蓝 → 描边 + 蓝图标**
  证明 toggle 真触发，且未误开搜索弹层。`emulator-5556`（pictelio_low，720×1280 / density320 /
  Android9）作跨规格冒烟：安装 / 启动 / 榜单卡渲染正常，无 `FATAL EXCEPTION`。
- 静态门禁现覆盖 **7 处站点**（`LEADING_SITES` 4 + `LEADING_FOLLOW_ACTIONS` 2 + `DISMISS_SITE` 1），
  债务登记 `BAND_DEBT` 已于 2026-10-12 **清空**（#950 / #951 结清）。⚠️ 门禁**不做全仓扫描**，
  其抓不到什么见该文件内的显式登记。E2E 不进 CI，不足以单独构成防线（见 ADR-0084 与
  AGENTS.md「门禁边界」）。
- 4 处按压状态层收敛为一致形态。
- **票 #957 收窄了「豁免失效」的实现缺口**（2026-10-11）。§7 原承诺「票关闭后豁免必须失效」，
  但门禁原先只校验 `toContain(标记字符串)`：**保留下标记的修复能骗过它**，豁免会静默存活。
  现改为校验**站点仍真在行尾**（源码顺序 / 尾推类，均为门禁已在信的静态判据，不引入几何推断）
  ⇒ **站点修好即豁免自动转红**，不再依赖任何人记得来删登记。
  ⚠️ **残留缺口（物理限制，不可再收窄）**：CI 内读不到 GitHub 票状态（不调 `gh`、无网络），
  故「**票被直接关掉而站点并未修复**」仍不会让门禁变红。该缺口只能靠关闭流程兜底：
  **关票前必须先让对应站点转红、或删除该条登记**。⚠️ 不得把这里的全绿读成「票与站点一致」。
- **门禁自身的判别力缺口，同日补上**（2026-10-12，由 review–fix 闭环第 1 轮查出）：
  ① 债务登记清零后，「站点修好即豁免自动腐烂」这条判据在真实站点上**执行实例为 0**，
  而它周围全是 `.not.toMatch` —— **全称否定断言在集合为空时恒真**。当时把尾推正则改成永不命中，
  整份门禁**仍然全绿**（ArchUnit `failOnEmptyShould` 同款陷阱）。现把判定抽为纯函数
  `judgeStillInBand`，并补一组**不读任何项目文件**的合成模板自检，双向证明判据会红。
  ② 同一自检还查出尾推正则的**两侧边界漏判**：`class="…"` 的首个类前面是 `"`、末个类后面是 `"`，
  原判据只认 `^` / 空白 ⇒ **类属性首/末位一律漏判**。实测漏网 6 处 `justify-between"`
  （`Me.vue` / `SearchSheet.vue` / `SettingsEndpoint.vue` ×2 / `RelatedInlineSection.vue` /
  `NovelDetail.vue`）。已改为两侧都认 `"` 作边界，并把裸 `absolute` 从枚举移除
  （靠不靠右取决于 `left-*` / `right-*`，`right-*` 已覆盖；留着它只会让每个绝对定位元素都误判）。
  ⚠️ **但这 6 处按设计仍不在门禁视野内** —— 扫描能力已整体删除，本门禁只读那 7 处登记站点，
  边界修复只提升「未来新增站点被登记时」的可判定性，**不追溯覆盖存量**。
  同轮补入 `order-first` / `order-last` / `order-<数字>`（同 `flex-row-reverse` 的论证：
  `order` 在本工程 preset 白名单内会产真规则，而全仓 `src/` 零使用 ⇒ 加它零成本）。
  检出实验：同一变异（`justify-between` 置于类属性末尾）下**新判据红、旧判据绿**。
- **门禁自检的判别力仍有一个自由度是空的，已补上**（2026-10-12，外部复核第 2 轮查出）：
  上述自检**只钉住了「极性」**（判为真 / 判为假），**没钉住「测量范围」** —— 把
  `openTagAt(tpl, actionAt)` 换成 `tpl`（量得太宽），自检原本**仍然全绿**，因为两条夹具都是
  单行、尾推令牌恰好就在动作元素自身。危害不是假想：`RankingEntryCard.vue:141/152` 本来就有
  两处与收起 ✕ 无关的 `right-*` 令牌，量宽后它们会替一个**已修好**的站点「续命」——
  而「站点已修好、豁免却静默存活」正是 #957 要杀的方向。已补一条夹具：动作在行首且自身
  开标签干净、模板**后段**另有 `right-*` ⇒ 必须判「不在带内」。复验：同一攻击现确定性转红。
  ⚠️ 同一轮还构造出**新的已知失效面**并已登记到门禁文件头失效面 6：`openTagAt` 返回完整开标签，
  `"` 成边界后**任何属性值**里的枚举词都会造成假阳性（如 `data-bandprobe="ml-auto"`）。
  收窄办法是只取 `class="…"` 的值再判；本轮不做（改判据本体须重跑一轮抗攻击复核），
  故**显式登记**而非当作已解决。
