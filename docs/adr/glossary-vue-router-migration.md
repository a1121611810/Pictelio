# app-lynx 路由迁移统一术语表（vue-router memory history）

> 范围：`packages/app-lynx` **自研内存路由（`src/router.ts` + `src/routerCore.ts`）→ 官方 vue-router（`createMemoryHistory()`）** 迁移的统一术语。结论来源：[vue-router 迁移可行性探针](../research/vue-router-migration-feasibility.md)（分支 `prototype/lynx-vue-router`，2026-09-03 双端实证，含系统返回桥、守卫鉴权、会话 epoch 共五轮）；语义保持的既有决策：ADR-0066（系统返回桥）、ADR-0049（极简历史栈）、#61/#63（首帧内容化）。本表只定义领域语言，不写实现；实现细节（shim 接口、探针代码）以可行性文档为准。

## 核心术语

| 术语 | 定义 | 与旧自研对照 |
|------|------|--------------|
| **内存路由（in-memory routing，自研）** | app-lynx 现役的极简路由实现——`src/router.ts` 的 `_state` ref（RouteState）+ `src/routerCore.ts` 的 `matchRoute` 纯函数 + App.vue 的 `<component :is>` + 自跟踪栈 `_history`。语义与 vue-router 对齐（path/name/params），无 URL 环境。迁移后整体退场，router.ts 变薄 shim。_Avoid_: 用「自研路由」泛指一切手写匹配（含 webview 端）；与下文官方 memory history 混称。 | = 本词条即旧实现（对照终点）；其语义由官方 memory history + shim 维持 |
| **vue-router memory history（官方 createMemoryHistory）** | 官方路由的内存历史模式：`createRouter({ history: createMemoryHistory(), routes })`，不读写 URL。官方特殊性**仅两点**：初始位置为 nowhere（须手动指定**首启动点**）、设计用途是无 URL 环境（SSR/原生）；其余能力（参数/KeepAlive/守卫/触发返回）与普通 history 一致。`RouterHistory` 接口成员 `location`（只读 live getter）/`go(delta, triggerListeners?)`/`push|replace(to, data?)` 双端实证可用。_Avoid_: 期望内存 history 自动初始导航（nowhere 特殊位置）；把 `history.state` 当 `{back, current, forward}`（那是 `createWebHistory` 的浏览器态；memory 的 `state` = **每条目可携带的数据**，默认 `{}`——第四轮实证修正）。 | 同时替代自研 `_state`（当前路由）+ `_history`（历史栈）两个数据结构 |
| **路由表（route records）** | `createRouter` 的 `routes` 数组：`{ path, name, component, meta }`。app-lynx 的 15 条路由 **1:1 搬迁**；`backBehavior: 'exit'` 由自研 route 顶层字段迁入 `meta.backBehavior`（vue-router 不认自定义顶层字段），新增 `meta.requiresAuth` 供全局守卫。_Avoid_: 给 record 加自定义顶层字段（必须经 meta）；在 `redirect` 记录上再声明 backBehavior/meta 语义（易被忽略）。 | `RouteDef`（path/name/component/backBehavior）→ vue-router `RouteRecordRaw`（path/name/component/meta） |
| **首帧内容化（first-frame content）** | 启动**首帧直接渲染推荐页**（骨架屏）、不等登录态恢复完成的启动体验（#61/#63）——消除已登录用户启动时的登录页闪屏；未登录用户由 initRouter 收敛 replace 到 /login（不入栈）。迁移后 = 模块顶层同步 `router.replace('/recommended')`（memory history 不主动触发初始导航；官方示例在 `app.mount()` 前 `push`，探针按官方顺序实证）。_Avoid_: 首帧前 `await restoreToken`（闪屏回归）；用 `push` 定起点（登录页入栈、被返回键可达——应为 replace）。 | 自研：`_state` 初始值即 `{ name: 'recommended', path: '/recommended' }` → 官方：顶层 `router.replace('/recommended')`（顺带承担**首启动点**职责） |
| **先渲染后加载（render-before-fetch）** | 项目级硬约束（根 `AGENTS.md`「即时导航硬约束」）：用户主动进入任何页面时必须**先渲染页面框架（含骨架屏）再发起数据请求**，禁止路由级 loader/middleware 以 await 网络阻塞渲染。迁移后的直接推论：全局守卫**必须同步判断、绝不 await 网络**（探针第 22 行实证：守卫内 800ms await → 该次受保护导航被延迟且 RouterView 空白至守卫结束）。_Avoid_: 守卫里 await restoreToken（首帧成空白）；借 vue-router 的导航守卫做数据预取。 | 旧自研无路由级守卫，约束由页面自理落地（`ensureAuth`/页面 watch 补拉）；迁移后守门点在**守卫写法和 bootstrap 放行** |
| **系统返回桥（system back bridge）** | 原生侧 `LynxActivity` 的 `OnBackPressedDispatcher`（返回键 + 侧滑手势**同路径**）拦截后经全局事件 `pictelioBack`（`sendGlobalEvent`）转发给 JS、由 JS 裁决的通道（ADR-0066）。错误页/未加载时原生直接 finish。**迁移方案原生侧不动**，JS 侧 `handleSystemBack` 拦截后注入裁决链。web-core 预览无 GlobalEventEmitter → 静默跳过（属预期）。_Avoid_: 把返回裁决搬回原生（历史形态已否决）；在 web 预览下验证返回行为（该桥不存在，用页面内返回按钮）。 | 不变（原生侧零改动）；JS 侧入口 `handleSystemBack` 的裁决依据从 `_history`/`matchRoute` 换成 `hasBackEntry()`/`currentRoute.meta` |
| **返回裁决链（back decision chain）** | JS 侧系统返回的逐级裁决顺序：① modalStack 有打开弹层 → 关弹层（返回键优先关弹层）；② 返回守卫拦截 → 消费本次返回；③ `meta.backBehavior === 'exit'` → 直接退出应用（不可回退到失效会话）；④ `hasBackEntry()` 为真 → `router.back()`；⑤ 无历史 → 提示「再按一次退出应用」+ 2s 窗口内再按 → `exitApp()`。旧自研等价物 = `evaluateBackRoute`（routerCore 纯函数，node 单测覆盖）；**裁决顺序本身不变**，仅③④的实现来源换为 vue-router 等价物。_Avoid_: 重排裁决顺序（modalStack 最前是「返回键优先关弹层」的语义；backBehavior 判定放在守卫之后会破坏 exit 页的安全语义）。 | `evaluateBackRoute`（modalStack → back-guard → `evaluateBackWithBehavior`）→ 同顺序，③读 `currentRoute.meta.backBehavior`、④用 `hasBackEntry()` 替代 `_history.length > 0` |
| **返回守卫（back-guard）** | 页面级返回拦截注册表：`registerBackGuard(guard)`，guard 返回 true = 本次返回已被页面消费（路由层不再 pop/回退），如小说详情页追更询问（spec app-lynx-novel-series-watchlist §US3，issue #222）。`requestBack()`（页面内返回按钮）与系统返回**共用同一守卫链**（两条返回路径行为一致）。注册表与裁决纯逻辑在 routerCore（node 可单测），router.ts 薄接线。守卫抛错 fail-open（warn + 按未拦截处理，守卫 bug 不卡死返回键）。_Avoid_: 把「询问弹窗」当 modalStack 弹层注册（弹层关掉了守卫询问就没机会弹，语义不同）；守卫做破坏性操作后返回 false。 | 完全保留（`registerBackGuard`/`requestBack`/`runBackGuards` 是 shim 页面调用面成员，注册表在 routerCore 不收编） |
| **hasBackEntry()** | 「能否返回」的**队列探测原语（官方 API，看门狗）**：`history.go(-1, false)` 静默移动指针 → `history.location` 比对（移动了 = 有上一页）→ 立即 `go(1, false)` 还原。`triggerListeners = false` 是官方文档化参数，保证不触发监听/守卫；同步原子（JS 单线程无 await 间隙）、无副作用。**经 code-review 修订（P1-2）：不再是「能否返回」的决策主源**——它无法识别 memory 队列中的旧会话残留条目（登出→重登录后仍判 true）；主源为「会话镜像栈」，本原语与其**并行取交集**（镜像非空 ∧ 队列真 = 可返回），充当镜像漂移的看门狗。_Avoid_: 用 `history.state` 探测能否返回（= 条目数据，非 back/current/forward 结构）；把本原语单独当决策主源（旧会话残留回车）；拿 `go()` 探针结果直接当导航（必须还原）。 | 替代自研 `_history.length > 0`（自跟踪栈计数）；与「会话镜像栈」组合为 `hasBackEntry()` = 镜像非空 ∧ 队列探测 |
| **会话镜像栈（session mirror stack）** | 与官方历史并行的会话级镜像栈（旧 `_history: string[]` 同构，生产实现 `_sessionStack`）：导航（`navigate` push/replace 语义）记录、`resetHistory`/`markSessionEstablished` **物理清空**。**「能否返回」的决策主源**——`hasBackEntry()` = 镜像非空 ∧ `hasBackEntryIn` 队列探测（看门狗）；`goBack` 弹栈先行、漂移（镜像与队列不一致）时清镜像降级回推荐页。**定稿理由（code-review P1-2）**：物理清空承载「清栈」语义（登出→重登录后旧的队列条目不可再经返回键进入），纯官方 API 探测无法覆盖该会话边界。_Avoid_: 绕过 shim 的导航（镜像失真——看门狗兜底但会降级）；把镜像当唯一判据（队列探测看门狗保留）；在会话边界外随意清镜像。 | 旧自研 `_history`（ADR-0049）→ 迁移后以「会话镜像栈」形态保留，弥补 pure API 无法识别旧会话残留条目的缺口 |
| **会话清除（session clear / 清栈语义）** | 登出/会话失效后「业务页不可达」的语义等价物：**forward**（任何业务页导航）由全局守卫重定向 /login（replace）；**back** 由 `canBack = 会话镜像栈非空 ∧ 队列探测（hasBackEntryIn）∧ !cleared` 判定（false 时返回键只走提示/双击退出）。**清栈语义 = 镜像栈物理清空（会话级）**——登出/重登录后旧 memory 队列条目不可经返回键进入（code-review P1-2 修订；纯 cleared 标记无法识别重登录后的旧条目）。`cleared` 置位点 = 登出/会话失效（`resetHistory()`）；清除点 = 登录成功（beginSession 语义）。/update、/error 的「不可回退」由 `meta.backBehavior: 'exit'` 承载。_Avoid_: 登出后 back 仍可达业务页（会话泄漏）；期望 `replace` 到 /login「清空」历史（replace 只覆盖当前条目，镜像栈必须物理清空）；纯 `cleared` 标记当唯一清栈（重登录后恢复 false → 旧条目泄漏，P1-2）。 | 自研 `resetHistory()` 清 `_history` 数组 → 迁移以「会话镜像栈物理清空 + cleared 语义拦截」承载（守卫管 forward、canBack 管 back） |
| **全局守卫鉴权（global auth guard）** | `router.beforeEach` + `meta.requiresAuth` 的路由级鉴权拦截（可行性文档 Q3 定论：**采用**）：未登录访问受保护路由 → `return { path: '/login', replace: true }`（replace 语义实证无报错）；已登录放行。配套设计规则：**守卫同步判断、不 await 网络**（await 会空白首帧）；bootstrap 期放行（见下条）；会话清除拦截 + `cleared` 置位（见「会话清除」）。**`requiresAuth` 只标业务页，/update、/error、/login 不标**（P0-1：/update、/error 恰在会话清除后经 cleared 语义进入，标了会被守卫自身重定向回 /login）。与页面侧分工：守卫是「拦截层」，鉴权失败的业务兑现由页面 401 兜底 + initRouter 收敛（沿用现状）。_Avoid_: 守卫 await 网络/调 restoreToken；对未声明 `requiresAuth` 的路由做鉴权（显式声明）；把页面级生命周期逻辑塞进守卫；给系统页（/update、/error）标 requiresAuth。 | 旧自研无路由级守卫，靠页面 `ensureAuth()`（restoreToken + 失败 redirect /login）；迁移后成为首道拦截，语义层保留「登录态未就绪 → 页面 401 兜底」的既有容错 |
| **bootstrap 放行（bootstrap pass-through）** | 守卫在 bootstrap 期（`restoreToken` 未完成、登录态未知）**直接放行**的规则：首帧先渲染（首帧内容化 + 先渲染后加载不被破坏）；鉴权后果由两条兜底收敛——页面 401 兜底（沿用现状）+ `initRouter` 收敛（restoreToken + loadSettings 完成后为定局：未登录 → 后续受保护导航被守卫重定向 /login）。探针第 21 行实证：bootstrap 放行时首帧 t=1.2s 已有内容，无空白。_Avoid_: 守卫等 bootstrap 完成（= await 网络，首帧空白）；放行条件写成除「bootstrap 未完成」以外的宽泛形态。 | 对应旧自研 initRouter 的时序语义（`_state` 初始即 /recommended、`restoreToken` 后 replace 收敛）；迁移后该语义显式化为守卫规则 |
| **路由 meta（route meta）** | route record 的 `meta` 字段承载的**路由级声明数据**：`meta: { backBehavior: 'exit' }`（返回键直接退出应用；/update 强制更新页、/error 会话失效页）、`meta: { requiresAuth: true }`（全局守卫鉴权目标）。裁决层读 `currentRoute.meta`。_Avoid_: meta 里放组件级会话态（应留 store/组件）；运行时改动 meta 控制路由行为（应经导航）；用同义重复键（如 `auth: true` 与 `requiresAuth` 并存）。 | 自研 `RouteDef.backBehavior?: 'exit'` 顶层字段 → 迁入 `meta.backBehavior`；`requiresAuth` 为新增键 |
| **KeepAlive 白名单（KeepAlive include）** | App.vue 路由出口形态：`<RouterView v-slot="{ Component }"><KeepAlive :include="[...]"><component :is="Component" /></KeepAlive></RouterView>`（**必须 PascalCase**，见 kebab-case 陷阱），`:include` 数组为 tab 页路由名（推荐/插画/小说/我的）。身份契约：组件 `defineOptions({ name })` = 路由 name（生产页面已有此惯例，管理 1:1 兼容）。_Avoid_: 路由 name ≠ 组件 name（KeepAlive 匹配静默失效）；把详情页等非 tab 页加入白名单（缓存膨胀）；用 `:exclude` 反向黑名单（页面多、易漏）。 | 自研 `<component :is="currentComponent">` 包 KeepAlive（App.vue ~3 行改动）；白名单组件名约定不变 |
| **kebab-case 陷阱** | vue-lynx 模板编译器把**带连字符的标签**当原生自定义元素：`<router-view>`（kebab-case）编译产物为自定义元素 `router-view` → Vue 不渲染任何内容（带 `v-slot` 时编译报 `VueCompilerError: v-slot can only be used on components`；不带 slot 时**静默渲染为空**，探针复现纯白屏）。**这就是 router.ts 注释声称「RouterView 渲染为空」的真正根因**（与 vue-router 兼容性无关）——规则：模板必须写 PascalCase `<RouterView />`；其它带连字符组件同理（本项目现有组件均 PascalCase，无新风险）。_Avoid_: kebab-case `<router-view>` / `<router-link>`；再把「RouterView 空」归因 vue-router 兼容性（首轮断言已证伪，迁移无需再验证）。 | 旧自研无 RouterView（`<component :is>` 天然规避）；迁移是新引入的专有风险，规范落点在代码评审与模板断言 |
| **首启动点（starter location）** | memory history 的初始位置是 **nowhere 特殊位置**（无自动初始导航），必须由用户 `router.push()` / `router.replace()` 指定起点（官方示例在 `app.mount()` 之前执行，探针按官方顺序实证可行）。app-lynx 生产语义 = **首帧内容化**：模块顶层 `router.replace('/recommended')` 即首启动点。_Avoid_: 依赖 `createMemoryHistory()` 自动导航（不指定起点 RouterView 渲染空/无匹配）；把定起点放在异步回调后（首帧时序漂移）；对起点用 push（入栈语义，见首帧内容化）。 | 自研起点 = `_state` 初始值（模块级常量）；官方 = 顶层显式 `replace`（memory history 特殊性之一） |
| **页面调用面（page call surface）** | 迁移后 **shim 保留的对外 API 集合**：`navigate(path, opts?)`、`goBack()`、`requestBack()`、`ensureAuth()`、`registerBackGuard(guard)`、`exitHint`、`currentParams`（另有 App.vue 消费的 `routeState`/`currentComponent` 换为 `router.currentRoute` + `<RouterView>`）。承诺：15 条路由的**页面调用方零改动**，工作量集中在新 shim 单测与 routerCore 适配。_Avoid_: 页面直接 import vue-router（应经 shim，保留换实现余地）；在 shim 之外再向页面暴露 RouterView/useRoute 等新 API（先迁移默认形态，按需再开放）。 | `navigate`/`goBack`/`requestBack`/`ensureAuth`/`registerBackGuard`/`exitHint`/`currentParams` 同名同签名；内部实现换 vue-router 等价物（`router.push/replace/back`、`currentRoute.value.params` 等） |

## 边界约定

- 本表只定义领域语言；`hasBackEntry()`/`hasBackEntryIn` 的具体实现（go(-1,false) + location 比对 + go(1,false) 还原）、`cleared` 的置位/清除点、`会话镜像栈` 物理清空时机、系统返回五段裁决伪码均以 `docs/adr/ADR-0138-app-lynx-vue-router.md`（含 2026-09-03 code-review 修订注记）与 `docs/research/vue-router-migration-feasibility.md` 为准。
- 探针代码（`prototype/lynx-vue-router` 分支 `src/prototype/`、`routeProbe.ts`）是 throwaway：其命名（`probeNavigate`/`probeBack`/`probeHasHistory`/`_epoch`/`setAuthed`）**禁止**进入生产代码与文档；生产对应命名为 `hasBackEntry()`、`canBack`、`cleared`、`会话镜像栈 _sessionStack`、`bootstrap 放行`。
- 「自跟踪栈」与「纯官方 API 形态」的历史判定二选一，**episode 定稿为混合形态**（code-review P1-2）：「会话镜像栈」为决策主源（物理清空承载清栈）+ `hasBackEntryIn` 队列探测为看门狗——纯官方 API 在「登出→重登录」后会误判旧会话残留条目，不作为唯一判据。
- `/update`、`/error` 的不可回退语义 = `meta.backBehavior: 'exit'`（裁决链③直取），**不依赖**物理清栈——「清栈语义」统一由「会话镜像栈物理清空 + cleared + canBack」表达。
