# ADR-0137: 滚动态 UI 真机测试方法——滚动中采样（并发截图）替代「滚动后截图」

- 状态：accepted
- 日期：2026-09-02
- 关联：ADR-0135（滚动指示条——本方法的首个应用）、ADR-0136（benchNav 钩子）、`packages/app-lynx/CONTEXT.md`（「滚动中采样」词条）
- 来源：用户反馈（「滚动指示条实际滚动时能看见，agent 为什么总说看不见」）→ 测试方法复盘

## 背景

滚动指示条（ADR-0135）验证期间，agent 反复报告「截图看不见指示条」，而用户真机目测「滚动时能看见」。排查多轮（数据链对、`onScroll` 在跑、geo 正确）后定位根因——

**不是代码问题，是验证姿势错了**：指示条是**瞬态 UI**——只在滚动进行中出现（`visible=true`），滚动停止 500ms 后淡出（`HIDE_DELAY_MS=500`）。agent 的验证姿势是「滚动（swipe）→ 结束后截图」——**截图时刻指示条已淡出**，必然错过。而人眼是连续观察，滚动全时段可见。

之前的成功命中（如「y 606-784」）靠的是碰巧卡在滚动中或放宽阈值，非方法性保证——单靠运气不可复现。

## 决策

1. **滚动态 UI 的验证 = 「滚动中采样」**：`adb shell input swipe <x> <y1> <x> <y2> 1000`（≥1000ms 长滚动）与 `adb exec-out screencap` **并发**（shell `&` 后台并行，或循环连拍）——滚动期间 `visible=true` 持续 >1s，采样必命中。滚动结束后截图**禁止**作为验证姿势。
2. **采样参数**：
   - swipe 时长 ≥1000ms（保证滚动窗口内可见时长 > 截图间隔 ~90ms）
   - 连续拍 8-10 帧（间隔 ~90ms）覆盖滚动全程
   - 判断标准：命中 = 右缘竖条（x 1000-1080）出现暗像素带（y 随 scrollTop 增长——位置跟随 = 功能正确）
3. **像素阈值**：指示条 2.4px 宽 + 35% alpha 半透明（rgba(73,69,79,0.35)）——扫描用 `r<200 && g<200 && b<210`（深背景上显著偏暗）；**r<140 过严会漏检**（曾漏）——半透明条像素值在 r~160-200 区间。
4. **复现三重保证**：单次命中不够（可能是运气）——复测≥2 轮，且指示条**位置逐轮下移**（随累计滚动量）为功能正确证据。

## 被考虑的方案

- **视频录制抽帧（screenrecord）**：理论最稳（全程可复检），但环境无 ffmpeg、avconvert 仅转码不逐帧解码——工具链不可用。若未来有 ffmpeg，可作第一选择。
- **logcat 数据链验证**（`[ind-dbg]` payload 在跑）：能证明 `onScroll` 执行、`geo` 非 null ——但**不能证明可见性**（渲染层与数据链可能脱节）——只作辅助，不作验收。
- **单帧「滚动后截图」**（旧姿势）：已证失败——淡出窗口错过。否决作为验证方法（仅作样本）。

## 后果

- 正面：滚动态 UI 验证从「碰运气」变为「方法性必命中」——8-10 帧内必有数帧命中（实测 2/10、2/8、复测一致），位置随滚动量移动可作功能正确签名。
- 代价（可接受）：连拍产生 ~8-10 张临时截图（/tmp 归档，用完即弃）；sampling 与 swipe 需 shell 时序控制（`&` 并行），失败会静默——需检查命中帧数非 0。
- 后续复用：所有「滚动进行中出现、停止后消失」的瞬态 UI（下拉刷新指示、滚动进度提示）均照此验证。
- 上游无关（纯测试方法，非产品行为），无产品影响。
