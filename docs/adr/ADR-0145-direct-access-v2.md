# ADR-0145: 直连 v2——多候选竞速、分层超时与握手快速重试

- 状态：accepted（用户拍板「重新改方案，极度稳定直连」方向）
- 日期：2026-09-07
- 关联：修订 [ADR-0144](./ADR-0144-direct-access-transport.md) D1/D2/D3 的传输策略部分；依赖 ADR-0143（缓存键不变量）；真机证据链见 issue #393 与分支 `prototype/diagnose-direct-oauth-rejection

## 背景

ADR-0144 直连（钉定 IP + 剥 SNI + Host 路由）原理经探针与真机实证有效（OAuth 200、图片 sha256 一致），但 v1 真机长期观测暴露三个结构性脆弱点：

1. **单候选单试**：每次 DNS lookup 只返回一个钉定 IP，OkHttp 无第二路线可试。GFW 的 RST 是**按连接概率性的（同分钟一失败一成功实测），单试把 p=50% 的连接成功率直接暴露给用户。
2. **熔断把抖动放大成死**：连续 3 次握手失败即 OPEN 60 秒。概率性 RST 下 3 连败并不罕见（p=0.3 时约 34%），OPEN 期间回退系统路线（被墙环境同样死），用户感知为整段不可用。
3. **无分层超时**：直连与系统路线共用同一超时预算（15s），失败推进慢，故障窗口内每个请求都要耗满超时。

对照：PixEz 同原理直连（官方 FAQ「瞒天过海躲过 SNI 嗅探）能做到"多数用户多数时间稳定"，工程差异在其多策略切换（用户可开关 SNI bypass）、传输层智能重试、以及持续跟版（证书轮换、IP 失效均以发版+热更消化）。

## 决策

### D1：单钉定地址 → 有序候选地址序列

`PinnedDns.lookup 对同一 host 返回**候选 IP 列表**（而非单地址）：

- 首位 = 会话内最近一次成功候选（last-good，会话级记忆）；
- 其后 = 同通道其余表条目对应 IP（按表顺序）；
- 末尾 = 主条目重复位 ×N（N = 握手重试预算，默认 1 次额外重试）——OkHttp `RouteSelector 对地址列表逐 route 重试，**同 IP 重复出现即同请求内原生握手重试，概率性 RST 被单请求吸收。

OkHttp 原生语义：连接失败自动尝试下一 route——**策略竞速零新增状态机，全部落在既有 DNS 接缝。

### D2：分层超时

`connectTimeout 收紧为 5s（候选推进快速失败；系统路线对可达目标 5s 内足以完成 TCP+TLS 握手），`read/`callTimeout 维持现值（body 阶段不受影响）。总预算由 OkHttp callTimeout 兜底，行为不劣于现状。

### D3：记账语义修正（多候选下的恰好一次）

候选序列中前序 route 失败、后序成功的调用**最终口径 = 成功：

- 失败归因维持 CAS 恰好一次（防重复计数）；
- **响应头到达时无条件 `recordSuccess（幂等清零）——覆盖"前序 route 失败已记账、最终调用成功"的保守误计，避免熔断被误开。
- warnSink 告警口径同步：route 失败告警保留（可观测），但注明"候选序列部分失败、最终成功"的调用不产生误导性最终失败语义。

### D4：熔断语义重估

失败计数单位从「单连接尝试」改为「完整候选序列（一次 lookup 的全部候选耗尽且全失败 = 记 1 次）。OPEN 60s 与半开探针语义不变，但探针 = 完整序列重放——单序列成功率经 D1/D3 提升后，熔断仅对「确认死透」的通路生效。

### D5：IP 池扩展机制

- 内置表维持「只内置实测条目」纪律（不发明未验证 IP）；
- 远端表 schema 增加可选 `alternates 字段（同通道备用 IP 列表，向后兼容：旧端忽略未知字段），维护者探测到新边缘即下发；
- 合并器对同 host 多候选按序产出（手动 > 远端 alternates > 远端主值 > 内置）。

### D6：证书轮换

标准证书链 + 泛域名校验保留（不做降级校验）。Pixiv 轮换证书（PixEz #1264 同款事故）= 发版/远端表跟进的运维面，与 ADR-0144 判断一致，不在传输层绕过。

### D7：多维测试矩阵（能模拟真机失败形态）

| 真机失败形态 | 模拟手段 | 断言 |
| --- | --- | --- |
| 概率性 RST（WiFi 实测：同分钟一失败一成功) | MockWebServer 前置 socket 代理按 seeded 概率在握手后即断连 | 候选序列内重试成功；last-good 被记忆；熔断不误开 |
| 静默超时（蜂窝实测：15s 无响应) | socket accept 后不响应不关闭 | connectTimeout 5s 快速推进候选；总时延有界（≤ 预算) |
| 边缘错配 421 | 既有 421 用例扩展 | 策略推进 + 失败记账 + 告警一行 |
| 证书轮换 | okhttp-tls 换发不同信任链证书 | 标准校验失败可见、不崩溃、不降级校验 |
| 系统路线零扰动 | 既有用例 | 系统路线失败零告警、body 阶段零告警（不变量) |

## 后果

- 真机抖动（概率 RST/慢超时)被候选序列与快速重试吸收，故障窗口内可用性显著提升；熔断仅在整条策略序列确认死亡后介入，且探针以完整序列为单位——恢复更快。
- 猫鼠本质不变：边缘 IP 仍可能整段失效，远端表仍是最终权威运维面；本 ADR 降低的是「抖动窗口的用户感知」与「诊断成本」（候选序列全程 warnSink 可观测)。
- 用户自建反代（Cloudflare Worker 等)作为独立演进路线保留，不在本 ADR 范围。
