# ADR-0130: 设置页按功能域重组 8 卡分类

- 状态：accepted
- 日期：2026-09-01
- 关联：ADR-0074（设置卡片化分组）、ADR-0129（UI 形态用户拍板模式）、`packages/app/src/components/settings/SettingsSections.tsx`
- 来源：用户提出「设置页太凌乱，重新归类整理」→ 诊断 → AskUserQuestion 三选项（按功能域拆 8 卡 / 保守修乱 / 合并大卡），用户拍板**按功能域拆 8 卡**；并确认「账户卡保持现状，不新增用户名/头像头部」。

## 背景

设置页此前按「业务模块加成时堆叠」组织为 7 卡（显示与交互 / 内容与过滤 / 图片与网络 / 翻译设置 / 客户端 / 账户与数据 / 退出登录）。经逐卡盘点，存在两个结构化问题：

1. **「账户与数据」卡是杂物间**：内含「启动时检查更新」「自动下载 Web 更新包」「检查更新」「关于」4 个与账户无关的条目（更新/关于属于独立功能域），还有「清除图片缓存」这一图片域条目；
2. **同域条目拆散**：「图片缓存」入口与「图床代理」在图片卡，而「清除图片缓存」在账户卡——用户查找「图片缓存」需要在两处之间跳转。

核心指标：设置项**零增减**、行为**零变更**，仅重新分组归类；E2E 锚点（「检查更新」文本、`[aria-label="关于"]`）保持命中。

## 决策

1. **8 卡顺序**（自上而下）：显示与交互 → 内容与过滤 → 图片 → 翻译 → 客户端 → 更新与关于 → 账户 → 退出登录（独立 danger 卡，不变）。
2. **拆分**：新建 `SettingsUpdate.tsx` 承载「更新与关于」卡（启动时检查更新 / 自动下载 Web 更新包 / 检查更新 / 关于入口），从 `SettingsAccount.tsx` 逐字移出（含 `handleCheckUpdate`、全部状态 hook、aria-label）。
3. **归位**：「清除图片缓存」行移入图片卡（`SettingsImage.tsx`，紧邻「图片缓存」入口），关闭图片卡解除对 toast 的依赖——新增 `SettingsImageProps.onActionToast` prop；账户卡随之删除 `onActionToast` prop，标题「账户与数据」→「账户」，只保留「清除所有本地数据」与「删除 Pixiv 账号」。
4. **卡片标题**：卡片头沿用既有样式（uppercase 小标题），无视觉令牌变更；无分节线引入，延续「少线条原则」。
5. **注释与术语**：分区组件头注释记录分组来源与拆分历史；无新增领域术语（无需更新 glossary），「更新与关于」仅为分组名。

## 被考虑的方案

- **保守修乱（保持 7 卡 + 只拆更新/归位图片缓存）**：改动最小，但「客户端」卡（仅 full 包渲染）与「更新与关于」同为低密度卡，视觉上 7 卡中有两张几乎空白的卡；用户未选。
- **合并大卡（5 卡）**：滚动更短，但「通用」卡混合引擎切换/更新/关于三类不相关条目，与本次「按用户查找心智归类」的目标相反；用户未选。
- **账户卡新增用户名/头像头部**：功能新增（超出「归类整理」范围），用户明确「保持现状不加」。

## 后果

**正面**：
- 同域条目邻接（图片缓存入口 + 清除操作），更新/关于/账户各归其域；
- 设置项零增减，无存储结构/设置键变动，无迁移需求；
- `SettingsUpdate.tsx` 为纯展示组件，后续新增更新项有落点。

**风险/验证项**：
- E2E 锚点：`update-flow.test.ts` 兜底文本「账户与数据」已随分类更名为「更新与关于」（主条件「检查更新」恒命中）；`sub-flows.test.ts`「关于」行为 `SettingsAccount` 处注释已同步为 `SettingsUpdate`；
- 新组件与接线由 `SettingsSections.test.tsx`（3 用例：8 卡顺序 / props 接线 / 账户卡不再接 toast）+ 全套单测 1103 通过 + 浏览器登录态逐屏实测（8 卡逐屏核对）验证。
