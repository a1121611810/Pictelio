# ADR-0167: lynx 小说导航三段式（列表 → 介绍页 → 正文）

- 状态：accepted
- 日期：2026-09-17
- 关联：wayfinder 地图 #575（决策票 #576-#584 全关）、spec #585、票 #586-#590、commits `21ed312e` / `bfd694c2` / `d9a3a317` / `ab3724e2`（feat/novel-intro-575）、`packages/app-lynx/CONTEXT.md`（词条：小说介绍页 / 三段式导航 / 开始阅读 / 小说导航）、ADR-0118（轮播 scrim 视觉先例）、ADR-0131（内容区尺寸契约——CTA 贴底几何）、ADR-0133（全局搜索弹层——标签点击接线）、ADR-0155（AI 过滤语义）、ADR-0163（init-only props 宿主矩阵——BookmarkButton :key 契约）、throwaway 分支 `prototype/novel-intro-575`（落选视觉案 A/B/C 留存）

## 背景

lynx 端小说与插画的导航不对称：插画是「列表 → 详情」两段式，小说的 6 个入口（推荐轮播 / 小说列表 / 收藏 / 用户主页 / 追更最新章节 / 搜索弹层）全部直达正文页；正文页头部只有 标题/作者/字数·收藏/系列行/评论·导出，无封面、无标签、无简介——用户在进入正文前没有判断「读不读」的信息面。而详情端点（`/v2/novel/detail`）本就返回 `caption`/`tags`/`total_view`/`series` 等全部字段，只是从未渲染（API 零新增的空间）。

地图 #575 用 9 张决策票把模糊需求收敛为可直接实施的决策集：边界（#576 UI 改道 vs 路由强制）、信息架构（#577）、正文页头部（#578）、开始阅读语义（#579）、受限呈现（#580）、入口取证（#581，搜索弹层是唯一无守卫入口）、追更询问时机（#582）、视觉方向（#583，四案原型对比选 D 轮播同族）、简介承载（#584，scrim 内展开）。

## 决策

1. **三段式是 UI 导航约束，不是路由约束**：6 个入口的小说点击一律先进介绍页 `/novel/:id/intro`；`/novel/:id` 保留路由可达性且**不做路由级重定向**（benchNav 测试通道、未来合法深链依赖直达性）。webview 端不在范围（lynx-only）。
2. **介绍页视觉 = D 轮播同族**（#583）：全屏封面 aspectFill 铺满 + 底部渐变 scrim（复用 `--md-scrim-overlay` token 与轮播配方）承载全部元信息，页内不滚动，「开始阅读」与收藏嵌 scrim 底部。落选案 A/B/C 随 throwaway 分支留存。
3. **信息架构**（#577）：封面（CoverImage 三态）/ AI 徽章 / 系列行（系列名 + 已追更 chip）/ 标题 / 作者行（→用户主页）/ 标签胶囊行（复用 AdaptiveTagRow「标签自适应折叠」，chip → 全局搜索弹层）/ 简介 2 行截断（点开弹 modalStack 底部面板读全文，#584）/ 统计行 / 评论入口 + 底部固定「开始阅读」+ 收藏。可选字段缺省显式降级（对应段隐藏 /「暂无简介」），禁静默假数据。
4. **受限/AI 语义与正文页同源**（#580/#581）：谓词直接复用 `settings.isRestricted` / `isAiRestricted`（R-18 优先、AI mask 次之，与正文页 v-if/v-else-if 顺序一致）；封面/标题/作者可见，简介位遮罩（RestrictOverlay/AiOverlay 同款），CTA 与简介展开入口置灰——置灰 = 处理器守卫（`if (masked.value) return`），不是仅视觉。
5. **「开始阅读」固定从头开始**（#579）：无续读/进度恢复（需数据模型 + 双端语义对齐，Out of scope，另立地图）。
6. **正文页头部精简**（#578）：头部 = 标题 + 作者小字 + 评论入口 + 导出入口；字数/收藏/系列行（含已追更 chip）移除，由介绍页承载。**系列判定数据仍经详情端点加载**——追更询问的 `getSeries` 依赖它，数据与展示解耦。
7. **追更询问时机不变**（#582）：仍在正文页返回键触发（返回守卫先于路由回退）；介绍页**不注册返回守卫**、不渲染弹窗。已追更 chip 复用 `createWatchlistPrompt` 深模块取 `watchAdded`（仅消费预取状态，不接守卫链）。
8. **lynx 补齐小说收藏能力**：介绍页是 lynx 首个小说收藏入口。API 端点逐字对齐 webview 端（`POST /v2/novel/bookmark/add`、`POST /v1/novel/bookmark/delete`，仓库内 oracle）；`useBookmarkMutation` 以可选 `targetKind` 分派端点（缺省 `illust` 零 blast radius），小说端点无 tags 载荷——`saveWith` 若被小说宿主调用显式 warn 后按 restrict 保存（禁静默丢载荷）。
9. **防线补齐**：改道前 6 入口仅搜索弹层有源级钉，漏改不会被测试暴露；新 `novelIntroEntryGuards.test.ts` 逐入口钉 intro 导航串 + 负向断言禁直达正文回退 + 路由共存与禁重定向。介绍页自身有模板源级守卫（三态/scrim/遮罩顺序/置灰绑定）+ 端点契约成功/失败测试（IO 边界硬约束）。

## 后果

- **正向**：小说与插画导航对称；进入正文前有完整决策信息面；入口行为收敛且逐入口有机器防线； lynx 首次具备小说收藏能力。
- **成本/风险**：正文页信息变少，依赖介绍页承接（两页数据请求各一次 `loadNovelDetail`，无共享缓存——同一会话内介绍页→正文会请求两次；量级可接受，若成为热点再加页面级缓存）；小说端点无 tags 载荷是 Pixiv 侧差异，收藏面板（带标签）对小说不可用是**有意不支持**而非缺陷。
- **双端不对称是现状**：webview 端维持两段式直达，将来对齐另立地图（Out of scope，#576 拍板）。
