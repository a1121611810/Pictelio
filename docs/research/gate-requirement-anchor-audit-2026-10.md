# 约定层门禁 · 需求锚点审计（2026-10-18）

> 起因：维护者判断测试「又全面又强硬但过于复杂、又笨重」，启动测试门禁重评
> （背景与决策过程见 `docs/testing/` 与长期记忆 `decisions/test-strategy-reassessment-2026-10.md`）。
> 本文是重评过程中的**第一份实证盘点**，产出为**只读对照表**，未修改任何测试。

## 范围与方法

**盘点对象**：`packages/app-lynx/{src,tests}/**/*.test.ts` 中「文件内出现过文档路径」的 158 个文件，
合计 47,083 行（占 app-lynx 全部测试代码 72,126 行的 65%）。

⚠️ **该 65% 是高估**，见下方「口径修正」。真实运行时读取文档/扫描全仓的只有 80 个文件 / 27,871 行。

**方法**：16 个只读审计 agent 并行，逐个 Read 测试文件搞清楚「它到底断言什么」，
再到仓内文档（`AGENTS.md`、`docs/adr/**`、`docs/specs/**`、`docs/testing/conventions.md`、
`workflows/review-fix-loop.md`、`packages/app-lynx/CONTEXT.md`）找该约束的**书面来源**。

## 判据（三档）

| 档 | 定义 |
| --- | --- |
| **A · 锚到用户可见行为** | 断言用户能看见/感知的东西，来源指向 `docs/specs/**` 或产品 spec |
| **B · 锚到明确书面约定** | 断言本仓自定的硬规则（AGENTS.md 禁令、ADR 决策、glossary 术语、测试硬约束 6 条、门禁冻结线） |
| **C · 指不出锚点** | 断言「代码长这样」，但仓内无任何文档要求它长这样 |

**判定纪律**：锚点必须是可 grep 的坐标；找不到书面来源 ⇒ 判 C 档；代码注释声称的规则不算锚点；
测试文件自己的头注**不算锚点**（自证不算）；文件含多档断言时取最高档。

## 结论

**这层门禁几乎全部有据可依，裁撤方向不成立。**

| 档 | 文件数 | 行数 | 占本层行数 |
| --- | --- | --- | --- |
| A | 108 | 29,381 | 62.4% |
| B | 48 | 17,148 | 36.4% |
| **C** | **2** | **554** | **1.2%** |

- **仅 2 个文件（1.2% 行数）完全找不到书面来源**；其中 `mojibakeGuard.test.ts` 已于 2026-10-18
  补源（`docs/testing/conventions.md` 强制约束第 7 条），**现存 C 档只剩 1 个**、待产品裁定。
- 相当一部分 spec **逐字点名了测试文件名及其断言内容**，例如
  `docs/specs/qa-defense-lines.md:82` 直接规定 `BookmarkButton.host-matrix.test.ts` 的断言形态，
  `docs/specs/qa-defense-lines.md:98` 点名 `PlatformCheck.template.test.ts`。
- 多数文件头注标注的 ADR 坐标经逐条 grep 复核**实锤存在**，未发现编造。

结论含义：这 158 个文件不是「拍脑袋的模式合规」，而是**「文档 → 机器防线」的映射实现**。
削减它们等于削减真实的书面约束防线，与 `workflows/review-fix-loop.md` §门禁冻结线 #1
「门禁的价值是防回归，不是显得严谨」相悖。

文件级 A/B/C 区分度低：绝大多数文件整体有强锚点，但**内部混着无书面来源的子断言**，
重构即误红、需求漂移时绿灯。以下为 16 块中 4 块的 agent 报告（**未全量覆盖**）：

## 审计局限（须知）

1. **子断言缺口只覆盖 4/16 块**，全量缺口规模未知，可能显著更大。
2. **「可证伪性」列提取不可靠**：部分表格行含转义竖线导致列错位，该列统计已作废，未列入本文。
3. **A/B 边界存在口径分歧**：部分 agent 按「来源是否在 `docs/specs/**`」判 A，
   另一些按「断言对象是否用户可见」判 A，两者在 glossary 术语与源级守卫上会打滑。
   若改用「有 spec 锚即 A」口径，`PlatformCheck` / `advancedImageCacheTemplate` 等会从 B 升 A，
   B 档规模进一步缩小。
4. agent 自登记的失效面（如「不验排他」「引用块是确凿盲区」）是**测试自述**，本次未独立验证。

## 对策结论

审计推翻了「按覆盖面裁撤」的思路。可行方向转为**降低阅读摩擦**：

1. **索引化**：把 158 个门禁按**被测对象**（而非文件名）重组为「改什么 → 看哪几个门禁」的对照，
   让人不必逐文件通读。
2. **保持单次全量跑**：27 秒的运行成本无需引入 test impact analysis（Meta 实测构建依赖式选测会过度触发，
   一次改动平均选中 25% 的测试），维护成本高于收益。
3. **补源优先于删**：C 档 2 个 + 上面列出的子断言缺口，按「补一条书面来源」处理。
4. **子断言缺口需全量普查**：这是下一轮最有价值的工作——按「文件内未锚定断言占比」再切一刀，
   比按文件档次更能定位真正的重构摩擦源。
