# 双端滚动跟手性 T0 基线 rev2（OPPO R11s 真机 · R18/R18G 开启，2026-09-02）

> 票：#306（父地图 #304）——**rev2 修订**：初版（scroll-baseline-t0-oppo.md）在 R18/R18G 开关**关闭**状态下采集，列表渲染的是「受限占位卡」（半透明灰块 + 徽章 + 无图文案，负载极轻）；且关注场景取自 `/following` 独立单列页（形态与产品主路径不同）。用户指出后按正确口径重测：**开关开启（完整卡：图/标题/标签/收藏）** + 关注场景 = **插画/小说 tab 内部「推荐|关注」子 tab**（双列瀑布流/单列卡）。
> 方法：同初版（input swipe + gfxinfo 聚合摘要，60Hz 预算 16.7ms；legacy jank 判定；备注见初版 §4）。
> 原始数据：`docs/research/scroll-baseline-data/r18on/oppo-r18on-*.jsonl`（g0/g1… 手势级记录）。
> **结论速览：完整卡负载下差异格局与初版一致但幅度更大——小说正文 lynx 14.2% vs webview 3.4%（4.2×）；插画推荐 feed lynx 16.8% vs 8.8%（1.9×）；关注插画反向（webview 31.2% vs lynx 19.0%）——完整卡（尤其关注 feed 的 R18 全图卡）把 webview 的图片解码/长列成本也显形了。P50 帧时长仍双端同量级（10-15ms，预算内）；差距主体在长尾脉冲（H1/H3 签名）与图片密集负载段。**

## 1. 环境（同初版）

OPPO R11s（Android 9 / 1080×2160 / 60Hz / WebView 138）；debug flavor 双包（`install -r` 共享登录与设置）；真实账号。

**本轮关键状态控制**：
- `show_r18_<uid> = true`、`show_r18g_<uid> = true`（账号级共享 prefs，webview 设置页 + `run-as` 核对双重确认；uid=11717768）。
- 内容验证：插画 tab→关注子 tab（截图确认 R18 完整卡：Hikari bunnysuit 等全图带元信息渲染）；小说 tab→关注子 tab（循环2 等 #R-18/#R-18G 完整小说卡）；推荐小说列表 R18 完整卡（#R-18 徽章/字数/标签）。
- 关注 feed 列表长度有限（关注 67 项）→ 关注场景采样 per=5（15 手势），防滚穿尾部零帧污染。

## 2. 结果（R18 ON 完整卡；同设备同日）

| 场景 | lynx jank / P50 | webview jank / P50 | 注释 |
| --- | --- | --- | --- |
| 插画 feed（推荐，推荐页） | **16.8%** / 11ms | 8.8% / 12ms | lynx 1.9× |
| 关注插画（插画 tab→关注） | 19.0% / 12ms | **31.2%** / 15ms | webview 1.6×（图片密集段） |
| 关注小说（小说 tab→关注） | 10.6% / 10ms | 8.5% / 12ms | 相近 |
| 小说正文 | **14.2%** / 10ms | 3.4% / 11ms | lynx 4.2×（全文渲染路径） |
| 小说 feed（推荐 tab） | 12.0% / 11ms | —（对照=搜索页 26.7%/14ms） | webview 侧内容不同构（搜索页），13-27% 含搜索页加载噪声 |

参考（R18 OFF 初版，受限占位卡）：lynx 插画 19.3%、小说正文 11.6%、webview 插画 9.7%/正文 3.3%——**开关本身主要改变内容形态而非双端相对格局**（off 时 lynx 也几乎等同完整卡负载：推荐插画 off 时多为普通卡）。

## 3. 发现

1. **小说正文差距最稳定且最大（lynx 4.2× webview）**：正文场景完整文本渲染，lynx `<scroll-view>` 全文一次性 + UI 线程滚动（webview 为合成器滚动 + 虚拟化）。rev1（r18 off）同场景 11.6% vs 3.3%——两组独立测量指向同一结论：**正文是双端差距最扎实的场景**，与用户「小说详情滑动明显更差」的体感完全一致。
2. **插画推荐 feed lynx 稳定劣于 webview（16.8% vs 8.8%，rev1 为 19.3% vs 8.6%）**：两轮一致。
3. **关注插画反向（lynx 19% 反而优于 webview 31%）**：完整卡+大量 R18 全图卡的关注 feed 里，webview 的图片解码/虚拟列表重建成本更高。**注意：本数值与「lynx 更差」的用户体感不一致——关注插画的比较仅本场景，且为 15/30 手势样本，需 T1/图像数据进一步确认（疑似 webview 关注列虚拟化重建 + 大图解码，或图片尺寸差异）。**
4. **P50 双端同量级、差距在长尾**：P50 10-15ms 均在 16.7ms 预算内；jank 差异来自每手势的高载帧（图片批量解码/翻页脉冲），同 rev1。
5. 「慢半拍」时延段仍属 T1 测量域。

## 4. Caveats（在初版基础上新增）

- 关注场景 per=5、15 手势/场景（样本量小于推荐 30）；关注 feed 内容当日静态。
- webview 小说 feed 对照组为搜索页（不同构）——该行数据不参与双端对比结论。
- 一次全测过程中出现设备网络断连（Pixiv TLS 超时 → lynx 掉线）后恢复重测；中断期间数据已弃用（novel-single r18-on 首轮 0 帧污染轮丢弃，第二轮为重测有效数据）。
- debug 构建（无 R8）；所有上述为设备上相对比较，绝对值随当日内容/网络波动。
