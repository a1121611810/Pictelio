## 1. 结论：布尔语法由服务端解析，客户端只需透传

| 语法 | 输入 | 判别依据（结果集之间的关系） | 判定 |
|---|---|---|---|
| AND（空格） | `A B` | 结果集 **≠** `A OR B`（相等就说明服务端只取了首词） | ✅ 按 AND 解析 |
| OR | `A OR B` | 含两个词各自的命中（并集），且 **≠** AND 结果集 | ✅ 真并集 |
| 负号排除 | `A -A` | **自排除返回 0 条**（`A -A == ∅`） | ✅ 负号被解析 |
| 括号嵌套 | `A (B OR C)` | 结果非空且 **≠** 单查 `A` | ✅ 被解析 |
| 全角归一 | `ｒｏｓｅｍａｒｙ` | 与 `rosemary` 结果集**逐条相等**（**所有档位**） | ✅ 归一 |
| 大小写归一 | `RoSeMaRy` | partial / 不传档 == `rosemary`；`exact_match_for_tags` 档 **0 条** | ⚠️ **只在 partial / 不传档成立** |

对照组：脚本还跑一条「非法字面串 → 0 条」，用于确认**"返回 0 条"本身是有意义的信号**，而不是端点恒定返空。

## 2. 判别方法（本轮方法论要点）

- **判别一律落在结果集之间的关系上**（并集 / 交集 / 空集 / 逐条相等），**不靠单次结果的有无**。
  「这次有没有结果」是最弱的一种证据：空结果既可能是语法没被解析，也可能是检索词本来就没内容。
- `AND ≠ OR` 是排除「服务端只取首词」这一伪解释的**最小充分条件**——若只取首词，两者会给出同一集合。
- `A -A == ∅` 是负号生效的最小充分证据；反过来，`A -C == A` **不能**证明负号无效：
  实测 `A`（`Rosmontis`）首屏 30 条里带 `#Rosmontis` 标签的**有 0 条**，根本没有可排除的对象。
- **只看「结果前几条里有没有另一个词」会误判 `OR`**：并集里两个词的命中可能都落在首屏之外，
  于是 `A OR B` 看起来与单查 `A` 无异。判据必须是**集合是否相等**，不是单页里有没有出现过。
- 检索词用真实存在的标签（`Rosmontis` / `rosemary` / `明日方舟`），不手写自洽数据。

## 3. 覆盖面

- **端点**：`/v1/search/illust` 与 `/v1/search/novel` **都成立**。
- **`search_target` 四档全部成立**：不传 / `partial_match_for_tags` / `exact_match_for_tags` / `title_and_caption`。
- ⇒ 布尔语法与搜索目标档位**正交**：档位不破坏 `OR` / 负号 / 括号 / 全角解析，本仓多词请求
  发 `exact_match_for_tags`（历史行为）也不会让这些语法失效。
- ⇒ 缺口是**可发现性**，不是能力：本仓透传用户原始 `word`，这些语法当天就能用。

## 5. 对本仓的含义

1. **只加提示文案，不写客户端查询解析器**：客户端拼串/解析与服务端语义重复且会随服务端演进而漂移。
   落地面 = 搜索弹层输入框下方一行提示（spec §7.2）。
2. **文案不得承诺「大小写无关」**：大小写归一只在 partial / 不传档成立，`exact_match_for_tags` 档实测大小写敏感。
3. **档位不对称不在本文证明**：见 §4 第 2 行——本文只证明语法与档位正交，映射不对称是另一条证据链。
