# Spec：行内动作离开行尾——遮挡带修复

- **承接**：[ADR-0221](../../adr/ADR-0221-row-action-leaves-trailing-band.md) · [术语表（命中测试与覆盖层）](../../adr/glossary-app-lynx-hit-testing.md) · [术语表（底部让位族）](../../adr/glossary-bottom-occlusion-allowance.md)
- **兑现**：票 #932（`/continue` 行尾「移除」被悬浮 FAB 遮挡）
- **决策来源**：Grill 两轮 + 真机三方案原型（方案 A 水平让位 / 方案 B 行首动作 / 方案 C FAB 滚动收起）逐一点按验证，2026-10-07 按推荐锁定方案 B
- **状态**：已实施（票 #952–#956 落地；真机取证仅覆盖 `/continue` 与 `/watchlist`，见 ADR-0221 §7）

---

## Problem Statement

我在「继续读」列表里想删掉一条记录，手指按在行尾的「移除」按钮上——**弹出来的是搜索框，不是删除**。
那一瞬间我以为 App 坏了。

问题不止「按钮看不见」：GlobalFab 是右下角一块**固定几何**，它的水平投影带
（真机实测 80.8vw..95.65vw）**横跨了整行的尾部**。而列表行的内容右边缘本身就在 94.665vw
⇒ 行尾按钮 **97% 的宽度**被它压住。点被压的部分，**确定性地**（不是"困难"，是 100%）
被 FAB 接走，触发搜索。

同一形态在四个页面出现，其中三个是**不可逆的破坏性操作**：

| 页面 | 动作 | 后果 |
|---|---|---|
| 继续读 `/continue` | 移除 | 硬删阅读/浏览记录，无二次确认 |
| 追更列表 `/watchlist` | 取消追更 | 取消订阅 |
| 稍后看 `/later` | 移除 | 硬删本地快照，无二次确认 |
| 静音标签 `/mute-tags` | 取消静音 | 取消静音 |

**已有的底部让位机制（`FabAllowanceSpacer`）治不了它**——那是**竖直轴**的（让末项能滚到 FAB 上方），
本缺陷在**水平轴**、发生在**中间某行**。两者正交，末项让位齐全照样吞点击。

---

## Solution

**行的尾部是被固定几何恒定占用的区域，因此行内动作一律放到行首**，形态为 40dp 圆形图标按钮。

行首离右下角的悬浮控件很远，且这条性质**不依赖 FAB 的当前位置**——即使 FAB 移动、隐藏或收起，
行的尾部仍然不可交互。

四个页面的行内动作同时改为行首按钮，并统一补齐按压状态层。

---

## User Stories

### 破坏性动作的可点性（本票核心）

1. 作为**继续读列表的用户**，我想点行上的删除按钮真的删掉这条记录，**而不只是"想删"却弹出搜索**，这样我的浏览记录才是我控制的。
2. 作为**继续读列表的用户**，我想在任何滚动位置都能点到删除按钮，**而不必先滚到某个特定位置**，这样删除不依赖我当前滚到哪。
3. 作为**追更列表的用户**，我想点「取消追更」真的弹出取消确认框，**而不是弹出搜索**，这样我不会误以为取消了其实没取消。
4. 作为**稍后看列表的用户**，我想点删除真的删掉快照，**而不是弹出搜索**，这样我的暂存列表保持干净。
5. 作为**静音标签的用户**，我想点取消静音真的取消，**而不是弹出搜索**，这样我的静音设置符合预期。
6. 作为**任何用户**，我想行内按钮的**视觉位置和它能点到的位置一致**，这样我看到的地方就是我能点到的地方。

### 破坏性的视觉严重性

7. 作为**要删除数据的用户**，我想删除动作**看起来就是删除动作**（保留错误色语义），这样我在按下之前就知道这是不可逆操作。
8. 作为**误触风险高的用户**，我想破坏性按钮**按下时确实有反馈**，这样我知道系统收到了我的意图。
9. 作为**浏览列表的用户**，我想一眼分辨出「这一行有个可点的动作」，而不是把动作图标误读成装饰。

### 空间与布局不退化

10. 作为**读长标题的用户**，我想标题**不要因为多了一个按钮就换成两行**，这样我能一行看完作品名。
11. 作为**浏览列表的用户**，我想封面图的位置和大小**不要因为加了按钮就明显右移**，这样整页的视觉重心不变。
12. 作为**用平板/大屏的用户**，我想行内按钮**不会因为屏宽不同就跑到别的位置上去**，这样布局是稳定的。

### 一致性与可预期

13. 作为**在四个页面之间来回切换的用户**，我想行内动作的**位置和形态在四处完全一致**，这样我学会一次就能到处用。
14. 作为**维护这份代码的人**，我想「行内动作不能放在行尾」是一条**写在文档里、能被门禁检查的规则**，而不是一句口头约定。

### 无障碍与诚实

15. 作为**使用读屏软件的用户**，我想知道按钮的真实语义标签，**而不是只看到一个图标**，这样我知道按下去会发生什么。
16. 作为**维护这份代码的人**，我不想把「读屏可达性」当成这次修复的成果——**当前 SDK 上这一点本来就不成立**，我不想制造假的绿灯。

## Implementation Decisions

### 1. 遮挡带是几何恒等式，不是布局巧合

遮挡带由 FAB 自身的本体尺寸与右距导出，**与路由无关、与档位无关**（档位只改变 FAB 的**竖直**位置，
水平带两档完全相同）。

⇒ 决策的表述是「**行的尾部不可交互**」，而不是「离 FAB 太近了」。前者在 FAB 移动后依然成立。

### 2. 行首动作：形态、尺寸、形状

- 形态：**40dp（10.667vw）圆形图标按钮**，置于行首、缩略图之前
- 形状：`rounded-full`（⚠️ 必须写全 `rounded-full`；裸方向类 `rounded-*` 取 `medium` 档）
- 触控目标：40dp **沿用既有偏差**——四处现状本就是 40dp，已低于 Android 48dp 建议值、但过 WCAG 2.2 AA(24px)。
  本决策**不新增**该偏差，也不修它（修是独立票）
- 通过统一图标组件渲染，**不内联字形**

### 3. 字形：沿用已登记的 `close`，不引入 `delete`

「移除」的语义字形是 `delete`，它在官方 codepoints 里存在但**未登记**进本仓映射表。
登记它需改映射表**并重跑图标子集生成脚本**——该脚本需**联网下载源字体**并依赖 fonttools，
产物是**提交的二进制字体 + base64 CSS**。

为一个遮挡修复引入「联网 + 二进制产物重生成」**不成比例** ⇒ 沿用已登记的 `close`。

⚠️ **已登记的代价**：`close` 在映射表中的语义注记是「✕ 关闭」，此处承载「移除」是**语义借用**。
若日后要真正的 `delete` 字形，应另开图标登记票，**不与本票捆绑**。

### 4. 破坏性语义：图标必须染 `text-error`

静音标签页的移除文案**刻意**用错误色。统一为图标按钮后，这个严重性线索会丢失
⇒ 图标在破坏性站点染错误色，普通站点染主色。**不得**为了"四处长得一样"而抹平严重性差异。

### 5. 按压状态层：四处收敛为一致形态

现状是**不一致的**：四处中只有静音标签页有按压状态层，其余三处**完全没有**。
图标按钮去掉了文字之后，按下反馈从「看得见文字」退化为「只有图标」——而拇指恰好会挡住图标。

⇒ 四处一律补 `active:bg-layer-pressed-on-surface` + 统一的按压色类。

⚠️ 状态层 utility 必须是**顶层** `bg-layer-pressed-*`。嵌在 `state` 下会产出 `bg-state-layer-*`
——**不同名的死类名，静默无样式**。仓内已有门禁检查载体，但**只检查"已有 `active:` 的元素"**；
完全省略状态层会**静默通过**。

### 6. `@tap.stop` 的语义与位置无关

行根带 `@tap` 的页面必须用 `.stop` 防止误触变成导航；行根**不带** `@tap` 的页面不需要。
`.stop` 与按钮在行内的位置**无关** ⇒ 移到行首后行为逐字不变。
⚠️ 登记这一点，避免下个维护者以为 `.stop` 是装饰而删掉它。

### 7. 刻意不处理的站点（登记在案）

以下站点**同样落在遮挡带内**，本票**不处理**，理由是**非破坏性**——
失败形态是「点了没反应」，而不是「数据没了」：

- 关注/取关（用户行，3 个路由）
- 关注作者（插画详情页）
- 关注数/粉丝数 chip（用户主页）
- 折叠 ✕（排行榜卡片）
- 历史 ✕（搜索弹层内 —— 弹层打开时悬浮控件被强制隐藏，**不可能重叠**）

⚠️ 其中**关注/取关的重叠比例比本票四处更高**（它的按钮更宽）。这一条需要在独立票里评估，
不能因为「本票没改它」就认为它安全。

## Testing Decisions

### 什么样的测试算好

**主防线必须跑在 CI 里。** 模拟器 E2E 不进 CI（见仓内门禁边界与相关 ADR），
只靠它防回归等于没有防线。

期望值必须能溯源到「真机像素实测」或「ADR-0221 的决策」，**禁止自洽反推**
（不能「因为代码这么写所以断言这么写」）。

### 缝的划分

| # | 缝 | 覆盖 |
|---|---|---|
| 1（主） | **静态门禁**（CI 内 vitest，源级扫描） | 任何页面的行内动作不得落在遮挡带内 |
| 2（辅） | **几何数值直测** | 遮挡带边界的数值判据 |
| 3（辅） | **真机点按**（手动 / 发版前） | 吞点击的行为面 |

### 缝 1 的形态：宽门禁 + 债务登记（**不是**白名单）

门禁**全仓扫描**：任何行的行内动作落在遮挡带内都应转红。

本票不处理的站点**必须以「已知债务 + 票号」登记豁免**，而不是简单列个白名单。

⇒ **豁免项的票号一旦对应票关闭，豁免必须自动失效**，逼着维护者处理。
这是本仓反复吃过亏的地方：白名单会**静默腐烂**，变成下一个「静默破版脚枪」。

⚠️ 门禁的判据必须**从几何常量推导**，不得写字面量——否则改 FAB 尺寸时门禁不会跟随，
又是一个「看起来在防漂移的空门禁」。

### 缝 2：几何数值

遮挡带边界应由共享几何模块导出，测试断言该导出的值。
**先取一个未被遮挡的同类样本作基线**，再与遮挡物算重叠——
不要直接在受遮挡的元素上量（会量到遮挡物本身，这是本票取证时真实踩过的坑）。

### 缝 3：真机点按（手动）

⚠️ **不可作为验收的唯一依据**，但它是唯一能证伪「吞点击」的手段。

在原被遮挡的行尾位置点按，断言**动作被触发**（条目数变化 / 确认框出现），
且日志中**无搜索弹层的进入动画**。

**取证范围**：只覆盖**有数据**的页面。

⚠️ 稍后看与静音标签两页在验证环境中为空态（无数据、无法触发动作）⇒
标注「**代码同型、无设备数据，取证待补**」，**不得**用「看起来对」替代真机取证。

## Out of Scope

1. **非破坏性行尾动作**（关注/取关、关注作者、关注数 chip、折叠 ✕）——另开票，并按债务登记进豁免
2. **FAB 滚动收起**（原型方案 C）——静止态不解决本缺陷，且需推翻一条已记录的 ADR 判断
3. **水平让位**（原型方案 A）——每行永久让出近 1/5 屏宽，且标题被迫换行
4. **`delete` 字形登记**——需联网重生成字体子集，与本修复不成比例，另开图标登记票
5. **读屏可达性**——当前 SDK 的 a11y 树只暴露表单元素，行级标签本身就会吞掉子文本。
   本票**不宣称**修好了或保持了可达性，也不承诺修复它
6. **40dp 触控目标提到 48dp**——沿用既有偏差，修它是独立票
7. **底部遮挡让位机制本身**——`FabAllowanceSpacer` 依然全绿、依然必要，本票不动它

## Further Notes

**为什么原型必须落在真机，不能用 web 预览。**
本缺陷是**原生 LynxView 的命中测试**问题：悬浮控件不识别 `pointer-events`，
而 web 预览的层叠与穿透语义与原生不同 ⇒ **在 web 上「看起来对了」不代表真机点得中**。
原型因此构建在真机上，并逐方案做了点按验证。

**验收里为什么不能写「拿到结构坐标」。**
Lynx 的 a11y 树不导出悬浮控件节点 ⇒ 结构坐标这条路在本场景**走不通**。
验收必须落在**行为**（点按后动作是否发生）与**像素**（行首按钮右缘与遮挡带左缘是否留有间隙）上。
⚠️ 贴边不算通过——贴边时命中归属没有余量可言。

**取证时的两个已知陷阱**（本轮真实踩过，记录在此避免重蹈）：
① 用宽色判据找目标元素会**同时命中遮挡物**，量出来的是遮挡物本身；
② 截图取景落在**错误页面**时，会把「量错页面」误读成「布局漂移」。
两者的正确做法都是：**先自证落在目标页面**，**再取未被遮挡的干净基线**。
