# Spec：继续读 + 浏览历史（书架段 3 / 段 4）

- **承接**：[ADR-0219](../../../adr/ADR-0219-lynx-continue-reading.md) ·
  [术语表](../../../adr/glossary-lynx-continue-reading.md)
- **兑现**：[`app-lynx-navigation-dimension-restructure.md`](./app-lynx-navigation-dimension-restructure.md) §4 P1 承诺
  与 ADR-0218 §3.2「"继续读"是空态占位」负面项
- **决策来源**：Grill Round 1–3，共 14 项决策，2026-10-04 全部按推荐锁定
- **状态**：待实施

## Problem Statement

我读一本小说读到第 5 话退出了，第二天回来，在书架上找不到它——上次读到哪，得自己重新翻系列目录。
我上周刷到一张很喜欢的插画，想再看一遍，只能去推荐流里靠运气刷到，或者去 Pixiv 官方的浏览记录里找。

「书架」是导航重构后回答「我存的、没看完的」这个问题的顶层位置，但它现在只有收藏和稍后看两段是活的：
第三段写着「阅读记录即将上线」，是一句占位说明；浏览历史功能则随旧 WebView 客户端一起消失了（ADR-0203）。

结果是我在客户端里**没有一条线索回到「我上次在这儿」**。而我之所以记得这张图、这本书，
恰恰因为我在这个客户端里看过它。

## Solution

书架扩为四段，其中两段是本地的**回访入口**：

- **段 3「继续读」**（小说）——每条显示「上次读到 第N话」，点开**直接回到那一话**，无论介绍页开关处于什么状态。
- **段 4「最近浏览」**（插画）——点开回到那张图。

两段各带一个「查看全部」次级页（`/continue` / `/history`），可看到完整列表、
移除单条、清除已完成/已过期项。

关键在**位置语义**：我退出时读到第 21 话，回来就回第 21 话。**包括我在重读一本已读完的书时**——
此时位置会从「读完」往回拨，而不是跳到我「还没读到的最远一章」。

## User Stories

### 继续读（小说）

1. 作为读者，我想在书架上看到我正在读的小说，以便不靠记忆找回它。
2. 作为读者，我想看到「上次读到 第3话」这样的具体坐标，以便知道点进去会落在哪。
3. 作为读者，我想点一下就直接回到上次那一话，而不是从头开始。
4. 作为读者，我想即使介绍页开关是开着的，点「继续读」也能直接进正文——我的意图是读，不是重新考虑要不要读。
5. 作为读者，我想在重读一本已读完的书时，位置能往回拨到我实际在读的那一话。
6. 作为读者，我想在没有读过这本书时，介绍页仍显示「开始阅读」并从头开始。
7. 作为读者，我想在读过之后，介绍页的主按钮变成「继续阅读」并跳到我上次的位置。
8. 作为读者，我想读完一本单篇小说（无系列）后，它能从「继续读」里离开。
9. 作为读者，我想读完一个系列的最后一话后，它能从「继续读」里离开。
10. 作为读者，我想在「已读完」之后仍然能在「查看全部」里找到它并清除，而不是它被悄悄删掉。
11. 作为读者，我想在读完某本之后又点进去重看时，它不会变回「在读」——我确实读完了。
12. 作为读者，我想同时读好几本书，每本各自记住自己的位置，互不干扰。
13. 作为读者，我想同一系列读到不同话时，「继续读」跟着我最近读的那话走。
14. 作为读者，我想让「继续读」按最近打开时间排序，最常读的在最上面。
15. 作为读者，我想在「继续读」里看到超过 3 本小说，不被截断。
16. 作为作者，我想让 R-18 作品在「继续读」里以受限卡呈现，而不是消失或露出内容。
17. 作为读者，我想让受 R-18 开关关闭影响的作品仍留在列表里（我知道它在那儿），只是点开受限。
18. 作为读者，我想在作品被作者删除后仍看到它被明确标记为「已不可用」，而不是它凭空消失。
19. 作为读者，我想手动移除一条失效记录。
20. 作为读者，我想换账号后看到那个账号自己的继续读，而不是别人的。
21. 作为读者，我想半年前在读的书今天仍然在「继续读」里——我没读完的事不该被系统替我结案。
22. 作为读者，我想删除某条继续读记录后它不再出现在书架上。

### 浏览历史（插画）

23. 作为读者，我想看到我最近浏览过的插画，以便找回刷到过但没存的好图。
24. 作为读者，我想重复打开同一张图时它不新增一条，而是更新时间并累计次数。
25. 作为读者，我想让浏览历史按最近浏览时间倒序排列。
26. 作为读者，我想在 30 天后过期的记录被自动清掉，列表不被陈年旧图塞满。
27. 作为读者，我想在「查看全部」里手动移除某条浏览记录。
28. 作为读者，我想清除全部浏览记录。
29. 作为读者，我想打开小说**不会**在「最近浏览」里留下一条插画式的流水记录——两件事分开。
30. 作为读者，我想浏览记录里的 R-18 作品以受限卡呈现。
31. 作为读者，我想在作品被删除后看到明确的不可用标记。
32. 作为读者，我想换账号后看到那个账号自己的浏览历史。

### 聚合面与度量

33. 作为读者，我想「继续读」和「最近浏览」在同一屏，但能一眼分清哪个是我在读、哪个是我刷过。
34. 作为读者，我想每段都能进入完整列表。
35. 作为开发者，我想在「更新」页之外也能读到分段使用度，以便知道这两段是空的还是被用起来的。

## Implementation Decisions

### 范围与分工

- 两条轴**按作品类型不相交**：插画 → 浏览历史；小说 → 继续读。零去重判断。
- 书架段结构变为 4 段（我的收藏 / 稍后看 / 继续读 / 最近浏览），**不新增顶层目的地**
  ——ADR-0218 §3.3 已算清加第 5 个顶层项会导致放射 FAB 外环重叠约 10px。

### 继续读：位置语义（本 spec 最核心的一条）

- 采用**会话末位置**：记录本次退出时读到的那话，**允许往回拨**。
- **不采用** Kindle 的「最远水位」或 Mihon 的「最旧未读」。理由不是偏好：
  那两个语义是**跨端冲突**逼出来的最小仲裁规则，而本项目本地单机、不存在需要仲裁的冲突。
- 结果：**重读场景正确**——这是上述两个产品做不到的（社区 issue 有明确投诉佐证）。

### 粒度：话级，且是平台约束

- 阅读位置的粒度是**话**（Pixiv 的 novel），不是段、不是页、不是百分比。
- 原因：`main-thread-bindscroll` 在当前构建**未确认派发**（2026-09-02 真机复测），
  段内滚动位置拿不到可靠信号。**任何「第N段 / 37%」的形态在当前引擎下不可实现，不得承诺。**
- 可观测的信号只有两个：打开了哪本、是否触底。**不引入依赖不存在信号的门槛条件**
  （如「停留 N 秒」「滚动超过 X%」）。

### 记录时机与完成判定

- 进入正文页即记录（零门槛）。触底即视为读完。
- 完成的两种情形：**单本小说**（无系列）触底，或**系列的末话**触底。
  ⚠️ 单本必须覆盖——Pixiv 上单篇小说是最常见形态，漏判则该场景下功能永不生效。
- **完成后再次进入该作品：完成态保留，仅更新位置。** 与「进入即记录」不冲突——
  记录更新的是位置，完成态是独立状态位。

### 导航落点

- 续读条目点击**无视介绍页开关直达正文**。
- 实现方式是给既有导航单点缝隙加**显式意图参数**（续读时无论开关如何都进正文），
  **不是**在第七个入口旁新开一条导航捷径——后者会与既有源级守卫（`/intro` 串只许存在于
  `novelNavigation.ts`）冲突并使该守卫转红。
- 介绍页主 CTA 依有无位置**改变文案与落点**（无位置 = 「开始阅读」从头；有位置 = 「继续阅读」从该话起）。
  **单按钮形态不变**，不新增视觉层级。

### 展示形态

- 段 3 每行：封面 + 标题 + 作者 + 「上次读到 第N话」；**不显示相对时间**
  （相对时间本地化与缺档兜底成本高于收益）。
- 段 4 每行：封面 + 标题 + 作者；**无状态文案**——浏览历史没有「读到哪」可言。
  两段的区分主要靠段标题，不靠行内文案。
- **不做进度条**：Pixiv 不返回字数分布，百分比只能按话数推算；
  单本小说连分母都没有。推算进度条是「看起来精确的假数据」，按禁静默降级红线不引入。
- 单本小说（无系列）没有 `chapterTotal`，此时**不渲染「第N话」**，退化显示标题。

### 生命周期（两轴两套规则，这是它们唯一的共享决策）

| 项 | 浏览历史 | 继续读 |
|---|---|---|
| 过期 | **30 天**（沿 ADR-0094 先例） | **不设过期** |
| 容量上限 | 300 条 | 200 条 |
| 超限处置 | 丢最旧 + `console.warn` | 同 |
| 完成态 | 无 | `completedAt` 软删 |
| 备份域 | **不进** | **不进** |

- ⚠️ **过期策略是逐对象的，不是按「历史」这个词统一施加**。
  把浏览历史的 30 天套到继续读上 = 替用户删掉没读完的书。
- 备份域已查证只收 `show_r18_` / `show_r18g_` / `ai_filter_mode_` 三类账号级键；
  稍后看当前也不在内，两轴沿用同一条边界。两者的键各自带账号 uid 后缀（本机多账号隔离），
  但**不随 WebDAV 迁移**。

### 容错与受限

- **失效作品**：照常渲染该条目 + 显式标注不可用 + 提供手动移除，**不静默隐藏**。
  空列表会被读成「我没有记录」，而真相是「作品没了」——这是禁静默降级红线。
- **受限内容**：快照存 `xRestrict`（ADR-0094 旧模型已有该字段先例），
  列表**本地**判定走受限卡，**零网络**。不存则每行都要等网络才知道能否显示，
  且网络失败时「受限」与「加载失败」会被混为一谈。

### 存储

- 两个独立 store，各自账号级键（带 uid 后缀，照 `watch_later_${uid}` 范式），
  值 = JSON 字符串数组，走既有 `prefs()` seam（原生 / web-core idbKV 分流）。
- **不得让两条轴复用 `watchLater*` 任何符号**，也不得与 `watchlist` 词根交叉
  （源级守卫沿 `watchLaterStore.test.ts` 同款做法）。
- hydrate 需代闸（uid 连续切换时旧账号的在飞读取作废）、损坏值 warn + 降级空列表、
  解析器逐条跳过非法条目。

### 度量

- 段 3 / 段 4 各接一次现成的分段观测读点（键名分别为 `continueReading` / `browsingHistory`），
  **零新增设施、零网络出口**。书架当前对本地使用度量的引用数为 0，本批为段 3/4 补上。
- **刻意不加**「条目被点击次数」：需要给纯逻辑状态机加字段/方法/单测，
  而**没有分母的点击数说明不了任何事**。

## Testing Decisions

### 什么样的测试算好

只测**外部可观察行为**：给定输入的状态变更与持久化结果，不断言内部实现。
断言的期望值必须能溯源到 ADR-0219 的某条决策或 Pixiv 的真实响应形状，
**禁止自洽反推**（即：不能「因为代码这么写所以断言这么写」）。

### 缝的划分（1 条主缝 + 复用 2 条既有辅助缝，不新增 E2E）

| # | 缝 | 覆盖 |
|---|---|---|
| 1（主） | **续读 store + 浏览历史 store**，prefs 可注入 | 见下方用例清单 |
| 2（复用） | **纯决策函数直测**（与缝 1 同文件） | 介绍页 CTA 文案分支、导航落点决策 |
| 3（复用） | **源级守卫**（读源文件断言接线，与缝 1 同文件） | 详情页进入即写记录、段 3/4 渲染文案、无新增 `/intro` 裸串 |

三条收在**一个测试文件**里，形状照抄 `watchLaterStore.test.ts`——
它本身就把「可注入 prefs 假存储 + 纯函数直测 + 源级守卫」混在一个文件里，是既有先例。

**主缝必须覆盖的用例**（每条都对应一条已拍板决策）：

- 位置记录为**会话末**语义：读第 3 话 → 退出 → 位置是第 3 话（不是最远、不是最旧未读）
- 进入即记录，零门槛（无停留/滚动条件依赖）
- 完成的两种情形各自触发：单本触底、系列末话触底
- **系列中间话触底不触发完成**（反例，防止判定放宽）
- 完成后重新进入：完成态保留 + 位置更新（**不复活为在读**）
- 容量上限 200 / 300：丢最旧 + `console.warn`（禁静默降级）
- 损坏存储值：warn + 降级空列表；非法条目逐条跳过并 warn
- 账号级隔离：uid 切换后读到的是新账号的数据，**不串号**
- hydrate 代闸：uid 连续切换时旧账号在飞响应作废
- 过期判定：浏览历史 30 天边界（**含边界当天**、含跨条目的日期独立计算），
  过期条目被懒清除；继续读**同类数据不因时间被清**
- 受限本地判定：快照带 `xRestrict` 时列表渲染受限卡，**不发任何网络请求**
- 失效条目：显式标注不可用 + 可移除，**不从列表消失**

**IO 边界双路径**（测试硬约束 #1）：prefs 的 `get` / `set` 失败各一条用例，
断言「内存态保留 + `console.warn`」，不得静默降级。

### 门禁规模自检

按门禁冻结线，单个门禁文件不超过被测对象的 30%。
**若测试文件在实现中开始膨胀，正确处置是抽出 `primitives/` 纯逻辑层单独测，
而不是继续往门禁里加码。**

### 不新增 E2E

android-e2e 不进 CI（ADR-0084），加一个手动跑的 spec 不构成防线，
却会让「有 e2e 覆盖」这句话变成误导。关键行为全部落在 CI 内的主缝上。
⚠️ 后果须登记：**本批无端到端回归防线**，真机验证是手动环节。

## Out of Scope

- **段内位置恢复**（第N段 / 37%）——引擎信号不可得，不是本批取舍。
- **跨端同步阅读位置**——本地单机；且备份域不收这两个键。
- **浏览记录进 WebDAV 备份**——沿用稍后看当前的边界。
- **「浏览超过 N 秒才算」过滤**——需停留时长信号；噪音问题若实测显现，处置方向是加过滤而非加排序。
- **条目点击埋点**——无分母的计数无解释力。
- **插画进「继续读」/ 小说进「浏览历史」**——两轴按作品类型固定分工。
- **第 5 个顶层导航目的地**——受放射 FAB 外环几何约束（ADR-0218 §3.3）。
- **粘性收益的量化验证**——本仓无发布前后基线；见下节。

## Further Notes

### 验证能力的诚实边界

两段的分段观测读点能回答「**功能被不被使用**」：长期为空 = 用户不在读小说/不再回看插画；
非空但零点击 = 位置存错或入口过深。

它们**不能**回答「**粘性因此提升**」——相邻启动间隔是**全局**指标，
不会因本功能单独变化；后者需要发布前后的整体对比，属发版观测，**本仓无基线**。
若要把粘性作为量化目标，需单独立项做度量设计。**此项不作为本批验收条件。**

### 落地时必须同轮改写的既有描述

以下三处描述的是**当前状态**而非机制，本批落地会使命中它们为假，
**必须与实现同轮提交**，否则文档开始说谎：

| # | 位置 | 须改为 |
|---|---|---|
| 1 | 客户端 CONTEXT.md 的「开始阅读」词条（约 :151） | 「无位置时从头；有位置时「继续阅读」并从该话开始」；_Avoid_ 去掉「静默」限定（现在是显式记忆 + 显式文案） |
| 2 | 本地使用度量 primitives 与 store 的字段注释 | 原本写死「「更新」页各段」，收窄为「聚合页分段」并列举 `updates` / `shelf` |
| 3 | ADR-0218 §3.2 / §4 P1 | 标注已由 ADR-0219 兑现（保留原文，不删） |

### 证据缺口

- **中文产品官方功能文档**（微信读书 / 起点 / 番茄）**未取到**——搜索结果几乎全是
  AI 生成内容农场，其中一条列了不存在的产品功能，已作废。
- 起点鸿蒙版的「阅读进度实时同步」只有科技媒体新闻稿，**不作承重依据**。
- 外部对照里 Kindle 为**页级**（分页读器模型，本项目不适用），
  LINE WEBTOON 与 Mihon 为**话级**（与本项目可比）。
