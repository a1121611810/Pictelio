# 辅助机制 fail-safe 与声称可复现 —— 功能规格

## 1. Problem Statement

#900–#907（首页沉浸悬浮顶栏）落地后，五轮以上真机验证 + 六轮 code-review 暴露了五个**互不相关**的缺陷。它们共享同一条结构：

> **一个「辅助性机制」失败了，而系统给出了「一切正常」的表象。**

| # | 辅助机制 | 失败形态 | 表象 | 现状 |
|---|---------|---------|------|------|
| A | 入场动画 | 绑在**冷挂载静态兄弟**上时整段设置区永久不可见 | 无日志、无报错、单测全绿 | 仅 benchNav 深链可达（真实导航正常），机理未定案 |
| B | 构建配置类型检查 | `tsconfig.node.json` 声明了 project reference 但**无任何命令执行过它** | 7 个类型错误长期存在 | 已建单 #910 |
| C | 对比度取样 | 文档里的 `12.03:1` **无法在提交内复现** | 数字看起来精确可信 | 已建单 #909 |
| D | 验收判据 | 「整屏浅纯色底」这一族输入下给不出答案 | 报 PASS 或 FAIL，**都不是「不知道」** | 已登记为失效面，判据本身无解 |
| E | 顶栏高度契约 | 脚本的 `17.067` 与页面的 `17.067vw` 是两个独立字面量 | 各自漂移时不会有任何东西变红 | 已补部分门禁，全站枚举仍无防线 |

同结构但已自愈的第六个实例：度量脚本依赖未在仓内声明的 Pillow——本机全绿、CI 全红（run 36991015462）。已修为零依赖。

这六条的共同点不是「代码写错了」，而是**失败方向错了**：都朝「静默通过」的方向坏。

维护者视角的损失具体是：我在这个特性上交付过**一个自称「已堵住漏洞、实际从未生效」的提交**（判据接缝字段序错位，而当时 3568 条测试全绿）。若它被发布，真机验收会给出「已验证」的假信号。

## 2. Solution

把「辅助机制」按 ADR-0215 决策 1 翻转为 **fail-safe**，并按决策 2 为每条声称补上可复现的机器证据或显式登记。

用户可见的结果：
1. **任何动效都不会让内容消失**。关掉全部动画后，每个页面的内容必须与开启动画时**完全一致地可见**。
2. **构建配置层的类型错误会阻断 CI**（它本该如此）。
3. 文档里出现的实测数字，可在仓内一条命令复现。
4. 判据给不出答案时明确说「不知道」，且这个「不知道」的族被登记在代码里。
5. 脚本与页面之间的契约等式有机器防线。

## 3. User Stories

1. **作为普通用户**，我想在「我的」页看到全部设置项，**以便**我能改主题、配 WebDAV、退出登录。
2. **作为普通用户**，我想在系统开启了「减弱动效」偏好时看到完全相同的页面内容，**以便**无障碍设置不导致功能缺失。
3. **作为普通用户**，我想在应用完全不播动画时页面内容仍完整，**以便**低性能设备不掉功能。
4. **作为维护者**，我想在真机上验证某个动效改动后内容仍可见，**以便**不必逐页人工翻看。
5. **作为维护者**，我想让「删掉入场动画」这个改动在真机上立刻暴露为「内容变了」，**以便**装饰改动不会悄悄改功能。
6. **作为维护者**，我想让构建配置层的类型错误阻断 CI，**以便**一个带类型错误的 `lynx.config.ts` 不会发版。
7. **作为维护者**，我想在改动 `lynx.config.ts` 后本地就能看到类型错误，**以便**不必等 CI。
8. **作为维护者**，我想在提交里复现文档中引用的对比度数字，**以便**评审者不必相信我。
9. **作为评审者**，我想看到「这个判据在哪些输入下给不出答案」被写在代码里，**以便**知道这道门禁的边界而不是以为它覆盖了全部。
10. **作为维护者**，我想在脚本里的硬编码常量与页面实际值不一致时被拦住，**以便**两者不会各自漂移。
11. **作为维护者**，我想在仓内脚本依赖未声明的第三方时立刻失败，**以便**干净环境（CI / 别人的机器）上能跑。
12. **作为维护者**，我想新增一个页面时不被要求手动登记到某个清单，**以便**登记不会成为新的漏网源。
13. **作为维护者**，我想知道顶栏高度门禁覆盖了什么、没覆盖什么，**以便**不误以为它守住了全站。
14. **作为维护者**，我想在真机上量一次对比度并把结果落进仓内，**以便**未来的对比度声明有可复现来源。

## 4. Implementation Decisions

### D1 · 入场动画的 fail-safe 契约（#908）

- 动效是**装饰性**的：可改变内容**如何**出现，不可改变内容**是否**出现。
- 帧体的 `from` 态**不得**包含会让元素「占位但不可见」的属性组合。当前 `item-rise` 的 `from { opacity: 0; … }` 是嫌疑点。
- 验收条件（形态无关）：**把动效整条摘掉，每个页面的内容必须完全可见**。这条比任何具体实现都重要。
- 该修复**优先于**保持错峰视觉一致性；两者冲突时牺牲视觉。错峰观感是否退化须在真机记录。
- 适用范围：`listItemStyle` 的**全部**消费方（8 个文件），而非只修 Me 页那 10 处。
- 冷挂载 vs patch 插入的区别要保留在文档里：`v-for` 动态行（patch 插入）正常，冷挂载的静态兄弟不正常——这是定位依据，不是豁免理由。

### D2 · 构建配置层的类型检查接入（#910）

- `tsconfig.node.json` 需开启「允许 `.ts` 扩展名 import」，并把 `include` 补全为构建配置层的全部文件。
- 处理 `@rsbuild/core` 的类型来源（显式类型依赖或 `skipLibCheck`），并补齐 `strict` 下的隐式 any。
- **最后**才把它接进 `check` 脚本；顺序反了会让 CI 因既有错误直接红。
- 已知代价：CI 门禁变严。这是它本来的样子。

### D3 · 对比度的仓内可复现取样（#909-1）

- 新增与 `verify-top-inset.mjs` **同构**的真机取样脚本：读 `dumpsys` 平台真值 + 截图取样 + 算 WCAG 相对亮度对比度，输出可复算的数字。
- 度量必须**零外部依赖**（Pillow 事件已证明未声明依赖会在干净环境炸）。PNG 解码走标准库。
- 输出形态与幅值对拍脚本一致：PASS / FAIL / **REJECT**（本判据在此样本上给不出答案）。
- 支撑文档中的对比度数字改为「引用该脚本的某次输出」，并登记取样条件（哪台机、哪张截图、哪段像素区）。

### D4 · 判据失效面的登记（#909-3）

- 「整屏浅纯色底」与浅色顶栏在**颜色统计上同形**，颜色维度已无信号可用——**不再投入**。
- 登记必须满足：写在**代码**里（不只是聊天/issue），且有**会红的断言**（该族行为若变化，门禁先响）。
- 脚本的 REJECT 文案必须点名这一族，并告诉操作者「看一眼截图确认标题真在」。
- ⚠️ **不得**为覆盖它而加第三/第四个颜色信号：硬加只会制造「看起来更全」的门禁。

### D5 · 顶栏几何门禁的范围限定

- 全站枚举**不做**：正则扫 `h-[Nvw]` 会把进度条、列表格高、网格单元误判为顶栏（首版实证）。
- 门禁只做无歧义断言：脚本硬编码常量 ↔ 页面实际值（跨文件等式）、公共组件两个变体、已登记的自绘页清单、清单防空转、换算处同源。
- **文件头必须明写它不做全站枚举**——宁可承认覆盖不全，也不留看起来覆盖了实际没有的门禁。
- 新增自绘顶栏页时，登记清单需要同步；这本身是新的漏网源，需在清单里注明。

### D6 · 横图封面留白：接受并登记

- 不改 ADR-0118 的「贴顶、宽满、不裁切」策略。
- 代价写明：首页的视觉均衡性依赖图片本身的宽高比分布，**不由代码保证**。将来若收到「某些图看起来不均衡」的反馈，那是本决策的已知代价，不是回归。

## 5. Testing Decisions

**好测试的标准**：只测外部可观察行为，不断言实现细节；每条门禁必须**自证能红**（把被守的东西改坏 → 转红 → 还原）；期望值来源可追溯到规格 / 真实数据 / 值域不变量，不从实现反推。

**Seam 选择**（沿用既有形态，不新造面）：

| Seam | 层级 | 覆盖 |
|---|---|---|
| 动效契约 | 帧体 + 预设的**纯函数** + 源级门禁 + 真机 | D1 |
| 构建配置 | `check` 脚本 + CI 必跑门禁 | D2 |
| 对比度取样 | 脚本 CLI（真机）+ 合成 fixture 单测 | D3 |
| 判据失效面 | 判定纯函数 + 已登记族的行为断言 | D4 |
| 顶栏几何 | 跨文件等式门禁 | D5 |

**先例**：`verify-top-inset` 的三层判据 + 合成 fixture 门禁 + 真机 CLI；`tests/metricsParse` 的接缝值域不变量；`tests/topBarHeightContract` 的跨文件等式；`PageTopBar.template.test.ts` 的容器类串钉死。

**新增测试的硬约束**：
- 每个抽取器/剥除器必须有**防空转断言**（ArchUnit `failOnEmptyShould` 教训）。
- 比率型输出必须有**值域不变量**（`[0,1]`）——比逐字段断言更抗重排。
- 合成 fixture 必须**实跑被测脚本**，不得用源码文本断言代替执行。
- ⚠️ **未声明的外部依赖会让门禁在干净环境失效**：任何仓内脚本用到的第三方，要么在仓内声明，要么改为零依赖。新增门禁时**必须**在无该依赖的条件下验证一次。

## 6. Out of Scope

- **全站顶栏几何一致性门禁**（D5 已说明为何不做；需要顶栏容器的结构化识别，不是本轮）。
- **「整屏浅纯色底」的可判别化**（D4：原理上不可判别）。
- **`TITLE_GLYPH_BIAS` 按标题变体分别标定**（提高判别力，非本轮目标；当前靠容差吸收）。
- **图片查看器跟随出血**（此前已裁定另票）。
- **benchNav 深链本身的改造**（A 项在产品代码治本，深链是否也改由实施期判断）。
- **首页搜索按钮**（此前已裁定不加）。

## 7. Further Notes

- 本 spec 的五项之间**无强依赖**，但有两处顺序约束：`tsconfig.node.json` 的**修复必须先于**接入 `check`；动效的 fail-safe 改造会改变视觉，须**先**在真机记录改造前的错峰观感，**再**改。
- 决策 1（fail-safe）会**改变动效契约**，与 ADR-0211 相关。实施首票需同步修订 ADR-0211 的失效方向（当前它允许 `both` 填充驻留 `from`）。
- 维护者已明确裁定：横图留白**接受并登记**，不改策略。
