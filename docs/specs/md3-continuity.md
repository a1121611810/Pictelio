# 界面连续性 spec —— 让 App 跟手（2026-10-01）

> 上游决策：[`ADR-0211`](../adr/ADR-0211-ui-continuity-motion-contract.md)（界面连续性契约，10 条决策 + P1–P7 待真机取证探针）
> 前置事实底座：[`ADR-0210`](../adr/ADR-0210-lynx-style-stack-capability-boundary.md)（Lynx 样式栈能力边界，路径 A–E 矩阵）
> 落地纪律来源：[`ADR-0212`](../adr/ADR-0212-tonal-elevation-surface-over-shadow.md) 后果章「三者必须分批落地、分批回归」
> 证据纪律：路径 + 符号名，**不写行号**；每条数字都带口径

## Problem Statement

### 用户看到的是什么

打开这个 App，**所有东西都是「啪」地换掉的**。

- 按下一个按钮，底色闪一下就没了 —— 不是「按下去、松手、回弹」这一段过程，是一个瞬间
- 从作品详情底部拉起操作面板，面板是**砸**在屏幕上的，不是**滑**上来的
- 从列表点进详情再返回，整页硬替换，来去两个方向**看起来一模一样**
- 一屏作品加载出来，是一瞬间**填满**的，不是逐张**铺开**的

用户不会用「令牌」「状态层」「过渡」这些词来形容这件事。用户会说：**粗糙、廉价、不跟手**。

### 为什么是「性质之别」而不是「强弱之别」

MD3 的按压反馈本质是**时间**：一层 12% 的 alpha 状态层在 100–150ms 内淡入。

本项目的颜色**是对的**（ADR-0205～0209 之后令牌层已高度合规），但时间是 **0ms**。
人眼对 0ms 变化的知觉是「闪」，对 150ms 的知觉是「响应」。这两者**不是同一件事做得强一点弱一点**，
而是两件不同的事。所以补一个时长不是「优化」，是把 App 从「闪」挪到「响应」这一侧。

### 问题的形状：合规的是令牌，空的是消费

ADR-0205 立项以来，**令牌层 20/20 齐备**：6 档时长、4 条缓动、15 档排版四元组、6 档 shape、20 条状态层
（`tokens.css` 中 `--duration*` 与 `--motion-*` 可复算，见 ADR-0211 背景章）。
本 spec **不重复任何令牌工作**，只处理消费层。

消费层的断裂还有一个更硬的形态：**63 个状态层点，颜色全对，时间全为 0**。
这 63 个点里，24 处走的是「预计算实色」这条**兜底**路径（ADR-0211 决策 8 判为口径待归正，不是缺陷），
27 处走的是 alpha 正路，7 处是透明度变化，5 处是用阴影表达状态（ADR-0212 决策 6 已裁定出清）。

### 这个问题为什么不能靠「照着 MD3 文档写」解决

因为**写出来的动效可能根本不渲染，而所有静态信号都是绿的**。

Lynx 侧有两类静默失效（ADR-0210 已实测定论）：

- `hover-class` 属性本身不产生视觉切换（真机实证，issue #868）
- `transform` / `scale` / `translate` / `rotate` **工具类**产出 CSS 规则，但那些规则引用 9 个
  **从未被定义**的 `--tw-*` 变量 ⇒ 按 CSS 规范该声明在计算值阶段非法 ⇒ 渲染为 `transform: none`

后者是**第三类失败**：构建过、类型过、单测过、产物有规则，**只有真机看得见渲染为空**。
本 spec 的 Testing Decisions 整节就是为这一类失败设计的。

## Solution

### 用户看到的是什么（改造后）

**让每一次可见的状态变化，都在时间维度上被表达出来。**

| 场景 | 现状 | 改造后 |
| --- | --- | --- |
| 按下任何可点的东西 | 底色 **0ms 瞬变**（闪） | 状态层在 **150ms** 内淡入（响应），关键按钮还会跟手缩放 |
| 底部面板 / 居中对话框 / 顶部锚定面板 / 分页器 | **0 个入场动画**（砸出来） | 遮罩淡入 + 面板按几何上滑或缩放入场，关闭时按同一段路退场 |
| 列表首次出现 | 瞬间填满 | 首屏前若干项**错峰**浮出，错峰量有上限 |
| 前进 / 后退 | 整页硬替换，**0 处转场** | forward 从右侧滑入、back 从左侧回位，**方向可分辨** |
| 开启「减弱动效」 | （该场景下同 0ms） | 三条既有降级规则全量接入，**且退场计时器同步归零**（不卡空窗） |

### 关键取舍（如实登记，不假装免费）

1. **退场会多一段 150ms 的不可交互窗口**。Lynx 无 `transitionend` 事件，退场只能「先播后退场再卸载」，
   期间弹层仍占位。纯触屏下 150ms 可接受；开启减弱动效时归零。这是**无 `transitionend` 的必然成本**。
2. **后退转场是能力削减**。back 不做「旧页等待新页退出」的双页并存（那是 Web 侧做法，Lynx 上生命周期成本高
   且无事件可挂），只给**重新进入的旧页**一个滑入，不做真实反向。**在此登记，不假装做到了双向完整转场。**
3. **按压的阴影那一档不引入过渡**。已验证的两个过渡载体都不覆盖 `box-shadow`，未验证的路径不押注。
   该点的颜色反馈不受影响（同元素并列的 pressed 状态层仍提供反馈）。这是**显式登记的失效面**，不是待修缺陷。
4. **路径 E 的存量疑点不修**（文本选中工具条的 `rotate-45` 抓手）。按 ADR-0210 决策 5 登记为待真机取证项，
   本 spec 不动它 —— 改它要先取证确认它当前确实未旋转，否则可能「修」一个其实正常的东西。

### 收口为项目级契约

动效从「6 个组件里的偶然实现」变成**项目级契约**：动效时长与曲线只有一个入口，导出四类预设
（**入场 / 退场 / 按压 / 错峰**），组件内禁止出现时长与曲线字面量；所有新动效一律接入既有的
「减弱动效」偏好事实源，**不新增降级规则**（复用 R1/R2/R3）。

### 双层防线

**静态自动门禁 + 真机像素自动门禁**。理由是本技术栈存在第三类失败模式（见 Problem Statement 末节），
静态手段在原理上抓不到它。因此**每条门禁都必须显式登记它抓不到什么** —— 这是本仓硬约束
（AGENTS.md「门禁冻结线」：*假绿比没门禁更糟：会骗人的门禁会被人信*）。

### 分批落地

本改造与排版（ADR-0206）、缓动（ADR-0207）、色调层级（ADR-0212）**叠在同一批 UI 上**。
必须分批落地、分批回归，否则无法归因是哪一个改善了观感。落地顺序见 Further Notes。

## User Stories

> 全部为**用户视角**。「减弱动效」= 系统「移除动画」/ `prefers-reduced-motion` 偏好。

### 一、按压反馈（1–9）

1. As a **作品浏览者**, I want **点瀑布流里任意一张作品卡时，卡片立刻给出可见的按压反馈**, so that **我确信这一下点中了，而不是怀疑自己没点上。**
2. As a **收藏用户**, I want **点收藏按钮时它先变暗、再落回原色**, so that **我知道收藏已经生效，不用回头再确认一次。**
3. As a **设置用户**, I want **按下设置列表里任意一行时，那一行浮起一层浅色**, so that **长列表里我不会按错行。**
4. As a **设置用户**, I want **拨动开关时底色是平滑变过去的，不是啪一下换掉**, so that **开关看起来是活的，不是一张静态图。**
5. As a **作品浏览者**, I want **悬浮按钮被按下时自己缩一下再弹回**, so that **它看起来是可以按的实体，不是贴在屏幕上的一张贴纸。**
6. As a **评论用户**, I want **点评论输入框时底色平滑过渡**, so that **我的注意力被引到「我要写评论」这件事上。**
7. As a **搜索用户**, I want **点搜索框时它的状态变化是渐变过来的**, so that **我知道焦点已经进去了。**
8. As a **作品浏览者**, I want **长按作品卡弹出的操作菜单里，按下菜单项时那一条有按压反馈**, so that **盲选菜单项时不会选错。**
9. As a **作品浏览者**, I want **按住不放的时候反馈一直保持、松手才消失**, so that **按压状态不会在按住期间自己闪掉。**

### 二、弹层的入场与退场（10–20）

10. As a **作品浏览者**, I want **作品详情底部的操作面板是从屏幕下缘滑上来的**, so that **它看起来是被托上来的，不是砸到我脸上的。**
11. As a **作品浏览者**, I want **面板上浮的同时背后的遮罩是淡进来的**, so that **我的注意力被引到面板上，而不是被整屏变暗打断。**
12. As a **小说读者**, I want **点「看系列」打开的系列面板是滑上来的**, so that **打开它像翻下一页，而不是被弹窗劫持。**
13. As a **评论用户**, I want **评论面板滑上来的同时，已有评论有轻微的错峰浮出**, so that **打开评论时内容是一层层出现的，不是一次砸满屏。**
14. As a **搜索用户**, I want **点搜索框拉起的搜索面板是滑上来的**, so that **它和底部其他面板是同一个动作，我不用学第二套手势。**
15. As a **小说读者**, I want **点导出按钮打开的导出面板是滑上来的**, so that **全站的弹层看起来是一套东西。**
16. As a **作品浏览者**, I want **分页器弹出时是从下方推上来的**, so that **选页码这件事不会打断我当前的浏览。**
17. As a **收藏用户**, I want **收藏面板弹出时是从上方落下来的**, so that **它和底部面板的来向不同，我一眼能分出这是「从上面压下来」的一层。**
18. As a **关注列表用户**, I want **提示我加入关注列表的居中对话框是「轻轻放大 + 淡入」而不是上滑**, so that **它和底部面板不混淆。**
19. As a **任意用户**, I want **我把面板关掉时它滑回去**, so that **我知道我确实关掉了它，而不是怀疑它还在。**
20. As a **任意用户**, I want **关掉面板不需要多点一次、也不需要等一秒**, so that **关闭动作不因为动画而变慢。**

### 三、列表入场与错峰（21–26）

21. As a **作品浏览者**, I want **列表刚加载出来时作品卡是逐张轻轻浮出的**, so that **页面像是被铺开，而不是被瞬间填满。**
22. As a **小说读者**, I want **小说列表的条目也是逐条浮出的**, so that **我知道内容已经到位，不需要再干等一次。**
23. As a **下载管理用户**, I want **滑进新的下载条目时只有新出现的那一条在动**, so that **我能一眼找到刚加进去的那条。**
24. As a **设置用户**, I want **很长的列表不会一项一项慢慢爬很久**, so that **我滑到哪它就是什么样，不等我。**
25. As a **任意用户**, I want **已经滚过去的条目不会在我回滚时重新演一遍入场**, so that **往回滑的时候画面是安静的。**
26. As a **作品浏览者**, I want **只有第一屏前几张有错峰，后面的直接就在那儿**, so that **加载完成的等待时间不会随着我滚多快而变长。**

### 四、页面导航（27–32）

27. As a **作品浏览者**, I want **点开作品详情时新页面从右边滑进来**, so that **我知道我往更深的地方走了。**
28. As a **作品浏览者**, I want **从详情返回列表时旧页面从左边回来**, so that **我知道我是往回走，不会以为自己又深了一层。**
29. As a **小说读者**, I want **从小说详情返回书架时，返回的来向和去时相反**, so that **我不会再在书架里迷路。**
30. As a **任意用户**, I want **页面切换时旧内容淡出、新内容淡入一点**, so that **切换不会像闪烁。**
31. As a **任意用户**, I want **在页面里按下返回与系统返回键的动画是同一个**, so that **两种返回方式的手感一致。**
32. As a **任意用户**, I want **哪怕我只是切回上一个页面，也能看出那是「回去」**, so that **前进和后退在视觉上是两件事。**

### 五、减弱动效偏好（33–38）

33. As a **设置了减弱动效的用户**, I want **系统的「移除动画」开着时，我按任何按钮都直接到最终状态**, so that **我不会因为界面动而感到不适。**
34. As a **设置了减弱动效的用户**, I want **弹层立刻出现、也立刻消失**, so that **我不会在关弹层时被迫等一段空白。**
35. As a **设置了减弱动效的用户**, I want **列表条目不会一个一个浮出**, so that **内容是直接铺好的。**
36. As a **设置了减弱动效的用户**, I want **页面切换不产生滑动**, so that **我不会因为位移而眩晕。**
37. As a **设置了减弱动效的用户**, I want **这个偏好在弹层、列表、页面切换三种场景里都生效**, so that **它不是只对某一个页面有效。**
38. As a **任意用户**, I want **如果系统不提供这个偏好，App 也不要偷偷地动**, so that **在不支持的设备上我不会遇到无预警的动画。**

### 六、加载态（39–43）

39. As a **任意用户**, I want **等待内容时看到的是骨架屏而不是空白**, so that **我知道 App 正在工作。**
40. As a **任意用户**, I want **骨架屏的微光是循环的**, so that **长时间等待时我知道它还在动、没有卡死。**
41. As a **设置了减弱动效的用户**, I want **骨架屏的循环微光在我开了减弱动效后停下**, so that **持续不断的运动不会一直干扰我。**
42. As a **作品浏览者**, I want **骨架屏换成真内容时有过渡**, so that **内容落位不是硬生生替换。**
43. As a **任意用户**, I want **刷新时旧内容留在原地、新内容覆盖上去**, so that **我刷新时不会看到一片空白。**

### 七、内容更新态（44–48）

44. As a **作品浏览者**, I want **加载更多时新的一批作品是浮出来的，而不是突然长出来**, so that **我知道这一批是新到的。**
45. As a **收藏用户**, I want **取消收藏时按钮上的反馈是「弹一下消失」**, so that **我知道它是被移走了，不是被禁用。**
46. As a **收藏用户**, I want **重新收藏时按钮弹回**, so that **我知道我加回来了。**
47. As a **任意用户**, I want **按下按钮之后、等待网络期间它不会自己弹回原样**, so that **我知道我的操作还在路上。**
48. As a **作品浏览者**, I want **下拉刷新时我知道已经在刷新了**, so that **我不会重复下拉。**

### 八、维护者（49–51）

49. As a **维护者**, I want **动效的时长和曲线只在一个地方能改**, so that **我改一个值就能改全站，不会出现两处不一样。**
50. As a **维护者**, I want **我写下一个不生效的动效写法时门禁立刻告诉我**, so that **我不会把一个静默失效的写法合进去。**
51. As a **维护者**, I want **每条门禁都写明它抓不到什么**, so that **我不会把「门禁全绿」读成「界面都对」。**

## Implementation Decisions

> 全部依据 ADR-0211 的 10 条决策 + ADR-0210 的能力矩阵。
> **本节不写具体文件路径与代码片段** —— 需要指代实现处一律引用决策内容或指向 ADR 本身。

### D1 · 动效唯一入口与四类预设（依据 ADR-0211 决策 1）

动效时长与曲线**只从唯一入口取**，组件内禁止出现时长或曲线字面量。入口导出四类预设：

| 预设 | 覆盖场景 |
| --- | --- |
| **入场** | 弹层、列表项、页面首次出现 |
| **退场** | 弹层、列表项消失 |
| **按压** | `active:` 状态层的过渡 |
| **错峰** | 列表项逐项延迟 |

两个必须遵守的实现约束（**都是会静默失效的坑**）：

1. **类名必须以字面量出现在入口里，不能运行时拼接**。构建的扫描面包含 `.ts`，字面量能被扫到；
   而拼接出来的名字扫不到 ⇒ **产物零规则、渲染零反馈**。判据是「构建时能否扫到」，不是「运行时能否拼对」。
2. **导出值必须区分「工具类串」与「inline style 值」两种形态**，因为引擎实际可过渡的属性不同（见 D3）。

**例外（刻意，与 D1 方向相反）**：`on-primary` 档的状态层类名**不搬进入口**，保持字面量留在元素上（依据见 D8）。

### D2 · 能力路径白名单 —— 哪些写法可用、哪些静默失效（依据 ADR-0210 路径矩阵 + 决策 2）

| 需求 | 唯一合规路径 | 状态 |
| --- | --- | --- |
| 颜色 / 透明度 / 尺寸等属性的过渡 | **路径 A**：Tailwind `transition-*` + `duration-[…]` + `ease-[…]` | **已验证**（产物有真规则） |
| 位移 / 缩放 / 旋转 | **路径 B**：inline `:style`，写**字面量** | **已验证**（生产实证） |
| 进入 / 退出 / 循环动画 | **路径 C**：`<style>` 块内 `@keyframes` + `animation` | **已验证**（产物有真规则） |
| 按压反馈 | `active:` 变体；**禁** `hover-class` | `active:` 已验证；`hover-class` **静默失效**（真机实证） |

**三类静默失效必须分别记住，方向相反的两条不能笼统叫「不支持」**：

- **真死类名**（构建期就 0 规则）：`cursor-*` / `select-*` / `touch-*` / `pointer-events-none`。
  其中只有 `pointer-events-none` 有门禁钉住，其余 3 个**无任何机器防线**。
- **路径 E**（**产出 CSS，但渲染无效**）：`transform` / `scale` / `translate` / `rotate` 工具类。
  机制是产物里的组合声明引用 9 个 `--tw-*` 变量，而这些变量**从未被定义**（preset 不发 base/preflight 层），
  按 CSS 规范该声明在计算值阶段失效 ⇒ `transform` 回落为 `none`。
  ⇒ **判据收敛成一句：这条 CSS 声明的每个 `var()` 是否有定义。有定义才渲染。**
- **`background-color` 是替换语义、不是合成语义**：alpha 状态层画在实心底色上会替换掉底色。
  这解释了为什么 `on-primary` 档必须是**预合成不透明色**（沿用既有令牌，不在本 spec 变更）。

**工作纪律（写死，来自 ADR-0210 决策 4）**：新增视觉能力**先验产物再写码**；
判据只认三类证据（从强到弱）—— ① 产物 CSS 表 / 真机截图 ② 用项目真实构建配置跑一次 JIT ③ preset 源码。
**配置与注释不是证据**（ADR-0210 的起因就是一条「看起来很有据」的注释）。
真机未取证的能力按「待取证」写，不按「能用」写。

### D3 · 状态层按形态分载体，而不是一律挂同一个过渡类（依据 ADR-0211 决策 2）

先看引擎**实际**过渡哪些属性（产物实测）：

| 载体 | 覆盖属性 | 判定 |
| --- | --- | --- |
| `transition-colors` | `background-color`、`border-color`、`color`（3 条） | **已验证** |
| 裸 `transition` | 上述 3 条 + `opacity`、`transform`（5 条） | 规则在产物中 |
| 二者 | **均不含 `box-shadow`** | 阴影过渡**无可用工具类** |
| `transition-opacity` / `-shadow` / `-transform` / `-all` | — | 产物 0 条，**未验证 ⇒ 不押注** |

由此得到**逐形态载体映射**（处数取自 ADR-0211 决策 2 表，口径为 CSS 变体）：

| 形态 | 处数 | 载体 | 时长 | 曲线 |
| --- | --- | --- | --- | --- |
| alpha 状态层 `active:bg-layer-*` | 27 | `transition-colors` 工具类 | `--durationFast` | `--motion-standard` |
| 预计算实色 `active:bg-state-pressed-*`（迁至 `bg-layer-pressed-*`） | 24 | `transition-colors` 工具类 | `--durationFast` | `--motion-standard` |
| `active:opacity-*` | 7 | **inline `:style`** | `--durationFast` | `--motion-standard` |
| `active:shadow-[var(--md-elevation-1)]` | 5 | **不引入过渡**（见 D4） | — | — |
| `active:w-…` / `active:h-…`（尺寸变化，非状态层） | 2 | **inline `:style`** | `--durationFast` | `--motion-standard` |
| `active:bg-white/10`（非令牌字面量，画在菜单面 scrim 上） | 1 | 归正后同上（alpha 行），**单列处置** | `--durationFast` | `--motion-standard` |

三条要点：

1. **`opacity` 不在 `transition-colors` 覆盖内** ⇒ 给透明度变化挂该类是**静默失效**。
   判据必须查**载体**，不能查「有没有 transition」。
2. **实色档与 alpha 档同档**（同为 `--durationFast`）：12% 明度差上曲线差异不可分辨，分档属凭感觉。
3. **非颜色属性一律走 inline `:style`**：`transition-opacity` / `transition-shadow` 在产物中是 0 条，
   而「产物 0 条」**无法区分「无人使用」与「引擎不支持」**。inline `:style` 已被生产实证，
   是当前**唯一无歧义**的路径。路径 B 的写法约束：不得引用 `--tw-*`（一律无定义），
   也不得依赖未在令牌表定义的变量。

### D4 · 阴影档选「不引入过渡」，并把它登记为显式失效面（依据 ADR-0211 决策 2 末）

按项目纪律（ADR-0205 决策 6「代码里写了 ≠ 真机生效」），**未验证的路径要么取证后再用、要么不用**。

- 阴影过渡列为**待真机取证项 P3**。若真机证实不支持，本条即成为**该失效面的显式登记**（而非「待修的缺陷」）。
- 该点的按压反馈靠**同元素并列**的 pressed 状态层提供，**颜色反馈不受影响**。
- 顺带承接 ADR-0212 决策 6 的裁定：**用阴影表达按压状态这条路整体出清**（禁写 `active:shadow-[var(--md-elevation-*)]`），
  改用状态层或透明度两条通道。**本 spec 不重复该裁定，只登记这条耦合。**

### D5 · 退场走「两段式显隐」协议，不靠事件驱动（依据 ADR-0211 决策 3）

**硬约束：Lynx 无 `transitionend` 事件**。这意味着退场动画**无法**用「播完再卸载」的事件回调实现，只能显式建模。

协议（由弹层壳收口，调用方从「直接条件渲染组件」改为「传开合状态」）：

```
open=true    → 挂载 + 挂入场动画
open=false   → 摘入场类 + 挂退场类 → 启动计时器
计时器到期   → 卸载（真正不渲染）
计时器时长   = 与退场动画**同源**的令牌值（不写字面量）
```

**计时器时长必须从令牌读**：降级开启时退场瞬间完成，计时器必须**同步归零**，
否则关弹层会卡住一个空窗期（`--durationFast` = 150ms 的停顿）。这是「唯一入口」的**第二个硬需求**。

**既有契约不得被破坏**：底部弹层的挂载由父级条件渲染控制、组件**不自带开合状态**、**禁止**改可见性隐藏
（ADR-0123）。即「卸载即消失」，**不存在「已挂载但正在淡出」的中间态** —— 上面这个协议正是为造出该中间态而存在。

**已知代价**：退场期间弹层仍占位且不响应滚动（需在退场态锁住滚动）。这是「无 `transitionend`」的必然成本。

### D6 · 弹层壳收口：按**几何**归属，不按「谁引入了我」（依据 ADR-0211 决策 4）

收口底部弹层的既有壳（遮罩 + 贴底面板 + 标题栏 + 关闭键），在其上**加两条入场动画**：
遮罩 `opacity` 淡入、面板 `translateY` 上滑（走 `@keyframes`，**非工具类** —— 见 D9）。

| 几何 | 弹层 | 处置 |
| --- | --- | --- |
| 贴底（`absolute bottom-0 left-0 right-0`） | 系列面板 / 评论浮层 / 搜索面板 / 小说导出面板（4 个底部弹层消费方） | **进壳** |
| 贴底（自绘壳，但几何与底部弹层同款，有根容器） | 分页器 | **进壳** |
| 顶部锚定 + 定高 | 收藏面板 | **进壳**，需支持「顶部锚定 + 定高」变体（或归一到贴底） |
| 居中 | 关注列表提示对话框 | **❌ 不进**：几何不同（入场应是缩放 + 淡入而非上滑）。**且它是唯一已有开合 prop 的弹层 ⇒ 选它做两段式退场的首个试点** |

> ⚠️ 归属边界按**几何**划分：注释自述「与贴底等价」但写法是「顶部锚点 + 定高」的，仍算贴底几何。
> 早期测绘曾把「自绘面板」「非底部几何」判给三个弹层，实跑已订正（见 ADR-0211 决策 4 的订正注）。

### D7 · 列表错峰有上限（依据 ADR-0211 决策 5）

**不是新建组件**，而是把既有列表组件已有的入场错峰机制（首屏分档 + 错峰量归零逻辑）**收口进错峰预设**，
并给剩余**手写滚动容器**的列表提供接入点。

- 实跑规模：**10 个页面**已覆盖（20 个调用点），**7 个页面**仍是手写滚动列表 —— 整改面就是这 7 个。
- **错峰上限**：只对**首屏可见的前 N 项**施加错峰，其余直接终态。
  虚拟滚动场景下若对全部项逐项延迟，长列表的末项入场时间会随长度线性漂移。

### D8 · 路由转场在导航发起侧自做，并登记能力削减（依据 ADR-0211 决策 6）

**Lynx 侧无路由 transition 支持**（vue-router 的过渡配置项与 `<Transition>` 不生效），
因此转场**只能在导航发起侧自建**：页面容器持有「方向 + 阶段」状态，导航时写入，页面按状态挂入场类。

| 方向 | 视觉 | 依据 |
| --- | --- | --- |
| **forward**（进入更深层级） | 新页面**从右侧**滑入 + 轻微淡入 | 平台约定：前进 = 内容右移 |
| **back**（返回上层） | 旧页面**从左侧**回位 | 与 forward 互为**逆操作**，不是新页面反向滑入 |

三条实现约束：

1. **不引入路由库层抽象** —— 只在路由处导出一个「导航 + 方向」的包装，现有推入/替换调用点保持不变。
2. **back 不做双页并存**（见 Solution 的取舍 2）—— 这是**有意的能力削减，在此登记**。
3. 与 D5 的两段式协议**共用同一套「令牌同源计时器」**。

**方向可分辨性依赖未取证能力**（探针 P6）：若真机证明 forward/back 不可区分，
则转场改为**无方向的纯淡入淡出**，并登记能力削减 —— 不假装能做到。

### D9 · 按压缩放走 inline 形态，不走工具类（依据 ADR-0211 决策 7 + ADR-0210 路径 E）

**这是「构建全绿、渲染为空」的典型陷阱。** 两个都可行的写法，按场景选：

1. **持续跟手的按压反馈**（按下即缩、松开复原）→ inline `:style`，绑响应式的 transform 值
2. **一次性播放的动画**（缩放入场 / 弹跳）→ `<style>` 块内 `@keyframes` 里**手写** transform 声明

**为什么 `@keyframes` 里能写而工具类不行**：既有列表入场关键帧的帧体里确实有
「位移 + 缩放」组合，即引擎**支持** transform 声明。失效的不是 transform 属性，
而是**工具类那条路径的 `--tw-*` 变量未定义**。**判据是「变量有没有定义」，不是「属性是什么」。**

**不要试图「把 corePlugin 加回白名单」来修** —— 规则本来就在，缺的是 `--tw-*` 的定义；
要它生效就得手工实现 Tailwind 的 base 层。

**同时禁止**：`hover-class` 承载任何缩放/位移（属性本身静默失效）。

### D10 · 状态层口径归正是**归正**，不是 bug 修复（依据 ADR-0211 决策 8）

24 处预计算实色档迁到 27 处所在的 alpha 正路。**必须写清楚它不是什么**：
这 24 处**当前是生效的**（预计算实色在实心底色上正常显示），它是**口径待归正**，不是「24 处按压没生效」的 bug 修复。

**迁移必须逐点判定底色档，不能批量改名**：

| 消费点底色 | 目标 | 依据 |
| --- | --- | --- |
| 实心主按钮 | 预合成不透明色的 `on-primary` 档 | `on-primary` 档的 alpha 叠加在 Lynx 上**原理不可达**（替换语义） |
| 各级 surface / 其他 | 保持 alpha 的四档（`primary` / `on-surface` / `error` / `surface`） | 「范围是封闭的」，**不得扩大化** |

**⛔ 与现有门禁的交互（本决策最容易踩的坑）**：`on-primary` 档类名**必须继续以字面量留在元素上，
不得搬进动效唯一入口**。现有门禁的 **C3** 逐标签扫生产组件，要求「元素写了 `on-primary` 档状态层 ⇒ 同元素必须带实心底色」；
已登记的盲区之一是「`.ts` 全文」。把类名挪进 `.ts` 会**主动制造**这个盲区，让消费约束失去机器防线。

### D11 · 全量接入既有的减弱动效偏好，不新增规则（依据 ADR-0211 决策 9）

偏好事实源是**唯一**的既有 composable（禁止组件自建媒体查询）。四类预设与本 spec 的所有新组件**一律接入**，
归入既有三条降级规则：

| 本 spec 的动效形态 | 归入 | 确定行为 |
| --- | --- | --- |
| 状态层过渡、遮罩淡入、面板上滑 | **R1（过渡）** | 整条过渡置 `none` ⇒ 状态瞬切。构建侧 = **不挂** `transition-*` 类（挂 0ms 是同义反复） |
| 列表项入场、错峰浮出、循环动画 | **R2（关键帧）** | 整条动画置 `none`，**含 infinite 循环** |
| 按压跟手缩放、弹跳 | **R3（弹性与错峰）** | 动效**本身不生成**（不改几何、错峰恒 0）。**只降时长无效**（前庭反应与位移量成正比） |

**两条增量**（都不新增规则形态，只把已有规则的适用范围写明）：

1. **R1 侧**：过渡被置 `none` 时，**D5 的退场计时器必须同步归零** —— 否则出现「动画已停但遮罩滞留」的空窗期。
2. **R3 侧**：D9 的 inline transform 跟手值在 R3 下**不生成**（不只是不加过渡）。

**未验证项**：该偏好走 `window.matchMedia`，而 Lynx 原生是否实现它需真机确认（**探针 P7**）。
该 composable 已有「无 `matchMedia` ⇒ 按未开启处理并 `console.warn`」的显式降级，符合禁静默降级。

### D12 · 残留项单列处置，不批量改名（依据 ADR-0211 决策 10）

| 残留 | 处置 |
| --- | --- |
| 注释里引用的 Fluent 遗留缓动旧值（实际取值已归正为 MD3 缓动令牌） | **不改代码**。残留物是「为何改」的证据链，**只删注释文本、不得回退代码** |
| 画在菜单面 scrim 上的非令牌字面量状态层（1 处） | **单列**，不并入 D10 的批量迁移。**实施前须逐点确认底色档** |
| 尺寸变化档（2 处） | 归 D3 表末行走 inline 过渡，**不计入状态层统计** |

## Testing Decisions

### 5.1 什么样的测试算好（本节的门禁纪律，违反视为架构违规）

1. **只测外部行为**：断「用户能观察到的结果」，不断「内部实现是不是这么写的」。
   动效的外部行为 = **某时刻这个元素在画面上是什么样子**，不是「某个类名被挂上了」。
2. **每条门禁必须自带判别力自证**，两个部分缺一不可：
   - **反事实**：塞进一个形态不同的违规样本，**必须转红**；且反事实要喂**两种以上换皮形态**
     （空白、引号种类、`var()` 带 fallback、模板字符串），避免单形态门禁 fail-open。
   - **抽取器自身有效**：扫描面非空、命中数有**下界**、扫描确实跑在真实目录上。
     理由：正则塌陷 ⇒ 集合为空 ⇒ 全称断言**恒绿**（这是本仓反复在消灭的假绿）。
3. **判据必须自带阳性对照**。否则「什么都没搜到 / 什么都没发生」无法区分
   「引擎不支持」与「判据写错了 / 探针没触发」。**这是本仓首版探针假阴性的直接教训。**
4. **期望值溯源（oracle）**：断言指向**独立来源**（官方令牌表 / ADR 决策表 / 可算的构造样本），
   禁从当前产物反推。仓内先例：对比度助手的 oracle 是 WCAG 2.1 公式；
   亮度探针的 oracle 是 BT.601 公式。
5. **规模线**：**单个门禁文件不得超过其被测对象的 30%**。超过就停下来问
   「我是在防回归，还是在给回归创造就业」。
6. **单轮诊断规则**：一轮只在「自己这轮写的」里找到问题、在「要交付的东西」里找到 0 个 ⇒ 该轮判为空转。

### 5.2 为什么必须「静态 + 真机像素」双层（用户已拍板）

本技术栈存在**第三类失败**：**构建过、类型过、单测过、产物有 CSS 规则，只有真机看得见渲染为空**（ADR-0210 路径 E）。
静态手段在**原理上**抓不到它 —— 因为静态面看到的一切都是绿的。

⇒ 因此**每条门禁都必须显式登记「已知失效面」**：它**抓不到什么**。
依据是本仓硬约束（AGENTS.md「门禁冻结线」：*假绿比没门禁更糟：会骗人的门禁会被人信*），
以及既有的挂账先例（`docs/research/md3-visual-regression-2026-09.md` §8.8「已知无机器防线的项（显式挂账，勿当『已覆盖』）」，
其 D-1…D-N 条目格式即为登记范式）。

### 5.3 静态层门禁（进 CI）—— 8 条

宿主文件：**优先挂在既有门禁宿主**（`md3GuardScans.test.ts` 现为规则 1–8，新规则沿用其既有纪律：
每条规则须有 `it('反事实')` 与 `it('抽取器自身有效')`），不另起炉灶。

| # | 门禁 | 判据要点 | **已知失效面（抓不到什么）** |
| --- | --- | --- | --- |
| **G1** | **唯一入口**：生产组件里 `transition:` / `animation:` 声明、或 `duration-*` / `ease-*` 工具类的**时长位与 timing-function 位**不得出现字面量 | 必须能区分「时长位 / 曲线位」「延迟位」「注释」三类。**早期粗口径会命中 54 处**，其中含长按 500ms、输入防抖 600ms 等**非动效时长**与大量中文注释 ⇒ **信噪比不可用，不得作为门禁**。已登记的例外须在同处有注释说明 | 抓不到**注释里新造的**字面量用法；抓不到 `.ts` 全文里拼接的类名（ADR-0211 决策 8 已登记的 C3 盲区同源）。**延迟位豁免是本门禁的主动放行面** |
| **G2** | **状态层过渡覆盖率**：状态层的 51 个点，**同元素**必须带正确的**载体**；透明度变化与尺寸变化的 9 个点必须带 inline 过渡 | 判据须查**载体**而非「有没有 transition」—— 必须抓住「挂了 `transition-colors` 却以为覆盖了透明度」这种错 | 抓不到「载体正确但时长/曲线值错」（那是 G1 的面）；**抓不到真机上该过渡是否真的插值**（P2 的面） |
| **G3** | **无死 transform 工具类**：生产组件与动效唯一入口中不得出现 `scale-*` / `translate-*` / `rotate-*` 工具类 | 复算产物中该族工具类计数必须为 0 | 抓不到 **inline `:style` 里引用未定义 `--tw-*`**（D9 已禁，但门禁不覆盖 inline 内部表达式）；抓不到手写 CSS 里**引用其他未定义变量**的声明 |
| **G4** | **`on-primary` 档类名仍留在组件里**：动效唯一入口中不得出现该档字面量 | 直接服务 D10 的 C3 防线不被主动制造 | 抓不到 `.vue` 的 `<script>` 块内**拼接**该类名（与 G1 同源的 `.ts` / script 盲区） |
| **G5** | **口径归正完成**：预计算实色档的 `active:` 消费处数归零 | 逐点判定底色档的结果必须被钉住，防止回潮 | 抓不到**底色档判错**（判错仍然通过，因为门禁只看「不是实色档」）⇒ 底色档正确性靠 D10 的人工逐点确认 + 真机取样 |
| **G6** | **弹层入场齐备**：7 个弹层组件**0 个零动画** | 6 个走壳（含入场）、1 个走居中变体。复算：7 个弹层的 `@keyframes` 命中数全部 > 0 | 抓不到「有 `@keyframes` 但**没挂到元素上**」；抓不到动画**时长/曲线**是否合理（观感类不判）；抓不到退场是否存在 |
| **G7** | **路由转场存在且方向集合恰为两值**：导航包装导出「导航 + 方向」，方向取值集合恰为 `{forward, back}`；路由本体**不带**过渡配置 | 防止方向集合被悄悄扩成三值 | 抓不到 **forward 与 back 在真机上是否真的可分辨**（P6 的面）—— 这是**能力削减登记项**，不是门禁可判 |
| **G8** | **产物级接缝**：新增动效用到的每个类名，在**真实构建产物**中确实产出规则，且该规则里**每个 `var()` 都有定义** | 唯一接缝 = **真实构建产物**（复用既有产物断言助手：加载真实构建配置 → 走 Tailwind 自己的插件 → 从 AST 取声明），**不自造构建管线**。⚠️ 合成内容只能证明「配置登记了」，**证明不了「代码里写的那个类名真的有规则」** —— 必须用真实源码目录 | **这是最接近第三类失败的一条，但它仍不是渲染门禁**：它证明「变量有定义」，不证明「引擎在真机上按规范处理了它」。**引擎层容错实现与 CSS 规范不一致时，本门禁判绿、真机不渲染** ⇒ 由 P1–P7 兜 |

**既有门禁的判别力分工必须保持**（先例：状态层门禁的 C2「验判据有分离能力」与 C5「钉当前事实」**不可合并**）：
一条验「判据在坏令牌下恒绿」、一条验「当前事实没塌陷」，缺一条门禁要么空转要么失灵。

### 5.4 真机像素层（手动，不进 CI）—— 2 条自动门禁 + 7 个待取证探针

**共同要求（硬约束）**：每条探针**必须自带阳性对照**；采样**必须留截图**，
**单点数值只作辅助、截图才是判据**（既有教训：曾因取样点未落在按钮填色区而记下一条不可信的绝对像素并撤稿）。
**阴影是投影，不能采元素中心像素**（那是底色）—— 须在正下方偏移投影模糊量 + 扩散量的水平扫描线上取最小亮度。
**明暗两套色板各跑一次**；**一次采完不跨批次**（避免设备亮度与环境光差异混入）。
设备：`pictelio_ui`（API 34 / Lynx SDK 4.0.1）。

| # | 像素门禁 | 判据要点 | **已知失效面** |
| --- | --- | --- | --- |
| **PX1** | **按压态必须出现中间帧**：静止 / 按住 两态连采，**必须出现介于两者之间的取值** | 这是「0ms 闪」与「有响应」的唯一客观判据。必须自带阳性对照（同期任一已验证的入场动画） | 抓不到「有中间帧但幅度小到人眼不可辨」；抓不到**观感好坏**（那是人眼的事，不配门禁） |
| **PX2** | **方向必须可分辨**：连续走 forward → back 两步，逐帧比对**位移方向相反** | 若不可分，按 D8 降级为无方向纯淡入淡出并登记能力削减 | 抓不到**动画是否过长/过短**（时长合理性属观感，不判） |

**待真机取证清单（引用 ADR-0211，非本 spec 新增）**：**P1–P7** 全部处于**待取证**状态。

**自检结论与预算**：

- 8 条静态门禁全部挂在既有宿主（G1–G6 进 `md3GuardScans.test.ts` 的新规则、G7 与 G8 各自贴既有接缝），

  它的 30% 上限会小到无法容纳任何真实判据。**此时的正确做法是把扫描面扩到消费侧**（全部生产 `.vue` 的动效消费面），

- 像素层不计入本线（人工触发、无文件规模），但**采集脚本与探针工具本身必须有行为门禁**（既有先例：
  亮度探针有专门的行为门禁，因为本轮改的正是它的判据语义，而它此前只被当**文本**读过、从未被 spawn 过）。

## Out of Scope

**以下明确不做（防止范围蔓延）**：

| 不做 | 原因 |
| --- | --- |
| **MD3 Expressive** | **用户已拍板不纳入**。形态弹簧、形状 morph、跨页容器过渡全部不纳入 |
| **ripple 触感反馈** | 需要 haptics / 触觉通道，本期不引入；且属「反馈强度」而非「时间表达」 |
| **图标可变轴** | 需可变字体 + 引擎支持，未取证（ADR-0208 已定的图标结论不在本 spec 变更） |
| **`hover:` 态** | 纯触屏判定为「不适用」（ADR-0205 决策 4 第 4 条，**封闭清单**条目）；`hover-class` 属性本身**静默失效**（真机实证） |
| **弹簧物理动效** | Expressive 的前提；且 R3 降级规则下弹簧本身**不生成**动效，无法验证其行为 |
| **任何令牌值变更** | 6 档时长 / 4 条缓动 / 排版 / shape / 状态层**一律不动**。本 spec 只加消费层 |
| **状态层 role 范围扩大化** | 五档封闭（`primary` / `on-surface` / `error` / `surface` / `on-primary`），**不得新增第六档** |
| **阴影档的过渡化** | 无可用载体；改用状态层/透明度两条通道（承接 ADR-0212 决策 6） |
| **双页并存的真实反向转场** | 引擎无 `transitionend`、生命周期成本高；**作为能力削减显式登记** |
| **骨架屏阴影的降档** | 属 ADR-0212 决策 7，不在本 spec |
| **文本选中工具条 `rotate-45` 抓手** | 属 ADR-0210 决策 5 登记的**待真机取证项**；改前必须先取证，否则可能「修」一个正常的东西 |
| **a11y 语义绑定**（`accessibility-*`） | 需先做真机探针验证引擎是否消费（对标 ADR-0207 决策 5 先例），未拿到证据前不开实施票 |
| **偏好规则本身的改写** | 「减弱动效」三条降级规则是既有事实源，本 spec **只接入、不新增、不改写** |
| **E2E 进 CI** | 既有门禁边界（ADR-0084） |
| **观感类断言** | 「动效好不好看」「时长期不长期」是人的判断，**不试图给它配门禁** |

## Further Notes

### 落地顺序（**硬要求**）

**前置（全部实施的地基）**：**ADR-0210 的能力边界结论**。
它是 D2/D9 的判据来源（「`var()` 是否有定义」）。**未落地 ADR-0210 的能力矩阵，不得开工任何一条实施** ——
否则就是回到「照白名单猜、大概率猜错、且错得静默」。

**分批纪律的来源**：本改造与排版（ADR-0206）、缓动（ADR-0207）、色调层级（ADR-0212）
**叠在同一批 UI 上**。三者**必须分批落地、分批回归，否则无法归因是哪一个改善了观感**。
每批**独立**跑整站截图矩阵并留档，不合并批次结论。

**推荐批次与依赖**：

| 批次 | 内容 | 前置 | 门禁 |
| --- | --- | --- | --- |
| **0** | 真机取证 **P4 → P2 → P1**（地基三条） | ADR-0210 结论 | — |
| **1** | **按压反馈**（D3 + D10）：状态层过渡化 + 口径归正 | 批次 0 结论 | G1–G5 |
| **2** | **弹层入场与退场**（D5 + D6） | 批次 1 已落地并回归 | G6 + P3/P5 |
| **3** | **列表入场与错峰**（D7） | 批次 2 已落地并回归 | G1 覆盖 |
| **4** | **路由转场**（D8） | 批次 3 已落地并回归 | G7 + P6 |
| **5** | **剩余取证** P3 / P7 结论回填 + 失效面登记 | 全部批次已回归 | — |

**门禁必须先于它守护的批次就位**：批次 1 若无 G1–G5，改整过程**没有任何机器防线**，
只有「改完人工看一遍」—— 那正是本仓在消灭的假绿。同理，批次 2 的 `SheetShell` 与批次 4 的导航包装
**先落门禁（红），再落实现（绿）**。

### 已知风险

1. **退场多一段不可交互窗口**（`--durationFast` = 150ms，纯触屏下可接受；减弱动效时归零）。
2. **阴影档按压无过渡**（D4）—— 显式登记的失效面，颜色反馈不受影响。
3. **后退转场是能力削减**（D8）—— 只做滑入，不做真实反向。
4. **视觉回归面扩大**：弹层入场 + 路由转场 + 状态层过渡都会改截图基准 ⇒ 必须与既有 MD3 视觉回归**分批对齐**。
5. **门禁的三处结构性盲区**（既有登记、非本 spec 新增）：`.ts` 全文、`.vue` 的 `<script>` 块内拼接的类名、
   注释口径。这三处**任何门禁都挡不住**，只能靠 review 与 5.1 第 3 条的阳性对照纪律。
6. **真机未取证能力不得当「能用」写**（ADR-0210 决策 4 第 3 条）。P1–P7 未回填前，
   批次 2–4 的实施面**可能需要重估** —— 这是排期风险，不是质量风险。

### 写作过程中发现的待澄清项（ADR-0211 内部，需回写决策处）

1. **复核判据 1 引用的门禁文件当前不存在**。ADR-0211 把「`--shimmer-motion` 回退实参」这条例外的
   既成防线记在一个名为 `motionDurationTokens.template.test.ts` 的文件上，但 `packages/app-lynx/tests/`
   下**无此文件**（glob 与全文 grep 均无命中）。**本 spec 因此不依赖该引用**：
   G1 的例外登记改以**实际存在的宿主**为准（产物断言助手 + 形态规则宿主）。需确认该文件是被改名/合并，还是引用失悬。
2. **「66 处 / 34 文件」是两个口径的混写**。按 ADR-0211 自己定义的口径（CSS 变体）实跑为
   **66 处 / 33 文件**；「34」来自宽口径 `active:`，多出的那个文件是 `DownloadManager.vue`
   —— 它命中的 `active` 是 **TS 标识符**，正是 ADR-0211 脚注自己警告的那类污染。引用时应写 66/33。
3. **口径归正完成后，预计算实色档的令牌与构建键可能变成零消费，而 ADR-0211 未处置**。
   `on-primary` 档的预合成值取自 `--md-state-layer-pressed-on-primary`（与 `--md-state-pressed-*` **是两个不同的令牌族**），
   故 24 处归正后，`--md-state-pressed-*`（令牌表内 51 行声明）与其对应构建键**将无任何消费点**。
   既有产物门禁仍只断言「这些键仍能产出规则」（**登记**层面），故不会转红；
   但 ADR-0207 复核判据第 5 条自己立下的原则是「死令牌应删而非留着」。
   ⇒ **需明确裁定**：删令牌 / 保留为能力储备 / 改为断言零消费。**本 spec 不代为决定**。
4. **ADR-0211 与 ADR-0212 决策 6 的耦合会改动本 spec 的处数**。ADR-0212 决策 6 要给主 FAB
   从「按压用阴影」改成透明度状态层，**透明度档会从 7 处变成 8 处**。
   ⇒ G2 的判据**不能把处数写死**（应写成「每个透明度变化点都必须带 inline 载体」的**全覆盖**判据），
   否则批次 1 会被另一票的落地顺序搞红。**本 spec 的 D3 表按 ADR-0211 原文的 7 处登记**，
   实现时以全覆盖判据为准。
5. **P6 是 D8 的地基而非收尾**。若 forward/back 不可分辨，D8 降级为无方向淡入淡出 ——
   这**不是**「转场没做完」，而是**能力削减的登记项**。批次 4 的验收标准应按「方向可分辨」
   与「不可分辨时已按降级方案落地并登记」两种情况分别定义。
