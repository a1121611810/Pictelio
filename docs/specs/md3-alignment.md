# app-lynx 对齐 Material Design 3

## Problem Statement

`AGENTS.md` 声明 `pictelio-app-lynx` 使用 Material Design 3，但这句话没有可执行细则：
篇幅最大的「Fluent Design 规范」章服务的是已被删除的 WebView 客户端，
读者无法判断现在写代码该听哪套约束。以官方一手令牌为基准的对标调研查出 **19 条差距**
（2 阻断 / 6 高 / 8 中 / 3 低）。

差距的分布**极不均匀**，这决定了本 spec 的形态：

- **已经对的地方不要动。** 色彩（38 组对比度抽查 36 组达标，唯一未达 3:1 的
  `outline-variant` 在 M3 里本就是装饰性分隔线角色）、shape scale 数值、底部导航
  （80dp 高 + 64×32dp 指示器胶囊）、暗色 tonal 板（`SchemeTonalSpot` 生成而非明暗反相）
  **都合规**。把它们当缺陷去"修"是引入回归。
- **真正不贴合的是两处系统性缺口。**
  ① MD3 type scale 是 15 档 × **四元组**（size / line-height / tracking / weight），
     而项目**只落地了 size**，行高与字距全丢——行高落到各组件自选（27 处），
     于是同一个 `text-body-medium` 在不同页面行高不同，排版节奏整个塌掉。
  ② 状态层官方四态是 hover 0.08 / focus 0.12 / pressed 0.12 / dragged 0.16，
     而项目**只做了 pressed**，hover 与 focus-visible 全仓 0 覆盖。

还有一类问题不体现为视觉差距，而体现为**没有防线**：shape scale 令牌值是对的，
但没注册进 `borderRadius`，所以 `rounded-*` 走 Tailwind 默认的 rem 值
（`rounded-md`=6px、`rounded-3xl`=24px 越界，28px 无法表达）。
存量代码靠 `rounded-[var(--md-shape-*)]` 274 处恰好绕过了这个坑，
但**写错 token 名会静默失效**——`rounded-[var(--md-shap-medium)]` 少个字母，
渲染出一个没圆角的元素，不报错不警告。

## Solution

把 MD3 从「文档里的一句话」变成「有令牌、有护栏、有门禁」的可执行基线：

1. **数值基线锚定到可逐字核对的来源**——material-web v0.192 生成令牌源文件。
   `m3.material.io` 是 JS 渲染抓不到正文，只能作图示参考。
2. **补齐两处系统性缺口**：type scale 四元组落地、状态层四态补齐。
3. **把「碰巧正确」变成「写错即失败」**：形状档位注册进构建配置，
   使 token 名错误在构建期暴露；新增门禁覆盖现有门禁扫不到的形态。
4. **图标换 Material Symbols**，同时消除「跨设备不一致 / 不可访问 / 不可验证」三条缺陷。
5. **合规判定必须三层证据**：静态审计 + 真机截图目视 + e2e 机器断言。
   Lynx 的 CSS 是子集，**代码里有声明 ≠ 真机生效**，单靠静态审计会系统性产生假绿。

## User Stories

### 排版（差距 #1，🔴 阻断）

1. As a 读者, I want 同一档字号的文字在任何页面行高一致, so that 长文阅读时不会因页面而异。
2. As a 读者, I want 标题与正文的行高比例符合 MD3 type scale, so that 层次感由排版节奏建立而非只靠字号。
3. As a 读者, I want 大标题（display 档）有独立的字号档位可用, so that 页面级标题不必用最大的 headline 硬撑。
4. As a 开发者, I want 字号档位同时携带行高与字距, so that 我写 `text-body-medium` 就得到正确的排版, 不需要再手写 `leading-*`。
5. As a 开发者, I want 旧字号别名也带上四元组, so that 存量代码即使不改类名也能获得正确行高。
6. As a 开发者, I want 自选行高在正文类内容上被禁止、装饰性场景可带注释豁免, so that 「有人又随手写了 `leading-[1.4]`」会被自动发现。
7. As a 读者, I want 字重符合 MD3 分档（label 与 title-small/medium 为 medium，其余 regular）, so that 标题不会因误用 `font-bold` 而偏离规范。

### 色彩与主题（差距 #2，🔴 阻断 · 决策为「有意不做」）

8. As a 维护者, I want 7 套静态色板 × 明暗共 14 个色板类的色角色齐备且取值合法, so that 换主题不会缺色。
9. As a 维护者, I want 「不做动态色 / 壁纸取色」这一决策在代码或文档留痕, so that 以后每次 review 不会重新把它当 bug 提出来。
10. As a 读者, I want 亮暗两套色板都满足 WCAG 对比度要求, so that 深色模式下也读得清。
11. As a 读者, I want 暗色是独立的 tonal palette 而非明暗反相, so that 深色模式不发灰、层级仍清晰。

### 状态与交互（差距 #3 / #4，🟠 高）

12. As a 使用键盘或辅助技术的用户, I want 焦点可见, so that 我知道当前焦点在哪。
13. As a 读者, I want 按下元素时有明确的视觉反馈, so that 我知道点中了。
14. As a 开发者, I want hover / focus / pressed / dragged 四态都有 alpha 状态层令牌, so that 状态反馈有统一来源而不是每处自己调颜色。
15. As a 开发者, I want 状态层用官方 alpha 叠加而非人工预计算的实色, so that 叠加在不同底色上都正确。
16. As a 开发者, I want 预计算实色的「视觉近似」性质在注释中写明, so that 没人把它当成精确合成去依赖。

### 动效（差距 #13 / #14，🟡 中）

17. As a 读者, I want 全站默认缓动是 MD3 emphasized 而非 MD2 遗留曲线, so that 位移动效的收尾手感符合规范。
18. As a 读者, I want 卡片按压回弹用 MD3 曲线, so that 弹性动画不突兀。
19. As a 维护者, I want 动画时长一律走令牌而非散落的硬编码毫秒数, so that 时长档位集中可调。
20. As a 对动效敏感的前庭障碍用户, I want 应用尊重「减弱动效」偏好, so that 我不会因动画产生不适。

### 形状（差距 #19，🟡 中）

21. As a 开发者, I want 形状档位（4/8/12/16/28/9999）作为 Tailwind 档位可用, so that 我不必记住 vw 换算值。
22. As a 维护者, I want 写错形状 token 名时构建期就报错, so that 不会静默渲染出无圆角的元素。
23. As a 维护者, I want 圆角不再出现指向 rem 或字面量的消费, so that 圆角始终落在 MD3 shape scale 上。
24. As a 读者, I want 所有表面的圆角都在规范档位内, so that 圆角语言统一。

### 层级（差距 #7，🟠 高）

25. As a 读者, I want 卡片、弹层、菜单的层级通过表面色调区分, so that 层次关系一眼可辨。
26. As a 开发者, I want elevation 五档齐备, so that 需要更明确的层级表达时有档位可用。

### 触控目标（差距 #6，🟠 高 · 部分判定为有意偏离）

27. As a 读者, I want 所有可点区域达到 WCAG 2.2 AA 的 24×24 CSS px 下限, so that 不会误触。
28. As a 读者, I want 主要导航目标达到 48dp 建议值, so that 单手操作时点得准。
29. As a 维护者, I want 「二级 tab 保持 48px、搜索框保持药丸形态」作为有意偏离被记录, so that 不会被反复当成不一致。

### 图标（差距 #5，🟠 高）

30. As a 读者, I want 图标在不同厂商 ROM 上长得一样, so that 界面观感一致。
31. As a 读屏用户, I want 图标位置有正确的无障碍名称, so that 屏幕阅读软件念出「首页」而不是「房屋符号」。
32. As a 维护者, I want 图标名集中在一张映射表里, so that 图标位可审计。
33. As a 维护者, I want 映射表与字体子集一一对应, so that 不会出现「映射有、字体没有」导致的空白图标。
34. As a 开发者, I want 手绘描边图标被规范图标替代, so that 少一处难以维护的手写图形。

### 可访问性（差距 #15）

35. As a 读者, I want 禁用的元素不响应点击, so that 我不会反复点一个没反应的东西。
36. As a 开发者, I want 现有无障碍标注不被回退, so that 整改设计不会顺带弄丢语义。

### 门禁与文档（差距 #9 / #12 / #16 / #17 / #18）

37. As a 维护者, I want 新增 MD3 数值时能逐字核到官方令牌, so that 不用依赖记忆或二手转述。
38. As a 维护者, I want 文档里只有一套现行设计约束, so that 读文档的人不用猜该听哪套。
39. As a 维护者, I want 新代码不使用旧 Fluent 语义名, so that 旧体系不会继续扩散。
40. As a 维护者, I want 整改完成后有截图留档, so that 后续 review 能对比是否回退。
41. As a 维护者, I want 每条差距的关闭都附带证据, so that 不会有一纸空文的「已对齐 MD3」。

## Implementation Decisions

1. **数值基线**：一切 MD3 数值以 material-web `tokens/versions/v0_192/` 下的生成令牌源文件
   为唯一基准。冲突时以令牌文件为准，不以记忆或二手转述为准。
   换算关系固定：375 设计稿下 **1sp = 2rpx**、**1dp = 0.2667vw**。

2. **排版档位采用 Tailwind 数组形式**承载四元组：

   ```ts
   // 形态示意：size + lineHeight + letterSpacing，weight 另由 fontWeight 档位承载
   'body-large': ['32rpx', { lineHeight: '48rpx', letterSpacing: '1rpx' }]
   ```

   **档位名不变**，故存量 75 个 `.vue` 的字号类无需修改即可获得正确行高。
   15 档全部补齐（含缺失的 display-small/medium/large）。
   `weight` 不进 `fontSize`（Tailwind 数组形式的第三元素不合法），改由
   `fontWeight: { regular, medium }` 档位承载。

3. **自选行高逐处判定**：27 处自选行高（不含 45 处 `leading-none` 的刻意收紧排版）
   中，多数删除以让档位接管；装饰性场景保留并**必须带注释说明理由**。
   判据：正文类内容（body-\* / label-\*）不得有自选行高。

4. **形状档位注册进构建配置**：`borderRadius` 的 6 档全部指向形状令牌。
   **意图不是减少 arbitrary 写法，而是让写错能失败。**
   存量 274 处 `rounded-[var(--md-shape-*)]` **不强制迁移**（当前正确，迁移属范围蔓延）；
   要清的是 14 处未接 token 的方向类与 2 处硬编码字面量圆角。

5. **形状随屏宽缩放是有意取舍**：形状令牌用 vw 而非固定 px，与项目既有
   「spacing/fontSize 随屏宽缩放」一致，比例关系不变、视觉层次一致。
   记为取舍而非缺陷，避免将来被反复当 bug 提。

6. **状态层以 alpha 叠加层为正路**：补齐 hover(0.08) / focus(0.12) / dragged(0.16)
   三态令牌 × 现有 4 个语义色，并在 Tailwind 颜色档位同步登记。
   预计算实色降级为「Lynx 不支持某伪类时的兜底」，其「视觉近似」性质必须在注释中保留。

7. **全站默认缓动改为 M3 emphasized**：Tailwind `transition-*` 的默认 timing function
   来自预设、是 MD2 遗留的 `cubic-bezier(0.4,0,0.2,1)`，需改接项目令牌。
   注意 `standard` 与 `emphasized` 在 v0.192 同为 `(0.2,0,0,1)`，
   本决策**不改变** standard 的既有取值（它本就正确），改的是实际生效的全站默认值。

8. **elevation 以表面色调为主表达**：五档齐备，并规定层级优先用
   `surface-container-low…highest` 色调、box-shadow 为辅——纯阴影叠加是 MD2 的做法。
   引擎约束：Lynx 对多层 `box-shadow` 支持度未知；若不生效，
   层级完全由表面色调承担，「辅」自然失效，不影响「主」。

9. **图标方案 = 子集字体 + 名称↔码点映射表**：Material Symbols **Outlined** 变体
   （与项目现有 2px 描边图标的密度接近，替换后视觉跳变最小）。
   字体子集在**构建期外离线生成，产物（字体文件 + 映射表）提交进仓库**——
   构建期联网取字体会让干净 clone 无法复现。
   映射表同时是三件事的源：子集生成输入、运行时查码点依据、**门禁的 oracle**。

10. **统一图标组件，不允许在模板里直接写字形**：所有图标位必须经统一组件。
    理由不只是封装——直接写字形等于把「用哪个图标」的决定权散落到 75 个文件，
    无法集中审计。组件是让门禁可判的前提。

11. **图标与无障碍名称并存，不互相替代**：unicode 字形时代无障碍名称是唯一语义来源，
    所以「有 label 就行」；换成规范图标集后若顺手删 label，
    会让「图标形状可读」退化成唯一线索，对读屏用户是净损失。

12. **图标接入的回退方案必须保留门禁**：Lynx 对 `@font-face` 与自定义字体的支持度
    未知。若不支持，回退是保留 unicode 字形但**照样落地映射表与门禁**
    （消除「不可验证」这条缺陷），放弃「不一致 / 不可访问」的改善。
    **门禁不可与字体一起放弃。**

13. **执行分三批，顺序硬约束**：
    - 第一批：零风险单文件改动（display 档位、形状档位注册、字重、时长令牌化、
      越界曲线、错误原型归档、文档补章）。可独立提交。
    - 第二批：排版四元组、状态层四态、focus-visible、图标。
    - 第三批：elevation、触控目标、输入框形态。
    **排版四元组与全站默认缓动必须分批落地、分批回归**——两者都改全站观感
    （前者改行高、后者改所有过渡的缓动形状），同批落地将无法归因是哪一个引起的。

14. **有意偏离清单是封闭的**：动态色不做、搜索框保持 42px 药丸、
    二级 tab 保持 48px、hover 在纯触屏判定为不适用。
    这 4 条必须**在代码或文档留痕**（不只存在于 ADR），
    否则下一个 reader 会在 review 时重新提出。
    不在清单内的差距，默认按「要修」处理。

## Testing Decisions

**什么样的测试算好**：只测外部可观察行为，断言指向**独立来源**（官方令牌 / 真实像素），
不自证。抽取器必须断言「集合非空 + 有数量下界」，否则正则失效会让全称断言静默恒真。
每条新门禁都要有**反事实**——把违规形态塞回去看它是否转红；改动前就已绿的断言不是防线。

### 接缝 A：Tailwind 构建产物契约（新增，主防线之一）

在 Vitest 里加载**真实**构建配置并生成 CSS，断言产物。

选它的理由：现有对配置的契约是**文本正则解析**，而该测试文件自己写着
「重构时若调整键序/缩进需同步此解析，否则会静默误测」。本轮要改的正是被解析的那一段，
文本接缝会与被测改动同生共死。构建产物接缝对配置格式变动免疫。

覆盖：15 档四元组齐备且取值等于官方换算值、形状档位 6 档全部指向形状令牌
（任一档指向字面量即判红）、全站默认缓动等于 M3 emphasized、状态层颜色可解析。

### 接缝 B：令牌取值契约（扩展现有引用完整性测试）

现有测试已守「`var(--md-*)` 必须在令牌文件中有定义」并自带「抽取器自身有效」用例。
扩展为取值契约：形状 6 档、动效 4 曲线 + 时长档位、状态层四态 opacity
（**要逐一核对数值，不能只判「有没有这个令牌」**）、7 主题 × 明暗色角色齐备、
以及按 WCAG 公式计算的对比度。

### 接缝 C：门禁扫描（新增，仿现有迁移门禁惯例）

禁：指向数字或 rem 的圆角消费、MD2 遗留缓动值、正文类内容上的自选行高、
状态层改用预计算实色。

**关键要求**：判据要能抓住「换了写法但没接令牌」的形态——
例如方向类圆角写成看似走档位、实则拿到预设默认 rem 的形式。
只认一种语法形态的门禁是 fail-open。

### 接缝 D：e2e 机器断言（新增，仅 A 类）

**必须知道的引擎约束**：Lynx 4.0.1 **不暴露无障碍树节点**（199 处标注了可访问性元素
也不出节点），因此**拿不到元素边界框**；`getCSSValue` 对非 DOM 的 Lynx 也无效。
⇒ 触控目标、圆角、对比度、状态层 alpha **无法**用结构化查询断言，只能靠像素测量，
而这些 B 类度量在本仓**从未实测过**，容差无依据。

故 e2e 只做 3~4 项 A 类断言：表面色值真的渲染到屏上（断言**具体 RGB 邻域**，
不能只判亮/暗）、明暗切换、主题切换、主 CTA 可见包围盒。
每项配一个「注入失败态必红」的负向对照防假绿。不挂发布门 tag，不进 CI。
复用现有模拟器编排基建，**不新建/删除 AVD**。

### 接缝 E：真机截图目视（人工）

观感类问题的唯一判据：排版节奏、elevation 观感、图标观感、整体贴合度。
机器断言**不假装能判这些**。截图需避开已知污染（调试 HUD 的 FPS 条与触摸十字、
详情页图片加载失败区）。

### 回归风险提示

排版四元组会改**全站 75 个文件**的行高，缓动变更会改**全站过渡的收尾手感**。
容器高度、flex 布局、居中态都可能位移。**这是本轮最大的回归面**，
必须整站截图回归，且两批变更分开落地以保归因。

## Out of Scope

- **动态色 / 壁纸取色**——有意不做（决策 14），如将来要重开须新开 ADR
- **Android 12+ 系统级动态色集成**——同上
- **内置 Roboto 字体**——本项目只构建 Android，系统字体即 Roboto，MD3 字体要求默认满足
- **MD3 Expressive spring 动效**——Lynx transition 支持不足，属引擎受限
- **`backdrop-filter` 毛玻璃**——Lynx 支持度未知，玻璃卡片已用纯色替代
- **旧 Fluent 兼容别名的存量清理**——只加门禁禁止新增，不做全量替换（风险高收益低）
- **旧字号别名的下线路径**——本次只做四元组补齐与注释标注留痕，不改类名
- **纯触屏场景的 hover 态实现**——判定为不适用（令牌仍补齐，为将来外接输入设备留位）
- **`m3.material.io` 的可抓取化**——JS 渲染站点不做工程改造，改用令牌源文件
- **WebView 客户端的任何改动**——已随 ADR-0203 整包删除

## Further Notes

- **本 spec 的事实底座是差距分析，不是记忆。** 该报告的 §8 记录了复核过程中
  纠正的 6 处问题（含 1 处把官方 `easing-standard` 取反的事实错误、
  2 处计数错误）。读结论前建议先读 §8。
- **一处已知的「看起来是缺陷、实际不是」**：本项目无字体声明不是缺口——
  Android 系统字体就是 Roboto，MD3 字体要求默认满足（brand 变体拿不到）。
- **一处刻意不动的东西**：形状令牌用 vw 而非固定 dp。MD3 的 shape scale 是固定 dp，
  但本项目 spacing/fontSize 都随屏宽缩放，形状跟随保持一致，比例关系不变。
- **未真机验证的部分**：Lynx 对 `:hover` / `:focus-visible` / 多层 `box-shadow` /
  `animation` / `@font-face` 的支持度。focus-visible 与图标接入的修法可行性
  直接取决于此，需在第二批开工前先验证。
- **E2E 前置**：模拟器当前无在线设备，跑测前需先启动；视觉类 spec 建议不做登录
  （避免引入凭据与网络代理两个阻塞）。
