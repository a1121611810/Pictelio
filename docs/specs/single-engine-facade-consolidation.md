# 规格：webview 下线后的三门面收口

> 配套决策：[ADR-0201](../../adr/ADR-0201-single-engine-facade-consolidation.md) ·
> 术语来源：[glossary-single-engine-facade](../../adr/glossary-single-engine-facade.md) ·
> 父执行票：[#805](https://github.com/a1121611810/Pictelio/issues/805)（已订正过期事实）·
> 范围外：[#819](https://github.com/a1121611810/Pictelio/issues/819) 第 4 项（WebView 源码清理）

## Problem Statement

v6.3.0 起 Pictelio 已是 Lynx 单引擎产品，落地页更新日志也已对外宣布「WebView 引擎已下线」。
但叙述项目形态的三处门面仍停在双引擎时代，且**三处各说各话**：

- 落地页把「双引擎，随心切换」当作架构差异化卖点摆在 Hero 之后，首屏即推一个已不存在的功能
- README 标题写 dual-engine、技术栈挂 Capacitor 徽章、脚本表列出已不存在的 `pnpm cap:*` 命令
- AGENTS.md 指示 agent「自定义 Capacitor 插件在 `MainActivity.java` 经 `registerPlugin()` 注册」——
  该类与该机制**均已不存在**，这会让下一个 agent 去改一个不存在的文件

对外部用户，这是一张与实际产品不符的宣传页；对 agent，这是一条指向幽灵类的错误指令。
两者的共同根因是「webview 下线了」这句话有歧义——它可以指运行时、可以指源码、可以指依赖，
而三处门面各自按不同理解落笔，于是必然分叉，且每次修补都会再次分叉。

## Solution

让三处门面叙述同一件事：**运行时只有 Lynx 一个形态；WebView 源码仍在库但不参与构建与运行；
Capacitor 依赖仍在声明中但只被留存源码引用。** 三者共用一份措辞锚点，逐字复用，不再各写各的。

对历史文档采取「加存档横幅、正文不改」的处置：既消除误导，又不抹掉决策史。
产品代码本次一行不动，源码清理维持 #819 第 4 项挂账。

## User Stories

1. 作为访问落地页的潜在用户，我希望看到的架构描述与我下载到的 App 一致，以便我不因「两个渲染内核可切换」这种我无法操作的承诺而误判产品能力。
2. 作为访问落地页的潜在用户，我希望首屏之后直接看到我关心的功能（浏览、详情、小说、翻译），以便我不必先读一段已经过时的架构宣传。
3. 作为访问落地页的潜在用户，我希望截图里出现的每个界面都真实存在，以便我不点进一个已下线的「引擎切换」页。
4. 作为访问落地页的潜在用户，我希望页面在桌面宽屏与手机窄屏下都排版正常，以便我在不同设备上看到一致的内容。
5. 作为从搜索引擎进入落地页的外部用户，我希望页面能正常构建并部署，以便我看到的不是半坏的页面。
6. 作为准备 clone 仓库的贡献者，我希望 README 告诉我这是一个单引擎的 Lynx 客户端，以便我对项目形态有正确预期。
7. 作为准备 clone 仓库的贡献者，我希望 README 的特性列表描述我实际能用的功能，以便我不去找一个已被移除的引擎切换开关。
8. 作为准备 clone 仓库的贡献者，我希望 README 不展示 Capacitor 徽章，以便我不误以为项目依赖 Capacitor 构建链。
9. 作为准备 clone 仓库的贡献者，我希望 README 的项目结构与真实仓库一致，以便我知道有哪些包、各自负责什么。
10. 作为准备 clone 仓库的贡献者，我希望 README 的命令表里每一条命令都真实存在，以便我复制粘贴就能跑通，而不是得到「command not found」。
11. 作为准备 clone 仓库的贡献者，我希望本地开发的启动命令被保留但标注清楚它的服务对象，以便我仍能起开发环境，同时不误以为它是给已下线客户端用的。
12. 作为阅读构建文档的贡献者，我希望 README 不再要求我准备一个 WebView 版本门槛，以便我不去满足一个已经不需要的条件。
13. 作为阅读项目说明的外部审阅者，我希望技术栈里出现的每个技术都还真实在用，以便我的评估基于事实。
14. 作为驱动本仓库的 agent，我希望 AGENTS.md 告诉我唯一入口是 Lynx 侧，以便我不去找已被删除的 `MainActivity.java`。
15. 作为驱动本仓库的 agent，我希望 AGENTS.md 里的原生侧约束指向真实存在的类与方法，以便我照着改能改对。
16. 作为驱动本仓库的 agent，我希望 AGENTS.md 明确说明 Capacitor 依赖为何仍在声明中，以便我不把它当成「忘记清理」而擅自删掉——那会击穿一条以 package.json 为 oracle 的漂移防线。
17. 作为驱动本仓库的 agent，我希望 AGENTS.md 的包清单与真实仓库一致，以便我不去找不存在的包、或漏掉真正存在的包。
18. 作为驱动本仓库的 agent，我希望我接手时 AGENTS.md 仍在体积门禁内，以便我的改动不会让 CI 红。
19. 作为维护者，我希望历史 ADR 与研究文档被标注为历史而不是被改写，以便未来的读者能看到当时的判断依据。
20. 作为维护者，我希望已过期的执行票事实被订正，以便后来者不会依据错误的前提重复劳动。
21. 作为维护者，我希望历史文档里那些已被验证为过时的描述被订正，以便执行票反映真实状态。
22. 作为维护者，我希望我不需要动产品代码就能完成这次收口，以便 WebView 源码清理的边界保持在它自己的票里。
23. 作为维护者，我希望三处门面共用一份措辞来源，以便下次改动时我能一眼看出哪里又分叉了。
24. 作为维护者，我希望 CI 的架构文档由定时任务重生成，而不是我手工维护，以便我不违反「openwiki 禁止手改」的规则。
25. 作为维护者，我希望这次收口有测试钉住关键事实，以便未来某次重构不会让幽灵类名重新溜回 agent 指令里。

## Implementation Decisions

- **三态并存是本次收口的核心建模。** 「webview 下线」拆成三个独立断言：运行时下线（有判据表支撑）、源码留存（无 Activity 承载）、依赖留存（5 个 npm 依赖仍在声明中，因留存源码仍 import）。任何只写其中一态的表述都不完整。
- **措辞锚点逐字复用。** 引擎形态的叙述在三个门面间必须逐字一致，不允许同义改写。锚点句写在术语文档里，三个门面都从那里取。
- **落地页整块删除而非改写。** 「双引擎」区块的存在前提（可切换的第二引擎）已消失；改写成单引擎价值主张需要臆造未经拍板的对外定位，删除是诚实且可逆的选择。
- **截图删除必须两侧联动。** 「引擎切换」截图同时被落地页与 README 引用，两侧引用都摘掉才能删文件——单删一侧会留下坏图引用。
- **AGENTS.md 的两条契约锚点：一条改写、一条加限定语。** 表面类名约束是「改写」而非删除——真实约束依然存在，只是机制从 Capacitor 插件注册变成了 AndroidX 启动屏安装；技术栈里的 Capacitor 字样是「加限定语」而非删除——依赖确实还在，删词会击穿以 package.json 为 oracle 的漂移防线。
- **历史文档只加横幅。** 覆盖 ADR、研究报告、规格、以及双引擎期的术语文档。正文一字不改。
- **父执行票订正而非另开平行票。** 门面工作挂入既有执行票，避免两票并行描述同一片区域。
- **openwiki 交给 CI。** 过期内容由定时任务重生成，本次不碰。

## Testing Decisions

**什么算好测试**：只断言外部可观察事实（某个文件里是否出现某句话、某条命令是否存在），
不断言改写过程的中间态。

**唯一的机器防线是 AGENTS.md 契约测试**，它已经存在并且是本次唯一能自动拦住「幽灵表述回流」的接缝。
但它当前**编码的是过时的世界**——它断言文档保留 Capacitor 插件注册的表述，
却没有断言该表述已消失。所以防线需要**双向加固**：

- 保留既有正向锚点（体积门禁、路由表表头、Fluent 规范、CDN 禁令）
- 保留「super.onCreate 之前」锚点——但它现在守护的是启动屏约束，不再是插件注册
- **新增负向断言**：AGENTS.md 不得再出现被删除的类名、不得再出现「双引擎」形态的表述
- **新增正向断言**：AGENTS.md 必须指向唯一入口的 Lynx 侧类

**反事实检验（项目硬约束）**：每条新防线必须把劣化塞回去确认转红。不转红即为摆设。
本次至少验证：把「改写」退回「删除」应转红，把「限定语」退回「裸写 Capacitor 8.5」应转红，
把负向断言的目标串塞回文档应转红。

**其余三个门面无自动测试接缝**（落地页无 test 脚本、README 无契约测试、docs 横幅为纯文本）。
这是既有现实，不在本次新建测试基建；改用可执行的验收动作：

- 落地页：构建通过 + 玻璃表面验证脚本 + 桌面/移动双宽度目视（该脚本是手动的，不进 CI）
- README：命令表逐条与根 package.json 实测比对
- docs 横幅：抽查若干份确认横幅存在且正文首段未变

**先例**：AGENTS.md 契约测试是该仓已有的「文档即代码」防线模式，本次沿用并扩展。

## Out of Scope

- **`packages/app/src/**` 的 WebView 源码清理**（约 291 源文件 + 约 170 单测）——维持 #819 第 4 项挂账
- **Capacitor npm 依赖的移除**——派生自源码留存，属 #819-4；本次只加限定语说明其状态
- **APK 内 WebView 死重资产**（`assets/public/*` 与 capacitor 配置残件）——属 #819-4
- **发布脚本中的 web-only 发布模式**——与本主题同源但独立，另票（已由 [ADR-0202](../adr/ADR-0202-ota-web-bundle-channel-retirement.md) 落地下线）
- **验收工作流中已失效的偏好文件路径**——同源但独立，另票
- **历史 ADR / 研究报告 / 规格的正文改写**——只加横幅
- **openwiki 目录的任何改动**——生成物，CI 定时重生成
- **产品代码、UI、构建链的任何改动**——本次为 0 行
