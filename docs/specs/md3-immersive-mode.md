# 沉浸式看图 spec（详情页全屏看图 + 点图隐藏全部界面元素）

> **决策依据**：`docs/adr/ADR-0213-immersive-media-view.md`（accepted，2026-10-01）——本 spec 的**全部**决策依据，
> 9 条决策与 P1–P7 探针清单均以该 ADR 为准绳。
> **本文不新增决策**，只做三件事：把决策翻译成用户可感知的收益与验收、登记门禁与其**已知失效面**、
> 把阻塞级前置门写成不可放行的条件。
> **用户已拍板**：应用内沉浸**与**原生系统栏隐藏**都做**。

## Problem Statement

用户点开一张插画想认真看图，屏幕上却有三层界面压在这张图上面：

1. **顶栏**（含返回键与标题）；
2. **图片下方那条操作/信息行**（作者头像、关注、收藏、评论、下载、标签）；
3. 多图作品右上角的**「第 n / N 张」页角标**。

三层都在图所在的滚动区域内或紧贴其上下，图本身被压成中间一条。想放大看时无处可去——图已经是满幅宽了，
放大不了；把界面撤掉，**这个状态不存在**。用户的体验是「我想看画，屏幕上大半是控件」。

已有的「全屏模式」开关只解决其中一层，而且不是最重的那层：它管的是**系统栏**（状态栏 / 导航栏），
管不到应用自己画的顶栏、操作行与页角标。而**没有「沉浸」这个状态**本身才是缺口——系统栏藏了，
顶栏和操作行照样压着图。

由此产生第二个问题：**界面撤掉之后怎么回来**。如果恢复路径不可靠，撤掉界面就从「清爽」变成「失控」——
用户面对一个没有按钮的界面，既不知道怎么退出，也不知道刚才发生了什么。这个风险决定了本轮的所有取舍
（不做自动隐藏超时、恢复入口押在单击上、必须先取证系统返回在隐藏态下是否仍然可用）。

## Solution

**单击插画 = 进入 / 退出「沉浸看图」**。这是唯一的新交互，其余全部是既有能力的接线。

进入沉浸后用户看到的：

- 顶栏、操作/信息行、「第 n / N 张」页角标**全部消失**，屏幕上只剩画；
- **系统状态栏与导航栏同时隐藏**，根安全区随之归零 ⇒ 图上下**贴到屏幕最上 / 最下像素**
  （已验证基础设施可用；「真的贴到像素」属待真机取证 P7）；
- 图片**不隐藏、不缩放、不裁切**——藏的是界面，不是画。

退出沉浸后用户看到的：

- 再单击图片，或系统返回（手势 / 按键）——两条都恢复；
- 界面**逐项回到进入前的位置**（顶栏、作者行、收藏、评论、下载、标签、角标）；
- **系统栏回到用户自己「全屏模式」开关的当前设定**，而不是一律显示出来。
  原本开了全屏模式的用户退出沉浸后，系统栏仍然是隐藏的。

用户看不到、但必须成立的四件事：

- **不会突然变**：没有自动隐藏超时，界面只在用户自己点的那一下变化；
- **不会弄丢东西**：沉浸不写「全屏模式」的持久开关——昨晚点过一张图，今早打开应用不会被扔进沉浸；
- **不会卡死**：从沉浸态返回、切页签、退出应用后，系统栏一定回到应有状态，不残留无栏界面；
- **不会挡住别人的手势**：关注、收藏、评论、下载、标签跳转这些既有入口一个都不动、一个都不被吞。

已知的诚实边界：顶栏**不在图上**（它是滚动容器的兄弟节点），所以「藏起顶栏」换来的不是「图变大一倍」，
而是**图片可用高度增加一个顶栏高度加上两条系统栏带**。用户能拿到的真实收益是**图边到边、屏幕上没有控件压着**，
以及**看图时不再被界面打断**。本轮不承诺把图放大到全屏。

## User Stories

**进入与退出**

1. As a 正在看图的浏览者, I want 轻点一下插画就把所有界面收起来, so that 屏幕上只剩画本身。
2. As a 正在看图的浏览者, I want 再点一下画面就恢复原来的界面, so that 我随时能回到操作界面而不必猜怎么回去。
3. As a 正在看图的浏览者, I want 界面只在我点的那一下变化、不要自己突然消失, so that 我始终知道当前能看到什么、也总有入口回来。
4. As a 正在看图的浏览者, I want 恢复后的界面与进入前一模一样（顶栏位置、操作项顺序、角标）, so that 我不需要重新找一遍刚才的入口。
5. As a 画全屏看图的浏览者, I want 沉浸时画的上边和下边贴到屏幕边缘, so that 屏幕上的每一行像素都是这张画。

**返回与系统栏**

6. As a 沉浸态的浏览者, I want 从屏幕边缘往回划（系统返回手势）能退出沉浸, so that 即使界面全没了我也有路可回。
7. As a 沉浸态的浏览者, I want 退出后系统栏回到我自己的「全屏模式」设定, so that 我不用为了看图去改一个全局偏好。
8. As a 已开启「全屏模式」的用户, I want 进入沉浸只是把应用内界面收起来、退出后系统栏依旧隐藏, so that 我的全局设定不会被看一次图改掉。
9. As a 未开启「全屏模式」的用户, I want 退出沉浸后状态栏和导航栏都回到可见, so that 图看完之后界面回到我平时的样子。
10. As a 任意用户, I want 「全屏模式」这个开关的显示与实际状态永远一致, so that 我在设置页看到的开关是可信的。
11. As a 任意用户, I want 沉浸不留下任何持久痕迹（杀掉应用重开是正常界面）, so that 我不会莫名其妙地再次被扔进沉浸模式。
12. As a 从最近任务切回的用户, I want 切回来后系统栏状态是正确的, so that 我不会停在一个残缺的无栏界面上。

**多图作品（「第 n / N 张」角标）**

13. As a 看多图作品的浏览者, I want 沉浸时右上角的「第 n / N 张」角标也一起消失, so that 画面上不留任何多余元素。
14. As a 看多图作品的浏览者, I want 隐藏角标后仍能从图片的无障碍标签里听到「第 n / N 张」, so that 屏幕阅读器用户不会丢失「第几张」这个信息。
15. As a 看多图作品的浏览者, I want 退出沉浸后角标回到原来的位置和内容, so that 多图信息只是被暂时收起而不是被删掉。
16. As a 看多图作品的浏览者, I want 点角标本身不会误触发「进入/退出沉浸」, so that 我想读角标时画面不会跟着闪一下。

**既有手势不能被吞**

17. As a 会关注作者的用户, I want 点作者头像进主页、点关注按钮都能正常工作, so that 看图和追作者可以连着做。
18. As a 会收藏的用户, I want 收藏/取消收藏、稍后再看这两个入口在改版后行为完全一致, so that 我的收藏不会因为这次改版出问题。
19. As a 会读评论的用户, I want 评论入口照常打开, so that 我能随时看作者和读者的讨论。
20. As a 会下载的用户, I want 下载入口照常走原有保存流程, so that 看中的图能照旧存下来。
21. As a 追标签找图的浏览者, I want 点标签跳搜索照常可用, so that 找同类图的路没被堵住。
22. As a 依赖既有手势的浏览者, I want 以上入口在沉浸退出后立刻可用, so that 我不需要先退出沉浸才能做这些事。
23. As a 依赖既有手势的浏览者, I want 这次改动不去改任何一个已有按钮的处理逻辑, so that 改版只增加沉浸、不改变别的语义。

**浮层（评论 / 选页 / 收藏面板）**

24. As a 沉浸态的浏览者, I want 打开评论、选页或收藏面板前先自动退出沉浸, so that 弹层不会变成一个「没有关闭按钮的模态」。
25. As a 关闭弹层后的浏览者, I want 能正常地再次点图进入沉浸, so that 弹层用完不影响继续沉浸看图。

**页面间与返回栈**

26. As a 从详情页跳到别处的浏览者, I want 走一圈回来时页面是干净的, so that 残留的沉浸状态不会让别人替我决定界面。
27. As a 边看图边切页签的用户, I want 切走再切回来时沉浸状态已干净复位, so that 无栏界面不会跟着我跑到别的页签去。
28. As a 设备内存紧张被系统回收应用的用户, I want 重新打开应用是正常界面, so that 我不会被卡在一个出不来的地方。

**可访问性与动效偏好**

29. As a 使用 TalkBack 的用户, I want 图片被朗读时告诉我「可以进入沉浸模式」, so that 我知道点这张图会发生什么。
30. As a 使用 TalkBack 且已在沉浸态的用户, I want 图片被朗读时告诉我「可以退出沉浸模式」, so that 我有一条不依赖视觉的退出路径。
31. As a 不使用屏幕阅读器的用户, I want 被隐藏的界面不再出现在无障碍树里, so that 无障碍工具不会念出我看不见也点不到的控件。
32. As a 使用各类辅助技术的用户, I want 应用里「无障碍元素开关」这个既有行为保持不变, so that 我的辅助设置不会因为这次改版失效。
33. As a 开启了系统「移除动画」的用户, I want 沉浸切换瞬间完成、不要有过渡动画, so that 界面变化不会让我不适或被动画干扰。
34. As a 手势敏感的用户, I want 上下滑动看图时界面不会反复闪, so that 浏览长图时不被误触发打断。

## Implementation Decisions

以下 9 条逐条对应 ADR-0213 的决策 1–9。**只写决策内容与稳定锚点**（事件名、类名、符号名、决策号），
不写文件路径与代码片段（会过期；精确锚点以 ADR 为准绳）。

### 决策 1 —— 状态形态与「不做自动隐藏超时」

- 沉浸状态是**页面本地状态**，不进 Pinia：它是「当前查看状态」，不是跨页共享数据（对应仓库「数据层分流」硬约束）。
- **单一所有权 token**：存在**一个**模块级所有权标记作为唯一事实源，**禁止在多处各写一份布尔量**。
  新 owner 申请时若已存在 owner，**先强制旧 owner 幂等复位、再接管**。这条专门解决
  「A 页进沉浸 → push B 页 → B 页 pop → A 页已卸载但标志仍为真」这一类泄漏。
- **触发 = 仅手动单击切换，无定时器**。因此不存在「定时器未清除」这一类泄漏，这是本决策最大的实际收益。
  代价明说：顶栏不在图上，藏它换来的可用高度增量有限；而自动隐藏会让用户在「chrome 曾存在」已遗忘的状态下
  只能盲点恢复——把恢复入口押在一个尚未取证的点击判定上，是把两个不确定性相乘。
- **连带约束（验收项；P6 探针已取证为阴性 ⇒ 登记为已知限制，当前不实现）**：隐藏顶栏会改变滚动容器的
  盒高 ⇒ 理论上切换时应**记录并恢复滚动位置**，否则用户在图中间点一下会跳回顶部。这条只在真机上可见。
  **2026-10-01 实测结论：P6 阴性** —— 详情页滚到图片区中部，进immersive 再退出，全图逐像素比对差异
  仅 425 px（0.018%）且全部落在状态栏时钟那一格，画面其余部分逐像素一致 ⇒ **未发生滚动跳变**。
  按 ADR-0213「P6 处置」的阴性分支，恢复逻辑**可不实现**（本仓 `IllustDetail.vue` 无任何
  `scrollTo` / `scroll-top` / `scrollTop`，与本结论一致）。完整测量方法、判据自检与一次判据恒真的
  翻车记录见 `docs/adr/ADR-0213-immersive-media-view.md` §探针实测结论。

### 决策 2 —— 单击绑定落在三处图片层容器上

- 图片层有**三处**分支（ugoira 播放器、多图连续列表、单图），不是两处。单击切换必须**三处全覆盖**，
  只改单图分支会让动图与多图两个分支**静默失去沉浸入口**。
- 绑定在**图片层容器（view）**上，不绑图片元素：容器可覆盖「图未加载完成时点空位」的情形，
  且三处形态一致；本仓既有口径是返回键绑在 view 层（根级 `text` 的 `@tap` 原生无效，同族已知陷阱）。
- **不动既有处理器**：本页 8 个已有处理器（6 个裸 `@tap` + 2 个 `@tap.stop`）与图片层是**兄弟节点、不冒泡**，
  因此**无需改、也不应改**。图片层内的图片组件本身零 `@tap`，不存在第二处冲突。
- **唯一真冲突**：多图分支的「n / N」页角标宿主（`absolute top-2 left-0 w-full …`）是图片层的**子节点**，
  点它会冒泡到图片层并切换 chrome ⇒ 给它补 `@tap.stop`（沿用本页既有的 `.stop` 范式）。
  注意：**图片层本身不隐藏**，角标是它的子节点、父不级联 ⇒ 角标必须**独立条件渲染**。

### 决策 3 —— chrome 边界与返回路径

隐藏的元素（封闭清单，**隐藏的是 chrome、不是图**）：

| 元素 | 隐藏时 | 备注 |
|---|---|---|
| 页级顶栏（含返回键与标题） | 隐藏 | 变体 b，高度 `h-[17.067vw]` |
| 操作/信息行（作者、关注、收藏、评论、下载、标签） | 隐藏 | 即 `p-4 bg-surface-container-lowest` 块 |
| 「n / N」页角标 | 隐藏 | 图片层的**子节点** ⇒ 必须独立条件渲染 |
| 骨架屏 / 错误态 | 不适用 | 与沉浸互斥，沉浸只在作品就绪后可用 |

- 沉浸态**不保留任何可见 chrome**。必须保留的只有三条**非可见路径**：① 系统返回键（不劫持、走既有返回裁决）；
  ② 图片单击（再次点 = 退出）；③ 屏幕阅读器退出路径（见决策 9）。
- ⚠️ **不可逆性风险**：顶栏隐藏后**页内**返回入口消失，唯一返回路径依赖系统返回 ⇒
  「沉浸态下系统手势返回是否仍派发 `pictelioBack`」是**唯一的阻塞级前置门 P4**，详见 Testing Decisions。
  另注 `singleTask` 启动模式意味着从最近任务回来是**同一实例**，不会借「重建 → 新 Window 默认全显」顺带复位。
- **浮层优先级**：浮层（评论 / 选页 / 收藏面板）打开 ⇒ **强制退出沉浸**。这三个都是需要 chrome 的模态，
  沉浸态下打开会得到「一个没有关闭按钮的模态」。实现为**进入浮层的既有入口统一走「先退出沉浸 + 再打开」的复合动作**，
  **不在浮层组件里反向感知沉浸**（避免反向依赖）。

### 决策 4 —— 系统栏：进入设隐藏，退出**回落到用户当前设定**

- 进入：调既有通道 `setSystemBarsHidden(true)`，**不新增 Java**。
- 退出：调 `setSystemBarsHidden(settingsStore.fullscreenMode)` —— **回落到用户原设定，不是硬编码 `false`**。
  理由：若用户本就开着「全屏模式」，全应用已处于系统栏隐藏态；硬编码 `false` 会把用户的持久设定**静默改掉一次**，
  表现为「设置页开关还是开，实际已被改回可见」的状态与 UI 不一致。回落到设置值 ⇒ 两条路线共存且互不污染。
- **失败可回滚**：回调返回错误时**同步回滚内存态**（照抄既有持久化开关的既有回滚范式），
  并**带模块前缀 `console.warn`**。**禁止静默失败**（测试硬约束 #3）。
- 「沉浸」是两件事的合取：**应用内 chrome 显隐** + **系统栏隐藏且根安全区归零**（后者由既有 insets 管线完成，
  值变化才下发事件）。只做前者仍是「贴边但不沉浸」。

### 决策 5 —— 复位保障四层（含一处明确缺口）

「flag 设了没复位 ⇒ 退出应用后系统栏还是隐藏的」是本改造最容易出 bug 的地方。四层按兜底方向排列：

| 层 | 机制 | 覆盖的失效场景 |
|---|---|---|
| **L1 单一所有权** | 模块级 token；新 owner 接管前强制旧 owner **幂等**复位 | 页面 push/pop 交错、owner 意外卸载 |
| **L2 生命周期兜底** | **`onUnmounted` 必复位** | 路由 pop、页面被卸载的一切路径 |
| **L3 返回路径必经** | **`registerBackGuard` 内先复位再放行，返回 `false` 不拦截** | 系统返回**与**页内返回两条路径（共用守卫链） |
| **L4 进程外兜底** | **无 —— 已知缺口** | 杀进程 / 同实例 resume |

- **L4 的确切事实（已验证）**：原生侧 `onResume` **没有**「重新应用隐藏」的分支；销毁时复位的是 insets 与
  `uiMode` 静态字段，**不复位系统栏可见性**。但失败方向是**安全**的：新建 Activity 尾部那句
  「若已隐藏则重新隐藏」自述依据是「新 Window 默认全显」⇒ 进程被杀后新实例从**可见**起步，**不会卡在隐藏**。
- **真正会卡的是同实例 resume**（不新建 Window）⇒ 这正是探针 **P3**。P3 阳性则补第五层。
- **不另选 `onDeactivated`**：keep-alive 路径下该钩子是否触发未验证；与其押注未验证钩子，
  不如让 **L3 返回守卫**覆盖「离开本页」这一事实上的唯一出口（L3 与「离开」语义直接绑定，不依赖组件生命周期钩子的触发时机）。

### 决策 6 —— 沉浸独立于持久化开关，**严禁写该键**

- 两者共用同一个原生通道 `setSystemBarsHidden`，但**不是同一个开关**：设置项是「设备级持久偏好」，
  沉浸是「当前查看状态」。
- **写键 = 永久生效**（原生侧读的是同一个键，且新建 Activity 据此重设系统栏）⇒ 若沉浸复用该键，
  **每次冷启动都会进入沉浸**——而用户上次只是在一张图上点了一下。这是「临时状态被存成持久偏好」的直接后果。
- **硬规则**：沉浸路径**只调** `setSystemBarsHidden`，**严禁写** 全屏模式持久键；既有 `setFullscreenMode`
  是该键的**唯一写点**，沉浸**不得**复用它。⇒ 这条必须有门禁，否则将来「顺手复用一下」会静默把临时状态写成持久偏好。
- **共存的唯一交互点**：退出沉浸时读该设置值作为回落目标（决策 4）。这是**读**，不违反本决策。

### 决策 7 —— 手势边界：本轮**只加**单击

- **不做双指缩放**：本仓全仓无多指手势词汇（无 `@pinch` / `@gesture` 命中），是**从零新建**，
  且需要与滚动容器的多指仲裁——两者都无先例也无阳性对照。
- **不做长按保存**：保存走操作行既有入口；加长按会与单击抢**同一条**手势通道，而单击判定的可靠性正是 P2 的对象。
  同样是叠不确定性。
- **单击判定最终形态取决于 P2**：阴性 ⇒ 直接 `@tap`（三处容器）；阳性（滑动抬手被派发 tap）⇒ 加**位移阈值**，
  复用本仓已有的 touch 三件套判位移，**不新建手势框架**。
- 单击**不吞双击**：无 dblclick 概念，两次快速点击 = 切换两次（回到原状），属可预期行为，不额外处理。

### 决策 8 —— 小说详情页本轮不做

小说是「长文本连续阅读」，不是「全幅看图」，收益低；其核心交互是文本选区，入口是长按，
且**长按抬手的那次 tap 已被打标消费**（否则菜单会被自己这次长按的抬手收掉），点图隐藏 chrome 会在这套仲裁里
再插一个 tap 消费者，而这套仲裁本轮不打算重新验证；另有既有硬门禁（小说页源码不得含 `registerBackGuard`）
会被连带触碰 ⇒ 范围蔓延。后续的前置条件：P2 有结论、选区与 tap 的仲裁被单独取证、那条门禁的处理方式先拍板。

### 决策 9 —— 降级与无障碍

- **减弱动效**：按既有 `useReducedMotion` 的 **R1** 规则——沉浸切换**不挂** `transition-*` 类（类级条件挂载），
  **不是**挂 `0ms` 时长。复用该 composable（全仓唯一的偏好事实源，组件只读，**禁自建 `matchMedia`**）。
- **无障碍**：
  - 隐藏的 chrome 从无障碍树移除是**正确的**，不是缺陷（不可见的控件不应被朗读）；
  - 但**必须补一条 TalkBack 可用的退出路径**：图片容器按状态切换动态 `accessibility-label`（「进入沉浸模式」/「退出沉浸模式」），
    否则屏幕阅读器用户**无法退出沉浸**（点得到图，但没人告诉他这是开关）⚠️ 该动态绑定是否生效见 **P5**；
  - 多图分支该标签还应带上**「第 n / N 张」**（角标在沉浸态已隐藏，位置信息不能从视觉与朗读双通道一起丢）；
  - 既有的无障碍元素开关常量**照旧只绑元素、不绑文案**；顶栏返回键的标签双分支形态不变。

## Testing Decisions

### 什么样的测试算好

**只测外部行为**（用户可观测的结果），不测内部实现。判定标准：断言写的是「用户看到 / 拿到什么」，
而不是「函数被调用了几次」「某个 ref 变成了什么」。

仓内**既有先例**有两类，各有其适用面，混用会出事：

| 先例 | 模式 | 适用 | 不适用 |
|---|---|---|---|
| `safeAreaJavaContract.test.ts` | **源级断言**（读源码字面量，任一侧漂移即红） | **跨端契约 / 硬规则**这类无法从行为观测的约束 | 一切可从行为断言的东西（源级断言对命名/位置敏感，重构会假红） |
| `backupRulesConsistency` | 一致性契约（两侧提取后比对） | 双侧成对存在且要求同步的常量 | 单侧规则 |

**源级门禁的硬性配套**（缺任一即判红，否则门禁恒真）：① **反事实**——塞一个坏形态进去必须转红；
② **抽取器自检**——扫描面非空 + 数量下界，防正则塌陷导致「什么都没查却报通过」。

### 本仓的第三类失败模式与双层门禁

**构建过、类型过、单测过、产物里也有 CSS 规则，真机却渲染为空**——这是本技术栈的第三类失败，
前两类门禁对它**完全无感**。沉浸模式尤其危险：**「系统栏到底隐藏了没有」只有真机看得见**，
静态层再绿也不构成「沉浸可用」的证据。故采用**双层**：

| 层 | 内容 | 是否进 CI |
|---|---|---|
| **L-静态层** | 行为层单测（纯逻辑）+ 源级不变量门禁（硬规则） | **进**（`test:all` / `check:all` / `lint:all`） |
| **L-真机像素层** | 截图矩阵 + 像素判据（双 oracle + preflight） | **不进**（E2E/真机类不进 CI 的既有口径） |

⚠️ 静态层门禁**不得缓存**：既有硬结论是「测试门禁一旦缓存命中 = 测试根本没跑、只重放日志，绿灯是假的」。
沉浸门禁随 `test:all` 走，同受此约束。

**本轮门禁清单（7 条）**

| # | 门禁 | 层 | 抓什么 |
|---|---|---|---|
| **G1** | 沉浸所有权单例的**行为**单测 | 静态 | 进入 / 退出 / 幂等复位 / 新 owner 接管时先复位旧 owner / 重复进入不叠加 |
| **G2** | 系统栏**目标值**行为单测（覆盖「全屏模式」开与关两态） | 静态 | 进入传隐藏、退出**回落到设置项当前值**（两态各一）；失败回调触发内存态回滚且有告警 |
| **G3** | 详情页沉浸接线**源级不变量** | 静态 | 三处图片层容器全覆盖；角标宿主带 `.stop`；8 个既有处理器**未被改动** |
| **G4** | 复位与持久键**源级不变量** | 静态 | `onUnmounted` 复位 / 返回守卫内复位且 `false` 不拦截 / 单一所有权接管；退出实参**不是**字面 `false`；沉浸路径**不含**持久键写点与其写函数名 |
| **G5** | 无障碍与减弱动效**源级不变量** | 静态 | 两态动态 `accessibility-label`；多图标签含「第 n / N 张」；减弱动效为真时**不挂** `transition-*`；**无**自建 `matchMedia` |
| **G6** | **真机像素门禁**：沉浸 / 非沉浸两态截图 + 贴边测量 | 真机 | 顶带与底带在两态下**像素形态不同**（系统栏是否还在）；chrome 是否消失；图是否贴到上下像素 |
| **G7** | **P4 阻塞级前置门**（见下） | 真机 | 沉浸态下系统手势返回是否仍派发 `pictelioBack` |

**G6 的做法必须沿用既有像素链路的纪律，不新造**：**先 preflight 确认 app 真的停在该页**（亮度只看得出明暗、
看不出「当前是哪个页面」，曾因此把「没登录」误诊成「按钮点不开」）；**判据用两个独立 oracle，任一失败即中止**，
绝不产出「名字对、内容错」的证据；**截图尺寸守卫**（截图像素尺寸必须等于本档声明尺寸），
否则会「一切正常」地产出一批名为宽屏、实为另一分辨率的图，而末尾只数张数照样报「完成」。
**脚本才是事实源**：本轮位图不入库，入库的是实测数字与复现命令。

**规模线（硬约束）**：**单个门禁文件不得超过其被测对象的 30%**。被测对象 = 详情页沉浸相关源码
（本轮撰写时详情页为 517 行 ⇒ 单个门禁文件上限约 155 行；新增的所有权单例远小于此，与详情页合并计量）。
源级门禁的膨胀是本仓已诊断的问题：**门禁的价值是防回归，不是显得严谨**；一旦「门禁是否完美」变成目标，
它就不再是目标。

### ⚠️ P4 = 唯一的阻塞级前置门（不放行、不靠推测）

**命题**：沉浸态（顶栏已隐藏）下，系统**手势**返回是否仍派发 `pictelioBack`。

**必须先于实施完成**。**阴性 ⇒ 页面内没有任何返回入口**（顶栏已隐藏、系统返回又收不到）= **死路**，
这不是体验降级。

**阴性时的回退动作（阴性即执行，不放行）**：回改决策 3 为「沉浸态保留一个最小返回入口」
（如右上角浮标，与浮层同层），并把该入口写进验收与用户故事（追加一条「沉浸态仍有页内返回入口」）。
回改只针对 chrome 边界，**不推翻**「应用内沉浸 + 系统栏隐藏都做」的方向。

**阳性对照（否则「什么都没发生」无法区分「引擎不支持」与「没触发」）**：同一路径下**非沉浸态**的同手势必须正常退出。
**阴性结论必须写明是「引擎不支持」还是「没触发」**——本仓在假阴性上付过代价。

### 每条门禁的已知失效面（**显式挂账，勿当「已覆盖」**）

**没有挂账就是没挂**。下表逐条写明它**抓不到什么**：

| 门禁 | **抓不到什么（显式挂账）** | 补齐条件 |
|---|---|---|
| **G1** | 只覆盖状态与复位的**纯逻辑**。抓不到「真机上系统栏是否真的变了」「insets 是否真的推下来」「单击判定在引擎上是否可靠」 | 真机像素门禁 G6 覆盖前两项；第三项属 P2 探针 |
| **G2** | 抓不到**回滚的外部效果**（回滚只保证内存态与告警，抓不到原生侧已隐藏的栏是否被重新显示） | 同上，走 G6 / P3 探针 |
| **G3** | 抓的是源码**字面形状**：能防「漏写三处」「顺手改了既有处理器」，抓不到「绑定在了错误的元素上」「条件渲染方向写反」「引擎实际派发行为」。且对**命名与位置敏感** ⇒ 重构会假红 | 行为层与真机层各自兜；假红按「门禁失效面」登记而非加断言 |
| **G4** | 同 G3。额外抓不到「复位代码在某个新增的离开路径上没跑到」——**新增的离开路径是新事实，源级断言不会自动覆盖** | 每次新增离开路径必须同步扩该门禁（**这条本身要人守，机器不守**） |
| **G5** | 抓不到无障碍树**实际内容**（属性写对了 ≠ 朗读生效 ⇒ P5）。也抓不到减弱动效偏好在系统侧被真实开启 | P5 真机探针；偏好为系统态，只能真机构造 |
| **G6** | ① 瞬时隐藏的**过渡帧**可能被拍到（与既有「切主题后内容未立即重绘」同类问题）；② 像素只看得到「长什么样」，判不出「**为什么**」——哪条分支没生效要看别的层；③ 导航模式（尤其三键）下底栏由系统主题决定，**可能只影响一边**；④ 依赖固定 AVD + 已登录态，**换实例或登录态失效会让门禁整批报废**（既有像素链路已为此付过代价） | 需要一个不依赖像素的正信号（进程 / 窗口 flag 读取），或补一组「已隐藏 / 未隐藏」双态基线图做逐位对照 |
| **G7** | 只验**一条路径**（沉浸态 + 系统手势 + 本页）。抓不到按键返回、浮层栈、`singleTask` 多入口回栈的组合 | 逐条路径另测；P3 覆盖 resume 侧 |

**另需显式登记的「本轮无机器防线」项**：① 沉浸态在 CI 内**没有任何**断言（真机类不进 CI）⇒ 静默回退到
「点图没反应」不会被 CI 发现；② android-e2e 侧的沉浸断言若要写，**只能是手动门禁**，
不构成 CI 内防线；③ **P1/P2/P5/P6/P7 的结论不写成自动化断言**（结论登记 ≠ 门禁覆盖）。

## Further Notes

### 最大风险：系统栏复位泄漏

**「flag 设了没复位 ⇒ 退出应用后系统栏还是隐藏的」是本改造最容易出 bug、也最容易被静态门禁放过的地方。**
用户在 app 内看不出问题（app 内本就该隐藏），一旦退出到桌面仍无栏，症状就是「这个应用把我的状态栏弄没了」，
而复现路径可能与触发路径完全无关。

四条保障（决策 5）：**L1** 单一所有权 token + 幂等复位 / **L2** `onUnmounted` 必复位 /
**L3** 返回守卫内先复位再放行（系统返回与页内返回共用）/ **L4 进程外兜底 —— 缺失**。

**已知缺口，如实登记**：

1. **L4 不存在。** 原生侧 `onResume` 没有「重新应用隐藏」的分支，销毁时也不复位系统栏可见性。
   进程被杀后是**安全**的（新 Activity 从「可见」起步），但**同实例 resume 会卡住** ⇒ 这就是 P3，
   也是唯一可能需要开 Java 的地方。
2. **P3 未出结论前，L3 覆盖不到「用户按 Home 再回来」这条离开路径。**
3. **L3 依赖返回守卫链真的被走到**：若某条离开路径绕过守卫链，守卫内的复位不会执行 ⇒ 每次新增离开路径
   必须复核（机器不守这条，见 G4 失效面登记）。
4. **「顺手复用持久化开关」是静默失败的最佳温床**：一旦沉浸写成持久化，症状不是「界面不对」，
   而是「每次冷启动都被扔进沉浸 + 设置页开关显示与实际状态不一致」——静态层若无门禁，CI 全绿也发现不了。

### ADR-0213 内部待澄清点（实施前请先拍板，不在实施期自行解释）

1. **既有处理器计数基线与决策 2 冲突**：ADR 复核判据要求「`@tap` 处理器计数**不回归**」，并给出
   「6 裸 + 2 `.stop`」的基线；但决策 2 **要求新增 1 个 `.stop`**（角标阻断冒泡）⇒ 实施后必然是 3 个 `.stop`。
   两条不能同时成立。门禁基线须按**新增后**口径登记。
2. **P6 的处置口径自相矛盾**：决策 1 把「记录并恢复滚动位置」写成**必做**（"必须写进验收"），
   而探针处置段把 P6 归为「体验级 ⇒ 记为已知限制，不改方向」。应明确为：**P6 阳性时执行已定的恢复逻辑**，
   「不改方向」仅指不改 chrome 边界。
3. **P5 的后果被低估**：ADR 把 P5 归为「无论正负只影响防御层」，但 P5 阴性时决策 9 要求的
   TalkBack 退出路径**根本不存在** ⇒ 那是一条**可达性死路**（只对屏幕阅读器用户）。建议改按可达性问题登记。
4. **P3 阳性时的 JS 侧回退未指定可用的生命周期钩子**：ADR 给了两个选项（原生 `onResume` 兜底 /
   要求 JS 侧在「页面隐藏」语义上复位），但后者在本栈对应哪个可验证的钩子未验证。
5. **决策 9 的新文案 vs 范围外登记**：决策 9 要求新增两段无障碍标签文案，而 R6 把文案改动划到范围外。
   本 spec 已按「新增必需 / 调整不纳入」切开（见 Out of Scope），请确认该切法。
6. **「复位三层」与「四层」字面不一致**：决策 5 写四层（L4 明确为「无」），复核判据写「三层齐备」。
   门禁实现者需明确 L4 不在勾选范围内，否则会为一个**刻意留空**的层去补门禁。
